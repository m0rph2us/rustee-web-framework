Rustee 공급망과 릴리스 증거

Rustee의 release artifact는 dependency policy, source package checksum, CycloneDX SBOM, keyless provenance를 함께 남깁니다. 이 문서는 각 증거의 범위와 release operator의 확인 순서를 정의합니다.

현재 통제

통제실행 시점보장하는 것
RustSec advisorydependency 변경 PR, main, daily현재 Cargo.lock의 알려진 취약 dependency와 yanked package를 release 전에 차단
cargo-denydependency 변경 PR, main, dailyall-feature graph의 SPDX license, registry/git source, wildcard dependency 정책을 검증

정책 경계

알려진 advisory, 허용되지 않은 license, unknown source는 exception 없이 release를 막습니다. deny.toml의 exception 목록은 비어 있어야 하며, 이 원칙을 바꾸는 변경은 ADR, owner, 만료일, compensating control과 release note를 함께 가져야 합니다.

  • 중복 전이 dependency는 현재 경고로 추적하되, security policy 위반으로 자동 통과시키지 않습니다.
  • SBOM은 dependency 구성표입니다. source artifact의 재현 빌드, runtime configuration, container image, cloud service의 보안을 대신 증명하지 않습니다.
  • check-workflow-action-pins.mjs는 repository workflow의 direct action reference만 검사합니다. action 내부의 composite/reusable workflow dependency, container image digest, GitHub organization action-allowlist와 runner image는 별도 trust review 대상입니다.
  • provenance attestation은 source package 및 SBOM 파일이 release workflow에서 생성된 사실을 묶습니다. crates.io publish 권한, registry upload, consumer runtime의 신뢰를 자동으로 보장하지 않습니다.
  • GitHub artifact attestation은 public repository 또는 이를 지원하는 GitHub Enterprise Cloud 환경을 요구합니다. 해당 기능을 사용할 수 없는 repository는 release를 승인하기 전에 동등한 signed provenance storage를 ADR로 정해야 합니다.

Release 산출물

target/package/*.crate
target/package/SHA256SUMS
target/sbom/**/sbom.cdx.json

SHA256SUMS는 source package 각각의 subject 목록이며, release workflow의 source provenance attestation에 사용합니다. cargo-cyclonedx 0.5.9는 Cargo metadata와 lockfile을 사용해 각 workspace package의 CycloneDX 1.5 JSON을 생성합니다. scripts/collect-cyclonedx-sboms.mjs는 JSON 형식과 spec version을 검증한 뒤 target/sbom에 모읍니다. source package와 SBOM archive는 모두 90일간 GitHub Actions artifact로 보관합니다.

Release 확인 순서

  1. dependency policy, RustSec advisory, MSRV/stable CI와 provider contract를 green 상태로 만듭니다.
  2. workflow action pin verifier가 every direct uses: reference의 full commit SHA를 확인합니다.
  3. release inventory가 publish intent와 package metadata를 현재 workspace와 일치한다고 확인합니다.
  4. v* tag의 release qualification에서 source package, checksum, SBOM archive와 두 provenance attestation을 확인합니다.
  5. 첫 publish와 이후 publish는 source package checksum, release note, migration guidance, publish credential ownership을 사람이 검토한 뒤 별도 승인 환경에서 수행합니다. local path dependency가 registry에서 해석될 수 있는 publish 뒤에는 verify-published-release-candidates.mjs의 registry source consumer compile verification을 별도 record로 남깁니다.
  6. consumer는 GitHub CLI의 attestation verification과 published package checksum 대조를 자신의 trust policy에 따라 수행합니다.

AI 유지 규칙

  • Cargo.toml, Cargo.lock, dependency feature, MSRV 또는 publish intent를 바꾸면 이 문서, 출하 계획, 테스트 전략, release inventory와 inventory verifier를 같은 변경에서 갱신합니다.
  • SBOM generator, retention, checksum subject, attestation 방식이 바뀌면 .github/workflows/release-qualification.yml와 scripts/collect-cyclonedx-sboms.mjs를 함께 검증합니다. workflow action을 추가하거나 바꾸면 full SHA/comment와 scripts/check-workflow-action-pins.mjs 결과를 함께 검증합니다.
  • release evidence의 한계나 새로운 exception을 발견하면 code comment가 아니라 이 HTML 문서와 ADR에 기록합니다.
