Validation Rules

  • Run node scripts/check-qualification-register.mjs whenever this register changes. CI checks its schema, required gates, safe ASCII fields, status-specific requirements, and qualified-record evidence fields. It rejects unknown options and more than one document path.
  • Run node scripts/check-qualification-register.mjs --require-qualified only when making an Enterprise-qualified claim. It rejects pending, failed, expired, or out-of-date records.
  • CI also runs node scripts/check-qualification-register.mjs --self-test to keep valid and invalid calendar-date and command-line boundaries verified.
  • A qualified record requires an owner, reviewer, source reference, environment, provider, scope, safe procedure/evidence references, recovery outcome, completion date, and expiry date. Dates must be real ISO calendar dates; normalized values such as 2026-02-31 are rejected.
  • Evidence references use typed non-secret identifiers such as artifact:, attestation:, issue:, report:, runbook:, or workflow:. Do not add raw credentials, tokens, prompts, payloads, private endpoints, or customer data.

Update Rules

Each adopter opens or updates its own record whenever a deployment claim, provider version, topology, security policy, recovery procedure, or benchmark comparison changes. A failed, expired, or missing record lowers that deployment's support claim; it is never replaced by an inference from local tests.
