Architecture

Rustee의 계층과 crate 경계

Rustee는 하나의 거대한 crate가 아니라, 안정적인 core와 선택 가능한 주변 기능으로 구성합니다. 공개 API는 단순하게 보이되 내부 경계는 엔터프라이즈 확장을 견딜 수 있어야 합니다.

Current MSRV: Rust 1.94.1.

event source settlement 관측은 rustee-events의 provider-neutral EventDeliveryObserver와 rustee-events-observability/rustee-events-observability-prometheus에 분리합니다. Kafka adapter는 KafkaEventConsumer::readiness로 subscription metadata만 read-only probe하며, metrics는 acknowledged/retried/dead-lettered/unsettled, bounded provider, in-flight와 global duration만 export합니다. scrape route, alert policy, replay와 external side-effect idempotency는 application deployment가 소유합니다.

public edge delivery는 rustee-server의 기능이 아닙니다. TLS termination, CDN cache key, purge와 edge compression은 deployment가 소유하며, origin은 edge peer CIDR만 trusted proxy로 설정합니다. cacheability와 edge qualification의 기준은 edge delivery policy와 ADR 0027에 있습니다.

transactional outbox relay의 exporter-neutral collector는 rustee-outbox-observability에 두고, explicit Prometheus text response는 rustee-outbox-observability-prometheus에 분리합니다. 둘 다 global registry나 automatic route를 만들지 않으며 alert policy와 scrape isolation은 application deployment가 소유합니다.

recurring scheduler는 별도 RecurringJobFireObserver lifecycle을 제공하고, rustee-jobs-cron-observability와 rustee-jobs-cron-observability-prometheus는 fixed terminal outcome, aggregate claimed/staged/rate-limited count와 global duration만 export합니다. cancellation은 abandoned로 기록하지만 schedule key, cron expression, destination, payload, tenant, rate key와 raw storage error는 metric에 남기지 않습니다.

durable worker delivery는 rustee-jobs-observability::JobMetrics로 bounded provider/outcome/global duration을 수집하고, rustee-jobs-observability-prometheus는 escaped provider label을 가진 explicit no-store text response만 제공합니다. global registry, listener, automatic route와 alert 정책은 만들지 않습니다.

event stream consumer도 rustee-events::EventDeliveryObserver와 optional rustee-events-observability/rustee-events-observability-prometheus로 같은 exporter-neutral boundary를 가집니다. Kafka adapter는 source commit 뒤 acknowledged/retried/dead-lettered만 finish하고, cancellation 또는 settlement failure는 unsettled가 됩니다. collector는 bounded provider/outcome, in-flight와 global duration만 보유하며 topic, partition, group, offset, key, payload, event identity, endpoint와 raw error를 exporter label로 쓰지 않습니다.

Nested service contract

let api = App::new()
    .get("/users/:id", get_user)
    .layer(AuthLayer::bearer(verifier));

let app = App::new()
    .get("/health", health)
    .nest("/api", api);

App::nest는 static, non-root prefix 아래에 Rustee App 또는 Tower-compatible service를 mount합니다. child에는 prefix를 제거한 URI와 원래 query/request extension을 전달하므로 service-scoped auth, policy, rate limit layer를 자연스럽게 조합할 수 있습니다.

  • prefix는 /api처럼 하나 이상의 static segment여야 합니다. root mount와 :tenant 같은 parameterized prefix는 construction time에 거부합니다.
  • child service는 자기 prefix 아래의 404, fallback, method 405/Allow response를 소유합니다. prefix 밖 request만 parent fallback으로 이동합니다.
  • 동일 request에 parent의 direct route가 있으면 direct route가 우선하며, 여러 nested prefix가 맞으면 더 긴 prefix가 우선합니다.
  • nested Rustee App의 handler와 response에는 외부 전체 RouteTemplate이 기록됩니다. 예를 들어 child /users/:id는 /api/users/:id로 metric을 분류합니다.
  • parent와 child의 StateStore는 합쳐지지 않습니다. 공유 state는 명시적으로 같은 value를 두 app에 주입하거나 outer Tower layer/request extension으로 전달합니다.

핵심 추상화

Handler

요청에서 값을 추출하고 응답으로 변환되는 async 함수의 공통 표현입니다.

IntoResponse

문자열, JSON, status tuple, custom error를 HTTP 응답으로 바꾸는 계약입니다.

FromRequest

Path, Query, Json, Header, State 같은 extractor의 기반입니다.

App / Router

라우트 등록, nesting, fallback, middleware 적용을 담당하는 사용자-facing 타입입니다.

Layer

timeout, tracing, auth, rate limit 등 횡단 관심사를 조합하는 표준 경로입니다.

State

공유 애플리케이션 상태를 타입 기반으로 안전하게 주입합니다. 데이터베이스 풀, Redis와 MongoDB client도 이 경로로 전달합니다.

데이터베이스 경계

rustee-core는 데이터베이스 trait나 ORM 모델을 알지 않습니다. 애플리케이션은 연결 풀을 AppState에 넣고 State<AppState> extractor로 핸들러에 전달합니다. Rustee의 첫 관계형 DB 통합은 선택적 rustee-sqlx crate이며, SeaORM과 Diesel 계열도 같은 상태 주입 경로로 사용할 수 있습니다. MongoDB는 문서 모델이 다르므로 별도 integration으로 관리합니다.

migration은 배포 단계의 명시적 작업입니다. 서버 시작 때 자동 실행하지 않으며, 요청 단위 transaction도 기본 extractor로 제공하지 않습니다. 두 정책의 상세와 예시는 데이터베이스 지원에서 관리합니다.

MongoDB 문서 데이터베이스 경계

Stage 7의 선택적 rustee-mongodb는 공식 mongodb Rust driver의 Client를 AppState로 주입합니다. driver가 내부 connection pool과 topology monitoring을 관리하므로 Rustee는 별도 pool을 만들지 않습니다. BSON document와 HTTP DTO는 분리하고, schema evolution과 index는 배포 단계에서 관리합니다.

begin_transaction은 explicit session transaction만 시작하며 operation의 session 연결과 commit/abort는 application이 수행합니다. next_change_until은 change stream의 다음 event 또는 shutdown과 opaque resume token을 제공합니다. ChangeStreamCheckpointStore와 선택적 rustee-mongodb-checkpoint-sqlx는 opaque resume token의 durable persistence, timeout-bound checkpoint readiness와 optional PostgreSQL-clock writer lease를 제공하지만 worker를 자동 시작하거나 renewal schedule을 조정하지 않습니다. lease owner identity, renewal 실패 뒤 stop/restart와 deployment strategy는 application이 소유합니다. MongoTenantScope는 trusted TenantContext를 BSON outer-AND filter, document, classic update, target collection의 first-match aggregation pipeline과 direct foreign $lookup/$unionWith first-match pipeline에 연결하지만 MongoDB RLS나 raw driver 접근 통제를 대체하지 않습니다. nested aggregation tenant policy, handler retry와 recovery supervisor는 application이 소유합니다. 상세 정책은 MongoDB 문서 저장소에서 관리합니다.

인증과 권한 경계

rustee-core는 Principal, JWT, cookie, identity provider를 알지 않습니다. rustee-auth가 AuthUser extractor, RequireAuth, bearer와 explicit header-only API-key authentication 및 keyed fingerprint store boundary, 권한 정책 middleware를 제공하고, rustee-auth-sqlx가 optional PostgreSQL record/audit adapter를 제공합니다. rustee-auth-jwt가 static verification key를 사용하는 JWT bearer token을 검증합니다. rustee-auth-oidc는 HTTPS JWKS bearer verification/key rotation, OIDC discovery/Code+PKCE browser login, opaque token introspection을, rustee-auth-oidc-redis은 durable state transaction을, rustee-auth-session은 browser session을 확장하며, rustee-auth-session-redis은 후자의 production state-store adapter를 제공합니다.

인증은 신원을 확인해 정규화된 Principal을 만들고, 권한 부여는 scope, server-configured role-to-permission policy, direct permission, tenant context를 사용해 별도로 판단합니다. rustee-tenant의 provider-neutral TenantContext를 configured host authority 기반 HostTenantResolver/TenantResolutionLayer가 principal tenant와 다시 비교한 뒤 extractor로 제공합니다. PostgreSQL service는 이 context를 rustee-sqlx의 RLS-scoped transaction에 전달할 수 있습니다. raw token이나 cookie를 handler에 전달하지 않으며, session store는 Redis 같은 선택적 상태 저장소 adapter로 연결합니다. Redis session store는 남은 session TTL을 Redis expiry로 저장하고 store 장애를 fail-closed로 처리합니다. 상세 정책은 인증과 권한에서 관리합니다.

Queue와 background job 경계

rustee-core는 broker나 worker runtime에 의존하지 않습니다. Stage 9A의 rustee-jobs는 HTTP handler가 typed job을 enqueue하고 별도 process가 worker를 실행할 수 있는 API를 제공합니다. 첫 durable provider는 NATS JetStream 기반 rustee-jobs-nats입니다. Redis Streams rustee-jobs-redis는 Stage 10에서 consumer group, delayed retry, DLQ, pending reclaim의 Redis 7 contract를 구현했고, RabbitMQ 4.3 quorum queue용 rustee-jobs-rabbitmq는 publisher confirm, manual ack/reject, native delayed-retry compatibility와 direct DLQ contract를 구현했습니다. rustee-jobs-sqs는 AWS SDK client injection, long polling, visibility lease heartbeat/delete, direct/redrive DLQ, Standard/FIFO route와 LocalStack contract를 구현했습니다.

public API는 job의 serialization, version, idempotency key, retry policy를 드러내며 성공 처리 뒤에만 ack합니다. at-least-once 전달을 기본으로 하므로 handler는 중복 실행을 견뎌야 합니다. PostgreSQL DB write와 enqueue는 rustee-outbox-sqlx의 same-transaction stage와 explicit lease relay로 연결하고 PostgresInbox로 database side effect receipt를 같은 transaction에 기록할 수 있습니다. rustee-jobs-cron-sqlx는 PostgreSQL durable template을 stored IANA zone으로 계산해 due row lock, fresh envelope outbox stage, next-run advance를 one transaction에 묶습니다. UTC가 default이며 DST forward gap은 skip하고 backward overlap은 earlier UTC occurrence만 materialize합니다. opt-in RecurringJobRateLimit은 shared key의 fixed-window capacity를 같은 transaction에서 consume하고, capacity 부족 시 outbox 없이 다음 window로 defer합니다. cancellation-safe RecurringJobFireObserver와 optional scheduler collector/exporter는 fixed outcome, aggregate claimed/staged/rate-limited count와 global duration만 live 집계합니다. polling supervisor, tzdb update qualification, holiday calendar, tenant fairness, daily quota와 external-provider quota는 application이 계속 소유합니다. PostgreSQL outbox relay는 one-pass relay_once 또는 application-owned supervisor에서 await하는 shutdown-aware run_until(RelayLoopConfig, shutdown)으로 실행하며, 후자는 bounded RelayLoopReport를 반환합니다. Kafka delayed-retry relay는 별도 KafkaDelayedRetryRelayLoopConfig과 KafkaDelayedRetryRelayLoopReport를 사용합니다. cancellation-safe OutboxRelayObserver와 optional rustee-outbox-observability는 fixed event/job kind, pass outcome, row count와 global duration만 live 집계합니다. consumer scope와 external side-effect idempotency는 application이 소유합니다. 상세 정책은 Queue와 background job에서 관리합니다.

Kafka event stream 경계

Kafka는 queue provider가 아니라 Stage 9B의 선택적 rustee-events-kafka integration입니다. event producer와 consumer는 topic, partition key, consumer group, offset commit, rebalance, replay를 명시적으로 다룹니다. 같은 event를 여러 consumer group이 각자 읽을 수 있다는 점이 background job과 다릅니다.

consumer는 side effect 성공 뒤 offset을 commit하고 duplicate delivery를 전제로 idempotent하게 작성합니다. rustee-events-schema는 typed JSON Schema artifact, exact fingerprint와 subject/version catalog를 제공하고 application registry adapter acknowledgement만 local artifact와 대조합니다. remote compatibility semantics, credential, schema-ID wire header, topic mapping과 consumer-first rollout은 deployment가 소유합니다. KafkaRetryConfig와 KafkaFailurePublisher를 연결한 consumer는 handler/decode failure를 immediate retry 또는 terminal DLQ로 broker acknowledgement 뒤 전송하고 그 뒤에만 source offset을 commit합니다. optional rustee-events-kafka-sqlx는 retry intent를 PostgreSQL에 durable stage한 뒤 source offset을 commit하고, application-owned relay가 database clock 이후 stored retry topic으로 다시 publish합니다. broker acknowledgement 뒤 PostgreSQL confirmation이 실패하면 duplicate publish가 가능하므로 event-id/domain-key idempotency는 유지합니다. optional delayed-retry observer/collector는 fixed pass outcome, confirmed successful-pass count와 aggregate backlog만 export하며 query cadence와 alert를 결정하지 않습니다. relay loop, migration, delay/lease/alert와 approved replay runbook은 application deployment가 소유합니다. optional OpenTelemetry adapter는 valid W3C envelope carrier를 event handler span의 parent로 연결합니다. 실제 Kafka+PostgreSQL contract는 staged failure가 due 전 relay되지 않고 due 뒤 confirmation되는지까지 고정합니다. DB write와 event publish는 rustee-outbox-sqlx의 same-transaction stage와 explicit lease relay로 연결하며, Kafka transaction이 external side effect까지 exactly-once로 만든다고 약속하지 않습니다. 상세 정책은 Kafka event stream에서 관리합니다.

KafkaEventConsumer::readiness는 subscribed source/retry topic metadata의 bounded read-only probe이고 group assignment, lag, handler readiness나 offset movement를 보장하지 않습니다. KafkaEventConsumer::with_delivery_observer는 source delivery가 실제로 settle된 뒤 event lifecycle을 emit합니다. rustee-events-observability collector와 explicit Prometheus helper는 source ack, retry route 또는 DLQ route의 completion을 bounded aggregate로만 보며 external side effect exactly-once, lag/rebalance diagnosis, alert/backoff, source group offset movement와 replay authority는 application deployment에 남깁니다.

AI application 경계

rustee-core는 model provider, API credential, prompt, vector database를 알지 않습니다. Stage 9C의 선택적 rustee-ai는 provider-neutral message, structured output, stream event, typed tool, embedding/retrieval와 final request policy가 적용되는 AiPipeline, request/response/stream AiAdvisor, typed ToolRegistry를 제공합니다. rustee-ai-rag는 tenant/ACL retrieval과 content-free document revision에서 chunk/embedding/vector upsert까지의 validation contract를, rustee-ai-rag-jobs는 그 request를 durable typed job으로 전달하는 adapter를, rustee-ai-rag-advisor는 application-owned query/renderer로 ACL-revalidated context를 advisor request에 추가하는 integration을 제공합니다. rustee-ai-test는 provider protocol test를 대체하지 않는 deterministic completion/stream fake와 content-free invocation record를 제공합니다. rustee-ai-openai은 OpenAI Responses의 text/function request/response와 SSE, Embeddings와 explicit bounded Batch file upload/download/create/retrieve/cancel을 typed HTTP codec으로 구현합니다. rustee-ai-web은 AI event stream을 redacted SSE/NDJSON HTTP response로 바꾸고 response drop을 upstream stream cancellation으로 전달합니다.

AI pipeline은 one-call-one-advisor API를 통해 tenant policy, RAG, memory, observability, budget 같은 AI-specific context를 조합합니다. 여러 advisor의 순서는 application-owned composite advisor에 명시하고, framework가 임의로 reordering하지 않습니다. model의 tool call은 신뢰할 수 없는 입력이므로 typed validation, authorization, tenant check, timeout, audit, step/token budget을 통과해야 합니다. AiExecutionContext는 verified tenant/subject를 budget advisor와 approval policy에 공유하고, ToolExecutionContext는 application-defined idempotency key를 typed handler와 audit event에 공유합니다. BudgetAdvisor는 provider 호출 전 content-free request metadata만 application budget gate에 전달합니다. durable provider attempt는 AiUsageReservation과 AiUsageLedger로 reserve한 뒤에만 시작하며, completed response/stream의 actual Usage만 terminal record로 settle합니다. advisor와 ledger를 함께 쓰는 pipeline은 final enriched request를 reserve하고 raw terminal usage를 advisor response/event hook 전에 settle합니다. provider transport failure 또는 stream drop은 refund를 추측하지 않고 pending reconciliation으로 남고 same key의 pending/settled re-call은 차단합니다. ToolRegistry::execute_with_approval_audit는 approved handler보다 먼저 audit sink를 성공시켜야 하며, execute_with_execution_audit는 terminal audit write가 실패하면 handler rollback을 주장하지 않고 reconciliation event를 반환합니다. rustee-ai-audit-sqlx는 tenant + idempotency key ledger에 tool approval/outcome과 provider usage를 replay-safe로 기록하고 conflicting identity/terminal value를 거부하며 bounded pending reconciliation record를 제공합니다. AiPipeline/ToolRegistry는 prompt, completion, model alias, identity, action identifier 없이 aggregate request/usage, fixed outcome, tool risk, latency만 가진 tracing span을 만들며 기존 OpenTelemetry subscriber layer가 이를 export합니다. quota admission의 atomic policy, actual provider lookup/refund, audit retention/retry worker, exporter/sampling/retention과 outbound trace header injection은 application policy가 소유합니다. RAG ingestion은 durable job으로 실행하고 source URI/text는 durable payload에 넣지 않으며, MCP integration은 Stage 10에서 rustee-ai-mcp은 Streamable HTTP JSON/SSE POST-response remote-tool approval boundary와 404 session invalidation/no automatic replay, DELETE/405 close를 구현했고, opt-in bounded HTTP session recovery는 404 뒤 새 handshake만 준비합니다. valid SSE event ID가 있을 때 opt-in bounded resumption은 Last-Event-ID GET만 보내며 origin POST를 replay하지 않습니다. open_server_event_stream()은 initialized session에서 standalone GET notification stream을 열고 server request/response를 fail-closed로 거부합니다. local stdio에는 deadline/discard/graceful-or-forced close/no-replay explicit restart와 opt-in bounded automatic restart/backoff가 있으며, 역시 다음 명시적 요청만 준비합니다. Rust fixture integration test와 macOS/Windows CI matrix는 initialize/discovery/approved execution/close 공통 경로를 검증하도록 구성합니다. negotiated capability 뒤 read-only resource/template/prompt discovery/read/get도 HTTP와 stdio에 제공합니다. 이 context와 standalone notification은 ChatRequest나 advisor에 자동 주입되지 않으며 application/user selection과 별도 authorization/redaction/budget policy가 필요합니다. rustee-mcp은 fail-closed Origin validation, access policy와 terminal audit을 강제하고 authenticated McpContextProvider로 선택적 read-only resource/template/prompt 결과를 제공하는 JSON server를 구현했습니다. Origin allowlist는 authentication/CORS를 대체하지 않습니다. client/server full session lifecycle, server-initiated request/sampling/elicitation, Windows advanced subprocess lifecycle과 context subscription/completion은 별도 contract로 남습니다. OAuth client/resource-server adapter는 아래 별도 경계에서 관리합니다. 상세 정책은 AI application integration에서 관리합니다.

rustee-ai-eval은 provider adapter나 pipeline policy를 바꾸지 않는 선택적 evaluation boundary입니다. application이 target, executor, trusted grader를 소유하고 runner는 safe/unique/bounded suite를 declaration 순서대로 한 번씩 실행합니다. provider 또는 grader 실패는 뒤 case와 retry fan-out 없이 반환하며 report/debug에는 case ID, model alias, usage, bounded grade만 남깁니다. rustee-ai-eval-jobs는 scope/catalog/run key만 가진 job과 run-key binding을, rustee-ai-eval-sqlx는 pending/completed durable run ledger를 제공합니다. catalog load, model/grader/record failure는 pending을 automatic retry하지 않으며 external grader authorization·spend·redaction, report retention/erase, comparative baseline, semantic cache와 provider batch reconciliation은 application/provider evidence입니다. ADR 0020과 ADR 0038을 따릅니다.

rustee-ai-cache는 application-generated tenant-scoped opaque SHA-256 exact key와 explicit TTL만 받는 non-streaming response adapter입니다. framework는 prompt를 hash하거나 AiPipeline에 cache를 자동 장착하지 않습니다. declared tool, prior tool result와 model tool-call response는 lookup/store 대상이 아니며 cache read failure는 fail-closed 또는 visible bypass를 선택합니다. provider completion 뒤 store failure는 response를 retry/error로 바꾸지 않고 status로만 남습니다. rustee-ai-cache-redis는 versioned namespace, serialized-entry bound, Redis-second TTL conversion과 exact delete를 제공하지만 encryption/TLS, tenant erase, key salt/version rotation, stale-answer UX, outage/restart evidence와 distributed stampede control은 deployment 책임입니다. ADR 0021을 따릅니다.

rustee-ai-batch는 raw provider work나 result artifact를 durable payload로 만들지 않는 control plane입니다. tenant/policy scope, catalog ID, stable run key만 가진 submission reference를 atomic ledger가 reserve하고 application catalog가 authorized worker 안에서 raw work를 load합니다. prior receipt는 duplicate delivery에 provider contact 없이 재사용하고 provider error는 receipt가 없는 pending ambiguity로 남아 automatic retry/re-submit하지 않습니다. output/error artifact는 batch reference, opaque provider file ID, reconciliation key만 가진 별도 reference이며 whole-artifact ledger가 Reserved/Reconciled/Pending을 보존합니다. loader가 authorization 뒤에 artifact를 얻고 application processor가 domain key와 provider custom_id로 row side effect를 멱등 적용합니다. rustee-ai-batch-jobs은 submission run key 또는 artifact reconciliation key와 같은 envelope idempotency key에서만 각각의 handler를 실행합니다. optional rustee-ai-batch-sqlx은 scope/reconciliation-key 단위 PostgreSQL reservation, exact identity conflict rejection, idempotent completion, bounded pending query를 제공하지만 row-level domain effect와 application authorization은 소유하지 않습니다. rustee-ai-openai은 safe generic JSONL builder와 typed ChatRequest Responses row, ordered EmbeddingInput Embeddings row mapping, explicit ChatResponse/Embedding conversion, bounded upload/download/delete와 OpenAI Batch create/retrieve/cancel, safe snapshot 및 structural output-row parser를 제공합니다. provider-only input fields, domain response semantics/side effect, partial-result routing, billing/reconciliation은 자동화하지 않습니다. catalog/artifact retention/erase와 queue retry policy는 application/provider adapter가 소유합니다. ADR 0022, ADR 0023, ADR 0024, ADR 0025를 따릅니다.

MCP OAuth Boundaries

rustee-ai-mcp-oauth는 rustee-ai-mcp transport core와 독립된 client adapter입니다. 401 challenge 또는 well-known protected-resource metadata에서 authorization server를 발견하고 OAuth/OIDC metadata fallback과 S256을 검증한 다음, application-selected public client/scope의 state + PKCE callback을 one-time transaction store로 연결합니다. token exchange와 explicit refresh는 canonical MCP resource parameter를 보내며 token set은 exact endpoint에만 적용됩니다. rustee-ai-mcp-oauth-redis는 AES-256-GCM envelope, key/purpose authenticated binding, active/retired decryption key rotation, TTL과 atomic state consume를 제공하지만 tenant/user binding, KMS key delivery, revocation, distributed refresh coordination과 consent rollback은 application deployment의 책임입니다. original MCP action은 authorization, expiry 또는 refresh 때문에 자동 replay되지 않습니다. 반대 방향의 rustee-mcp-oauth는 server token을 저장하거나 발급하지 않고 canonical resource/metadata/issuer allowlist와 required scope를 configuration으로 고정하며 public metadata service와 bearer challenge layer를 제공합니다. verifier는 exact resource audience와 issuer/key source를 검증한 Principal만 기존 MCP policy에 전달합니다. 상세는 MCP OAuth, ADR 0018, ADR 0019에서 관리합니다.

테스트와 검증 경계

Rustee는 stable cargo test를 기본으로 unit/in-process integration/doctest를 실행하고, 빠른 workspace test binary는 cargo-nextest로 병렬 실행합니다. rustee-test는 in-process TestApp의 request/JSON/header/body, bounded response decode와 status/header assertion, opt-in bounded session-style cookie jar를 제공합니다. jar는 valid name/value와 Max-Age=0 deletion만 보존하고 browser origin/path/secure/same-site/expiry 정책은 구현하지 않으므로, SSE, cancellation 또는 실제 TCP/HTTP/browser end-to-end test를 대체하지 않습니다. rustee-test-support는 공개 API가 아닌 fixture, isolated port/namespace, deterministic clock, Testcontainers setup을 담당합니다.

rustee-macros의 opt-in routes!는 existing App registration chain만 만들고, FromHeader derive는 explicit header name을 가진 single-field tuple newtype에만 기존 extractor trait 구현을 생성합니다. 생성 코드는 facade의 hidden re-export만 사용하며 handler, authorization 또는 schema를 추론하지 않습니다. optional integration crate는 real backend contract와 failure/cancellation test를 함께 가지며, 영향을 받은 crate는 required Linux pull-request integration lane에서 이를 실행합니다. macro/API misuse는 compile-fail test로, router/parser/state machine은 property/fuzz로 넓힙니다. wall-clock sleep과 shared resource에 의존하는 test는 금지하며 상세 정책은 테스트와 검증 전략과 매크로 경계에서 관리합니다.

Redis와 상태 저장소 경계

Redis는 rustee-core의 의존성이 아닙니다. 애플리케이션은 clone 가능한 async client를 AppState에 넣고 필요할 때 명시적으로 사용합니다. Stage 6의 선택적 rustee-redis는 redis-rs 기반 client 설정, cache helper, rustee-auth-session-redis가 사용하는 JSON/TTL/delete primitive를 제공하지만 명령 API를 새로 감싸지 않습니다.

Pub/Sub과 blocking command는 일반 request client와 분리하고, 분산 락은 별도 명시적 API와 fencing 요구를 검토한 뒤에만 지원합니다. 상세 정책은 Redis와 상태 저장소에서 관리합니다.

초기 API 목표

use rustee::{App, Json, Path};

#[tokio::main]
async fn main() -> rustee::Result<()> {
    let app = App::new()
        .get("/", || async { "hello rustee" })
        .get("/users/:id", get_user);

    rustee::serve("127.0.0.1:3000", app).await
}

async fn get_user(Path(id): Path<u64>) -> Json<User> {
    Json(User { id })
}

확장 규칙

  • 새 기능이 모든 사용자에게 필요한 계약이면 rustee-core 후보입니다.
  • 특정 HTTP 실행 방식에 묶이면 rustee-server나 별도 adapter 후보입니다.
  • 횡단 관심사는 우선 Tower-compatible middleware로 설계합니다.
  • 매크로는 non-macro API 위에 얹습니다. 매크로만으로 가능한 기능은 피합니다.
  • 엔터프라이즈 기능은 feature flag나 별도 crate로 시작하고, core 침투를 최소화합니다.
  • 데이터베이스 풀, ORM, migration 도구는 애플리케이션 또는 선택적 integration crate에 두고 core에 역의존하지 않습니다.
  • Redis client와 상태 저장소 adapter는 선택적 crate에 두고, cache TTL과 장애 정책을 숨기는 전역 API를 만들지 않습니다.
  • MongoDB client와 BSON helper는 선택적 crate에 두고, document schema와 index 변경을 서버 시작 시 자동 실행하지 않습니다.
  • 인증 provider, token format, session store는 선택적 crate에 두고, core에는 인증 결과가 아닌 HTTP 확장 계약만 남깁니다.
  • job broker, worker, retry, DLQ는 선택적 crate에 두고, broker별 delivery semantics와 DB outbox를 숨기지 않습니다.
  • event stream broker와 Kafka offset/replay contract는 별도 crate에 두고, work queue API로 평준화하지 않습니다.
  • model provider, tool executor, vector index, MCP transport는 선택적 crate에 두고, prompt injection과 side effect 정책을 core에 숨기지 않습니다.
  • test helper는 작은 dev crate에 두고, real transport/backend contract와 deterministic fixture를 mock-only test로 대체하지 않습니다.
  • configuration, secret, observability, proxy trust는 storage integration보다 먼저 정하고, 특정 cloud/config format을 core에 넣지 않습니다.
