Rustee 웹 프레임워크 설계 문서

Rustee는 Rust로 웹 서비스를 만들 때 작은 API에서 시작해 운영, 확장, 엔터프라이즈 요구사항까지 자연스럽게 이어지도록 설계하는 웹 프레임워크입니다. 이 문서 세트는 구현보다 먼저 합의해야 할 철학, 구조, 로드맵, AI 협업 규칙을 정의합니다.

문서 맵

디자인 철학

Rustee가 어떤 문제를 풀고, 어떤 문제는 일부러 풀지 않는지 정의합니다.

프레임워크 구조

workspace, crate 경계, 핵심 추상화, 확장 포인트를 설명합니다.

공식 예제

quickstart, API, middleware, security, job, AI 예제의 실행 조건과 검증 범위를 확인합니다.

데이터베이스 지원

SQLx 중심의 공식 통합 경로, ORM 공존 방식, migration과 transaction 운영 원칙을 정리합니다.

Redis와 상태 저장소

캐시, 세션, rate limit, Pub/Sub을 위한 client 선택, 장애 정책, 확장 경계를 정의합니다.

MongoDB 문서 저장소

공식 Rust driver, BSON tenant 경계, schema evolution, transaction, change stream과 durable checkpoint 운영 원칙을 정리합니다.

인증과 권한

OIDC, bearer token, session, RBAC, tenant context와 보안 기본값을 정의합니다.

Queue와 background job

at-least-once job, worker, retry, DLQ, outbox, one-time delay와 IANA time-zone recurring scheduler, PostgreSQL fixed-window governor 및 bounded scheduler pass observability 경계를 정의합니다.

Kafka event stream

topic, partition key, consumer group, offset, immediate/DLQ와 PostgreSQL durable delayed retry, replay, schema와 outbox 경계를 정의합니다.

AI application integration

chat, streaming, tool, RAG, structured output, AI 보안과 운영 경계를 정의합니다.

AI Batch 운영 runbook

Batch artifact reconciliation, pending 재처리, row idempotency, retention/delete의 운영 책임을 정리합니다.

MCP OAuth

MCP protected resource discovery, PKCE callback, metadata, bearer authorization과 no-replay 경계를 정의합니다.

테스트와 검증 전략

test layer, feature matrix, 실제 backend contract, CI와 release gate를 정의합니다.

OpenAPI

명시적 route, operation, JSON Schema 문서와 application-owned API 의미의 경계를 정의합니다.

매크로 경계

선택적 routes! builder와 FromHeader derive의 입력 형태, 실패 진단과 non-macro API 우선 원칙을 정의합니다.

운영과 배포

configuration, lifecycle, health, observability, TLS와 reverse proxy trust 경계를 정의합니다.

Kafka Delayed Retry Runbook

Kafka와 PostgreSQL delayed retry의 migration, readiness, 장애, restore와 승인 replay 절차를 정리합니다.

Event Schema Runbook

JSON Schema artifact, registry verification, consumer-first rollout, rollback과 replay 검토 절차를 정리합니다.

정적 파일

prefix-bound static delivery, cache policy, MIME, filesystem security 경계를 정의합니다.

응답 압축

gzip/Brotli negotiation, streaming body, cache variation과 proxy/CDN ownership 경계를 정의합니다.

로드맵

MVP부터 엔터프라이즈 기능까지의 단계별 목표와 완료 기준을 정리합니다.

출하 계획과 지원 정책

v1 경계, 선택적 adapter의 지원 단계, enterprise qualification과 release gate를 정리합니다.

공급망과 릴리스 증거

dependency policy, source package checksum, CycloneDX SBOM과 provenance attestation의 범위를 확인합니다.

Release inventory

공개 후보와 workspace-only package의 의도, package metadata 검증 기준을 확인합니다.

Release checklist

clean source preflight, tag evidence, publish approval과 사후 확인의 운영 순서를 정리합니다.

Release notes

공개 release의 변경, 지원 약속, provenance와 known limitation을 기록합니다.

Migration guide

API, configuration, schema, provider와 deployment 변경의 전환·rollback 절차를 기록합니다.

Qualification register

release, edge, provider, AI의 외부 evidence와 owner gate를 한 곳에서 추적합니다.

Edge delivery policy

TLS, proxy trust, CDN cache, compression, purge와 origin drain의 배포 책임을 정리합니다.

지원 현황 매트릭스

각 crate와 provider의 검증 증거, 현재 상태, 승격 전 공백을 확인합니다.

구현 계획 재검토

현재 구현 범위, release blocker, 다음 milestone의 우선순위를 정리합니다.

AI 유지관리 규칙

AI 에이전트가 작업 전에 읽고, 작업 후 갱신해야 하는 문서 규칙입니다.

현재 합의

Rustee의 1차 방향은 작고 안정적인 core, Tower 호환 미들웨어 모델, Tokio/Hyper 기반 서버 어댑터, 기능별 crate 분리, SQLx 중심의 선택적 관계형 데이터베이스 통합, Redis 기반의 선택적 상태 저장소 통합, MongoDB 기반의 선택적 문서 데이터베이스 통합, 표준 기반의 선택적 인증과 권한 통합, durable queue와 background job 통합, Kafka event stream 통합, 선택적 AI application 통합, 계층형 테스트와 검증 전략, 운영과 배포 trust boundary입니다.

자세한 근거는 ADR 0001: 프레임워크 기반 선택과 ADR 0002: 데이터베이스 통합 경계, ADR 0003: Redis 통합 경계, ADR 0004: MongoDB 통합 경계, ADR 0005: 인증과 권한 경계, ADR 0006: background job과 queue 경계, ADR 0007: Kafka event stream 통합 경계, ADR 0034: Kafka PostgreSQL delayed retry, ADR 0008: AI application 통합 경계, ADR 0009: 테스트와 검증 전략, ADR 0010: platform foundation과 배포 trust boundary, ADR 0011: MSRV와 통합 지원선, ADR 0012: tenant persistence isolation, ADR 0013: 출하 트랙과 지원 정책, ADR 0018: MCP OAuth client boundary와 ADR 0019: MCP OAuth resource-server boundary에 기록합니다.
