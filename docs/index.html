Rustee Web Framework Design Documents

Rustee is a Rust web framework designed to take a service from a small API to operational, scalable, and enterprise requirements without abandoning its core principles. This document set establishes the philosophy, architecture, roadmap, and AI collaboration rules that must be agreed before implementation grows.

Current Agreement

Rustee is built around a small and stable core, a Tower-compatible middleware model, a Tokio/Hyper server adapter, feature-specific crates, optional SQLx relational database, Redis state-store, MongoDB document-database, and standards-based identity and access integrations. Durable queues and jobs, Kafka event streams, optional AI application integration, layered verification, and operational and deployment trust boundaries complete the platform direction.

The rationale is recorded in ADR 0001: Framework Foundation, ADR 0002: Database Integration Boundary, ADR 0003: Redis Integration Boundary, ADR 0004: MongoDB Integration Boundary, ADR 0005: Authentication and Authorization Boundary, ADR 0006: Background Jobs and Queue Boundary, ADR 0007: Kafka Event Stream Boundary, ADR 0034: Kafka PostgreSQL Delayed Retry, ADR 0008: AI Application Integration Boundary, ADR 0009: Testing and Verification Strategy, ADR 0010: Platform Foundation and Deployment Trust, ADR 0011: MSRV and Integration Support Line, ADR 0012: Tenant Persistence Isolation, ADR 0013: Release Tracks and Support Policy, ADR 0018: MCP OAuth Client Boundary, and ADR 0019: MCP OAuth Resource-Server Boundary.

Documentation Rules

  • Official project documentation is written in HTML, not Markdown.
  • Changes to architecture, public APIs, the roadmap, or the design philosophy update the relevant HTML documents in the same change.
  • Important design decisions are recorded as HTML ADRs.
  • AI agents read the AI Maintenance Rules before starting work.
