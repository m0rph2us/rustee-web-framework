Implementation Review

기반은 갖췄고, 이제 실제 backend 계약을 닫아야 합니다

Rustee의 전체 방향은 유지합니다. 현재 가장 큰 위험은 기능 목록 부족이 아니라, 이미 만든 선택적 adapter를 실제 infrastructure와 security failure에서 끝까지 검증하지 않은 상태입니다. 다음 작업은 breadth보다 이 경계를 닫는 데 우선순위를 둡니다.

재검토 기준

현재 구현은 “기능 부족”보다 “지원 선언의 증거 부족”이 더 큰 위험입니다. 따라서 v1은 F1 framework baseline을 안정화하는 release로 한정하고, database, auth, jobs, Kafka, AI는 출하 계획과 지원 정책의 Experimental, Contract-verified, Supported, Enterprise-qualified 단계를 독립적으로 밟습니다.

이 표의 공백은 다음 crate를 만들기 위한 backlog가 아니라 각 adapter가 실제 운영 지원을 얻기 위한 evidence backlog입니다. adapter별 현재 단계와 증거는 지원 현황 매트릭스에서 추적합니다. provider 하나의 미완성으로 core v1을 막지 않으며, container happy path만으로 Supported라고 부르지도 않습니다.

2026-08-04 전체 계획 재정렬

다음 계획은 “모든 crate를 동시에 완성”하는 순서가 아니라, 첫 release 기준선을 만든 뒤 framework와 optional integration을 서로 다른 증거로 승격하는 순서입니다. main의 첫 intentional source baseline commit은 존재하지만 tag와 publish record가 없으므로 public compatibility 또는 Supported 약속의 기준점은 아직 없습니다. 이번 재검토에서 Kafka event의 durable delayed retry, schema registry boundary, source-settlement delivery observer/Prometheus export와 read-only consumer readiness, TestApp의 bounded session-style cookie test boundary, OpenAPI의 static OAuth2/global override, mutualTLS metadata와 API-key header grammar, router/OpenAPI route conversion 및 API-key header-name의 property/fuzz 경계, explicit header-only API-key runtime authentication, bounded active/retired pepper dual-read와 keyed fingerprint store/PostgreSQL atomic audit adapter까지 code/contract 범위를 닫았습니다. OpenAPI metadata는 token lifecycle, API-key parser나 direct TLS/client-certificate runtime을 구성하지 않고, separate ApiKeyLayer와 its reference store도 pepper/KMS replacement fingerprint migration, database restore, retention policy를 추론하지 않습니다. 따라서 다음 내부 우선순위는 새 provider나 Kafka facade가 아니라 P0/F1 기준선, 하나의 명시적 reference deployment와 그 failure/operation evidence입니다.

우선순위목표완료 판단
P0source/release baseline첫 intentional source commit과 publish 후보 확정은 완료했습니다. 다음은 v0.1.0 source tag, draft release notes/migration guide 검토, release owner의 clean tag qualification과 publish approval입니다. local preflight/archive assembly는 통과했지만 tag, provenance workflow, registry publish의 증거는 아닙니다. 그 전에는 semver diff와 Supported 선언을 하지 않습니다.
P1F1 framework baselineHTTP/1.1 origin, proxy trust, shutdown, opt-in panic-to-redacted-500 boundary, explicit OpenAPI route/schema/security-metadata plus static OAuth2/global override and mutual-TLS declaration consistency, optional routes!/FromHeader runtime and compile diagnostics와 observability deployment policy, CDN/TLS/cache-control policy를 release evidence로 닫는다. OpenAPI와 macro는 handler/authorization을 자동 추론하지 않으며 mutual-TLS metadata도 TLS/client-certificate runtime을 구성하지 않는다. exporter endpoint/credential/sampling/shutdown은 tracer provider를 만드는 application 책임이고, panic hook/restart, post-commit failure와 chosen CDN qualification도 deployment 책임으로 남긴다. 이 track만 v1 hard gate다.
P2I1/I2 reference deployment qualification모든 adapter를 동시에 승격하지 않습니다. 먼저 owner가 PostgreSQL/Redis/OIDC와 하나의 delivery provider를 명시한 reference deployment를 선택하고, version/topology, outage, duplicate, drain, restore, DLQ/replay, alert와 operator runbook evidence를 한 조합에서 닫습니다. Kafka를 선택하면 Confluent provider/version/credential/ACL/outage, consumer-first rollout, replay와 external side-effect idempotency까지 같은 record로 남깁니다.
P3remaining adapters and I3 AI qualificationreference deployment의 결과를 일반화하지 않습니다. 다른 broker, MongoDB, alternate IdP와 AI Batch/RAG/vector는 각자의 provider evidence로 독립 승격합니다. AI Batch는 typed Responses/Embeddings rows, explicit result conversion, artifact ledger와 runbook까지 구현됐지만 live provider, catalog authorization, domain row ledger, partial-result/billing과 vector source는 별도 evidence다. 비용 승인은 자동 CI와 분리합니다.
P4enterprise topology각 adapter가 Supported가 된 뒤에만 cluster, sharding, multi-region, direct protocol expansion을 workload ADR, recovery guide, performance/soak evidence와 함께 검토한다.

실행 순서는 P0 → P1 → 선택한 reference deployment의 P2 증거 → 나머지 P3 integration → P4입니다. 따라서 지금부터의 기본 작업 단위는 “새 기능 하나”가 아니라 하나의 documented boundary와 그 failure/operation evidence입니다. P0/P1을 우회해 optional adapter의 상태를 올리거나 P4 topology를 미리 약속하지 않습니다.

Outbox observability update

PostgreSQL outbox의 exporter 공백은 rustee-outbox-observability-prometheus로 닫았습니다. collector snapshot을 fixed relay kind/outcome, aggregate row count, in-flight와 global duration만 가진 Prometheus 0.0.4 no-store response로 바꾸며 destination, message ID, payload, broker endpoint와 raw error는 내보내지 않습니다. scrape route/network isolation, alert threshold와 owner, migration/restore 및 external side-effect idempotency는 여전히 application/deployment release gate입니다.

Scheduler observability update

PostgreSQL recurring scheduler의 exporter 공백은 RecurringJobFireObserver, rustee-jobs-cron-observability와 rustee-jobs-cron-observability-prometheus로 닫았습니다. cancellation-safe observer는 fixed succeeded/failed/abandoned outcome, aggregate claimed/staged/rate-limited count, in-flight와 global duration만 전달합니다. Prometheus text response는 explicit no-store helper이고 schedule key, destination, payload, tenant, rate key와 raw storage error는 내보내지 않습니다. scrape isolation, alert threshold와 owner, polling cadence, PostgreSQL outage runbook, tzdb update qualification, holiday calendar와 downstream idempotency는 application/deployment release gate입니다.

Worker Prometheus update

shared worker-delivery collector의 exporter 공백은 rustee-jobs-observability-prometheus로 닫았습니다. helper는 bounded provider와 fixed outcome, in-flight/global duration만 escaped Prometheus 0.0.4 no-store response로 인코드합니다. registry, listener, scrape route, broker health probe, alert threshold와 DLQ replay authority는 추가하지 않습니다. provider-specific backlog/visibility signal, outage/duplicate matrix와 production scrape isolation은 각 broker deployment qualification에 남습니다.

재검토 반영

SQS는 client injection과 queue lifecycle 경계는 갖췄지만 단일 요청이 SDK retry에 오래 머물 수 있었습니다. 이제 publisher와 worker에 기본 25초의 outer request deadline을 두고, worker receive deadline은 long poll보다 길게 검증합니다. CI는 stopped LocalStack에서 500ms의 sanitized failure를 확인한 뒤 재시작 후 전체 SQS suite를 다시 실행합니다. 남은 SQS evidence는 IAM/KMS outage, Standard duplicate/receive-count variation, replay procedure와 real AWS opt-in qualification입니다.

Redis Streams도 reconnecting connection manager에 명령 시간을 맡긴 채 두지 않습니다. publisher와 worker의 모든 Redis command는 기본 5초 deadline 안에서 끝나고 blocking read보다 짧은 worker deadline은 거부합니다. Redis 7 CI의 intentional pause contract가 500ms sanitized readiness failure를 확인합니다. retention/replay, Cluster/Sentinel failover와 reclaim-idle 운영 절차는 여전히 별도 release gate입니다.

PostgreSQL persistence는 초기 pool connect를 기본 5초로 제한하고 CI가 stopped database에서 500ms의 credential/endpoint-free failure를 확인합니다. restart 뒤 SQLx, outbox, AI audit/usage ledger, checkpoint PostgreSQL contracts를 재실행해 connection recovery를 검증합니다. migration/restore, alert/export, external side-effect idempotency와 broader outage matrix는 release gate로 남습니다.

AI tool ecosystem은 raw remote client 또는 server capability를 core에 넣지 않습니다. rustee-ai-mcp은 trusted Streamable HTTP JSON/SSE POST-response endpoint를 bounded하게 initialize/discover하고 session 404를 explicit reinitialization-required state로 바꾸며 DELETE/405 close를 지원합니다. opt-in HTTP session recovery와 application-trusted local subprocess의 opt-in automatic restart는 bounded exponential backoff로 replacement handshake만 준비하고 original action을 성공으로 바꾸거나 재실행하지 않습니다. valid SSE event ID 뒤 opt-in resumption은 bounded retry/total-response limit 안에서 Last-Event-ID GET만 보내며 original POST를 재실행하지 않습니다. explicit standalone GET stream은 untrusted notification을 한 개씩 전달하고 event-ID reconnect도 GET만 쓰며 server request/response는 fail-closed로 거부합니다. stdio에는 bounded initialize/discovery/call, request timeout 뒤 connection discard, stdin EOF 뒤 graceful/forced close와 prior action을 replay하지 않는 explicit restart도 있습니다. Rust fixture integration test와 macOS/Windows CI matrix는 stdio initialize/discovery/approved execution/close 공통 경로를 검증하도록 구성합니다. negotiated resources/prompts capability와 standalone notification은 ChatRequest 또는 advisor로 자동 전달하지 않습니다. 두 remote transport 모두 selected tool을 existing ToolRegistry의 approval/audit 뒤에만 실행합니다. rustee-mcp은 fail-closed Origin validation, access-filtered tool discovery와 application-created execution context, pre/post terminal audit을 강제하는 nested Tower server이며 authenticated McpContextProvider가 opt-in한 read-only resource/template/prompt request도 item/response bound 안에서 처리합니다. local TCP/in-process/subprocess contract는 deny-before-call, session propagation/expiry without automatic replay/explicit close, opt-in idempotency metadata, SSE notification/result framing and bound, SSE event-ID GET resume without POST replay, standalone GET notification/reconnect/no-server-request, HTTP session/stdio process automatic-recovery no-replay bound, client context capability denial/URI/cursor/decoded-content redaction, server context default denial/provider authorization/URI equality/item bound, Origin allowlist/default denial, handler-error redaction, body/pagination bound와 prefix mount를 고정합니다. Origin allowlist는 CORS/authentication을 대체하지 않으며 client/server full session lifecycle/server-initiated request/sampling/elicitation, Windows advanced subprocess lifecycle evidence, context subscription/completion와 endpoint trust operation procedure는 Supported gate 전에 남아 있습니다.

MCP OAuth client는 별도 rustee-ai-mcp-oauth adapter로 시작했습니다. bounded protected-resource/authorization-server discovery, S256 PKCE state transaction, single-use callback, resource-bound code/refresh exchange와 redacted token-store contract를 local/loopback contract로 검증합니다. rustee-ai-mcp-oauth-redis는 AES-256-GCM envelope, key/purpose binding, retained decrypt key rotation, TTL/GETDEL state consume와 token load/delete Redis contract를 제공합니다. counterpart rustee-mcp-oauth는 validated public metadata, 401/403 challenge, required scope와 verified-principal handoff을 in-process contract로 고정하며 token lifecycle을 소유하지 않습니다. transport core나 browser session이 token을 자동 소유하지 않고 authorization/refresh는 original MCP action을 replay하지 않습니다. KMS/tenant key policy, revocation/rotation/consent rollback, distributed refresh coordination, provider/JWKS/introspection version and outage matrix, canonical proxy URL와 live deployment evidence는 Supported gate 전 운영 증거로 남습니다.

AI evaluation은 rustee-ai-eval로 pipeline/provider와 분리했습니다. application-owned target, executor, trusted grader를 받아 unique/bounded suite를 sequential no-retry로 실행하며, executor/grader error가 나면 뒤 case를 실행하지 않습니다. report/debug는 case ID, model alias, usage, bounded grade만 포함하고 private prompt/target/completion을 기록하지 않습니다. AiEvaluationReference와 rustee-ai-eval-jobs는 scope/catalog/run key만 durable payload로 전달하고 envelope key가 다르면 실행 전에 거부합니다. rustee-ai-eval-sqlx는 PostgreSQL에 pending/completed reservation과 exact catalog identity만 기록하며, failure를 release하거나 provider를 자동 재호출하지 않습니다. catalog authorization, report retention/erase, external human/LLM grader의 authorization·spend·redaction, comparable baseline, fresh-run reconciliation, semantic cache와 live provider evidence는 다음 release gate입니다.

response cache도 AiPipeline에서 분리했습니다. rustee-ai-cache는 application-generated tenant-scoped opaque exact key, bounded TTL/read failure policy, tool interaction exclusion, hit/write-failure status와 exact invalidation을 제공하고 rustee-ai-cache-redis는 versioned Redis namespace, response size bound, TTL/delete contract를 제공합니다. raw prompt hash, automatic cache attachment, wildcard tenant purge, cache write failure 뒤 provider retry는 제공하지 않습니다. key/salt/version design, encryption/TLS, tenant erase, retention, outage/restart, stampede와 stale-answer UX는 Supported gate 전 application/deployment evidence로 남습니다.

provider batch도 generic retry loop가 아니라 rustee-ai-batch의 catalog reference와 atomic submission ledger로 분리했습니다. safe tenant scope/catalog/run key를 reserve한 뒤 application catalog가 raw work를 load하며, recorded receipt는 duplicate delivery에서 provider를 다시 호출하지 않게 합니다. provider failure는 pending reconciliation으로 보존하므로 automatic resubmit하지 않습니다. output/error artifact도 batch/file/reconciliation-key reference만 durable하게 남기고, whole-artifact ledger가 successful reconciliation은 재다운로드 없이 재사용하며 ambiguous attempt는 Pending으로 고정합니다. authorized loader 뒤 application processor가 domain key와 provider custom_id로 row effect를 멱등 처리합니다. rustee-ai-batch-sqlx은 scope/reconciliation-key durable reservation, exact identity conflict rejection, idempotent completion과 redacted bounded pending query를 PostgreSQL migration으로 제공합니다. 같은 pending key는 release하지 않으며 application이 row ledger를 검토한 뒤 새 reconciliation key로만 새 attempt를 발급합니다. rustee-ai-batch-jobs은 raw work/result 없이 submission/artifact reference만 durable payload로 넣고 envelope key mismatch를 handler 전 거부합니다. rustee-ai-openai은 explicit bounded JSONL upload/download/delete와 Batch create/retrieve/cancel, safe status/count/file-ID snapshot, structural output-row parser, explicit ChatResponse/Embedding conversion, explicitly environment-gated live upload/submit/retrieve/cancel test를 제공합니다. model body는 application의 explicit consume 뒤에만 이 두 conversion으로 해석됩니다. provider-only input JSONL row validation, domain response semantics/side effect, catalog/artifact authorization/retention/erase, row-level domain ledger, broker retry/DLQ/operator reconciliation, PostgreSQL outage/recovery, partial-result/billing reconciliation과 executed live provider outage evidence는 Supported gate 전에 남습니다. AI Batch 운영 runbook이 pending, retention, delete의 운영 절차를 정의합니다.

우선순위 재정렬

  1. 운영과 security contract를 먼저 닫습니다. request ID, router outcome metrics, latency histogram, Prometheus export, OpenTelemetry bridge/W3C propagation/Collector receipt CI와 default Forwarded/explicit X-Forwarded-* proxy trust가 있습니다. Linux Nginx는 spoofed Forwarded overwrite와 gzip/identity Vary cache separation을 deployment contract로 고정합니다. production OTel policy, vendor CDN purge/TLS/cache-control verification과 OIDC/JWT/session failure는 모든 optional 기능의 공통 release blocker입니다.
  2. backend contract를 canonical container로 검증합니다. SQLx, Redis, MongoDB, NATS, RabbitMQ, Kafka는 unit test만으로 official support가 되지 않습니다. provider마다 happy path, outage, duplicate/retry, cancellation/drain을 고정합니다.
  3. job/event consumer lifecycle을 producer보다 먼저 완성합니다. 실제 가치와 위험은 enqueue/publish가 아니라 ack/commit 후 재전달, backpressure, shutdown에서 발생합니다.
  4. AI provider는 authorization과 spending policy를 함께 추가합니다. raw provider adapter만 먼저 공개하지 않고 tenant context, manual tool approval, redacted telemetry와 deterministic recorded-stream helper를 같은 release gate로 둡니다.
  5. RabbitMQ, SQS, Redis Streams는 공통 facade를 서두르지 않습니다. 각 provider가 NATS contract를 실제로 충족하는지 independent crate와 test matrix로 증명한 후 지원합니다.

지원선과 검증

  • workspace MSRV는 Rust 1.94.1입니다. 최신 MongoDB, Redis, async-nats driver line을 유지하는 이유와 migration rule은 ADR 0011에 기록합니다.
  • 기본 workspace는 native Kafka dependency를 강제하지 않습니다. rustee-events-kafka의 rdkafka feature는 CMake/librdkafka build와 실제 broker consumer lifecycle contract가 가능한 CI lane에서 별도로 실행합니다.
  • 기본 검증은 format, strict clippy, workspace unit/wire test입니다. official backend support의 완료 기준은 테스트 전략에 정의한 container contract suite입니다.
  • 문서에 존재하는 crate 이름은 구현 완료 선언이 아닙니다. 각 문서와 로드맵의 status 및 "남아 있는" 항목이 현재 release 범위를 결정합니다.

재검토 결론

Rustee의 다음 release 목표는 provider 수를 늘리는 것이 아니라 이미 지원하는 경계의 운영 의미를 닫는 것입니다. core HTTP API와 optional integration crate의 분리 원칙은 유지하고, 아래 순서가 바뀌려면 새 ADR과 real-backend contract가 필요합니다.

  1. Job provider 안정화: NATS, Redis Streams, RabbitMQ, SQS는 shared worker observer와 bounded metrics/trace를 구현했고 real broker success/retry-to-DLQ contract에서 outcome을 assertion합니다. RabbitMQ는 CI의 실제 Management API snapshot으로 native policy/delivery-limit/DLX route drift도 확인합니다. typed DLQ investigation/replay runbook도 고정했습니다. 다음은 broker outage, duplicate delivery, lease/ack loss와 deployment drift를 provider별로 검증하는 일입니다. SQS는 IAM/KMS failure와 Standard queue receive-count variation을, RabbitMQ는 Management TLS/ACL과 outage/duplicate matrix를 우선합니다.
  2. Security와 data exit criteria: outbox relay의 explicit shutdown-aware scheduling과 bounded aggregate report contract는 PostgreSQL suite에 고정했습니다. MongoDB replica-set suite도 explicit transaction commit/abort, change-stream checkpoint/shutdown, trusted tenant A/B BSON read/update/delete/first-match aggregation boundary와 tenant-field mutation rejection을 확인하고 PostgreSQL checkpoint suite는 opaque token load/upsert/corruption rejection과 database-clock writer-lease contention/renewal/expiry/stale-write rejection, stopped checkpoint-store readiness failure/recovery, combined suite는 new-client resume-to-next-event, stopped replica set은 bounded readiness failure와 restart recovery를 확인합니다. 다음은 exporter/alert policy, external IdP revocation lifecycle과 raw driver, aggregation $lookup/$unionWith, change-stream tenant access review를 실제 backend contract로 닫습니다. lease owner identity와 renewal scheduler는 application deployment가 문서화합니다. public security convenience API를 더하기 전에 fail-closed behavior와 operator procedure를 먼저 고정합니다.
  3. AI production qualification: real document source/vector adapter, opt-in live provider credential contract, atomic quota/pricing admission, provider lookup/refund policy, audit retention/retry worker를 tenant policy와 함께 검증합니다. MCP는 HTTP/stdio tool의 explicit no-replay recovery와 application/user-selected read-only context client를 고정했고, context adoption은 per-resource authorization/consent/redaction/token budget evidence가, OAuth는 credential rotation과 consent/rollback procedure가 같은 release gate로 증명될 때만 확장합니다. model provider나 automatic tool loop는 이 경계가 완성된 뒤에만 확장합니다.
  4. Enterprise topology: multi-tenant database, read/write split, Redis Cluster/Sentinel, MongoDB replica set/sharding은 workload-specific ADR, rollback/upgrade guide, supported-version matrix가 생길 때만 채택합니다.
  5. Release qualification: router와 OpenAPI route conversion은 PR property contract와 separate nightly libFuzzer corpus lane을 갖고, macOS/Windows는 every-PR Rust 1.94.1 workspace all-target compile과 MCP stdio fixture lifecycle을 실행합니다. 현재 official example인 hello-world, typed json-api, explicit middleware-example, security-jwt, jobs-example, ai-pipeline은 workspace compile 대상이며 JSON/middleware/security/job/AI representative flow를 in-process로 고정합니다. supported runtime/container platform matrix, provider matrix, header/query/body/range/state-machine fuzz, soak/benchmark, migration guide, real broker/OIDC/JWKS와 live AI provider qualification은 release gate로 남습니다. 이 단계 전에는 API surface를 넓히기보다 existing adapter의 breaking-change risk를 낮춥니다.
