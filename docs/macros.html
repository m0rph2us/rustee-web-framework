Optional Ergonomics

매크로는 기존 HTTP 계약만 구현합니다

rustee-macros는 non-macro Rustee API 위에 선택적으로 얹히는 편의 계층입니다. routes!는 기존 route registration 반복을 줄이고, FromHeader derive는 헤더 값을 newtype으로 읽는 반복을 줄입니다. 둘 다 handler 의미나 HTTP 정책을 추론하지 않습니다.

Route Builder

facade에서 rustee = { features = ["macros"] }를 선택한 뒤, one application builder expression과 explicit route registrations를 routes!에 전달합니다. path는 ordinary expression이며 application construction 때 기존 App validation을 거칩니다. 

let app = rustee::routes!(
    App::new().with_state(state);
    GET "/todos" => list_todos,
    POST "/todos" => create_todo,
    HEAD "/todos/:id" => todo_head,
);

GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS, TRACE, CONNECT를 지원합니다. custom HTTP method는 macro를 우회해 existing App::route를 사용합니다. macro는 at least one entry를 요구하지만 route pattern, handler signature, extractor, state, fallback과 middleware 의미는 바꾸지 않습니다.

Header Derive

facade에서 rustee = { features = ["macros"] }를 선택한 뒤, header name을 명시한 one-field tuple newtype에 #[derive(rustee::FromHeader)]를 붙입니다. 내부 field는 FromStr를 구현해야 합니다. 

#[derive(rustee::FromHeader)]
#[rustee(header = "x-request-id")]
struct RequestId(u64);

생성된 implementation은 기존 rustee::FromHeader trait과 Header<T> extractor를 사용합니다. parse 또는 header text decoding 실패는 기존 Rustee bad_request boundary로 끝나며, header value를 error에 포함하지 않습니다.

의도적인 제한

  • routes!는 new router type이나 attribute route registration을 만들지 않고, supplied builder expression에 existing method call만 연결합니다.
  • custom method, route pattern validation, duplicate route policy, handler/extractor inference와 middleware order는 manual App API가 소유합니다.
  • header name attribute는 필수이며 HTTP header-name 문법을 compile time에 검사합니다.
  • named field, unit struct, multiple-field tuple struct, enum과 union은 지원하지 않습니다.
  • derive는 handler, middleware, authorization, response status, OpenAPI schema 또는 security scheme를 생성하거나 추론하지 않습니다.
  • facade의 hidden re-export는 generated code용 안정 경로일 뿐 application이 import할 public API가 아닙니다.
  • custom validation, multi-header aggregation, domain error/status mapping은 application의 manual FromHeader implementation으로 남습니다.

컴파일 계약

trybuild suite는 valid newtype과 missing header attribute, wrong struct shape, invalid header name, valid standard methods, unsupported method, missing route entry를 각각 고정합니다. Fast PR과 release qualification은 facade macros feature에서 header parse와 route dispatch regression, 이 diagnostic suite를 실행합니다. workspace-only consumer fixture는 renamed Cargo dependency에서도 derive와 route builder의 generated code가 facade alias를 찾는지 확인합니다. Rustee facade 자체는 application dependency로 남아야 합니다.

확장 규칙

attribute route macro, schema derive 또는 handler signature inference는 현재 기능의 follow-up이 아닙니다. 추가하려면 non-macro API parity, generated HTTP semantics의 ownership, semver/diagnostic compatibility, compile-fail fixture와 별도 ADR을 먼저 정합니다.

관련 결정

public boundary는 ADR 0040과 ADR 0041을 따릅니다. 테스트와 출하 증거는 테스트 전략, 현재 지원 상태는 지원 현황에서 확인합니다.
