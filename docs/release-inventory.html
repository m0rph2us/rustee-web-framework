Release Inventory

Workspace Release Inventory

The inventory distinguishes packages that may be published from workspace-only support packages. Publication intent is checked from package metadata, not inferred from directory presence.

Verification Rules

  • Run node scripts/check-release-inventory.mjs before a release candidate; CI also runs its --self-test boundary cases.
  • Every publish candidate has an intentional package name, version, the repository's MIT OR Apache-2.0 SPDX license expression, repository, Rust version, documentation policy, and publish setting.
  • A publish candidate may not use a workspace-only package through a normal or build dependency; fixture-only dependencies must stay dev-only.
  • Workspace-only packages such as test fixtures, internal support, fuzz harnesses, and examples remain explicitly unpublished.
  • The inventory checker, source-archive assembler, and post-publication consumer verifier use the same metadata-generated inventory loader.
  • Inventory changes require release-plan, support-matrix, and release-note review.

Publication Boundary

Candidate packages are the public facade, foundational shared crates, and individual optional integration crates intended for external consumption. The exact list is generated and verified from the workspace manifest and release scripts. No package is published merely because it compiles or appears in documentation.

Approval Boundary

Adding, removing, renaming, or changing a package's publish intent requires maintainer approval, source-package review, dependency/license review, release evidence, and a support statement. A package with external-provider code remains Experimental until its provider qualification requirements are satisfied.
