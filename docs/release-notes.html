v0.1.0

Status: Draft / Unreleased. Date: not assigned.

2026-08-04 현재 첫 intentional source baseline commit은 존재하지만 v0.1.0 source tag와 registry publish record는 없습니다. 이 항목은 initial release의 review template이며 published artifact나 Supported declaration이 아닙니다.

Planned baseline

  • HTTP/1.1 origin, router, typed extractor, Tower middleware, timeout/body/concurrency limit, graceful shutdown과 cleartext origin deployment boundary를 제공합니다.
  • trusted reverse proxy CIDR, default Forwarded/explicit X-Forwarded-* restoration, static delivery, conditional/range response와 opt-in compression은 framework candidate surface입니다.
  • typed configuration/redaction, request correlation, bounded metrics, Prometheus helper, optional OpenTelemetry bridge와 opt-in panic-to-redacted-500 boundary는 application-owned deployment policy와 함께 사용합니다.
  • rustee-openapi는 선택 feature로 explicit OpenAPI 3.1 document, JSON route와 HTTP Basic/Bearer, API key, OpenID Connect, Authorization Code/Client Credentials OAuth2 및 mutualTLS security metadata, document-wide default/anonymous/clear operation override를 제공합니다. mutualTLS는 deployment의 client-certificate contract를 문서화할 뿐이며 Rustee가 TLS를 종료하거나 인증서를 검증하지 않습니다. route handler, token lifecycle, runtime authorization, error semantics 또는 schema derive를 자동 추론하지 않습니다.
  • rustee-auth는 explicit header-only ApiKeyLayer와 HMAC-SHA-256 KeyedApiKeyAuthenticator/ApiKeyFingerprintStore 경계를 제공합니다. optional rustee-auth-sqlx는 PostgreSQL fingerprint record, active/revoked/expiry lookup, no-overlap rotation과 atomic successful-auth audit reference adapter를 제공합니다. missing/repeated/malformed key는 provider 전에 401로 거부하고 provider outage는 sanitized 503으로 처리합니다. static mapping은 local/test only이며 production pepper/KMS migration, store outage/recovery, retention과 tenant/permission mapping은 application integration이 소유합니다.
  • rustee-macros는 facade macros feature에서 explicit header name의 single-field tuple newtype에만 FromHeader implementation을 생성합니다. route/handler/authorization/schema를 생성하거나 추론하지 않습니다.
  • rustee::routes!는 standard HTTP method registration을 existing App builder chain으로 확장합니다. handler signature, route validity, custom method, authorization과 schema는 기존 application API가 계속 소유합니다.
  • rustee-jobs-cron-sqlx는 PostgreSQL outbox를 통해 IANA time-zone recurring job을 materialize하는 optional candidate입니다. UTC default와 durable RecurringJobTimeZone, DST forward-gap skip/overlap-earlier-once policy, forward migration과 definition-drift conflict를 제공합니다. optional shared-key PostgreSQL fixed-window governor는 capacity consume 또는 no-outbox defer를 same transaction으로 처리하고, optional pass observer와 separate Prometheus helper는 fixed outcome/aggregate count/global duration만 export합니다. tzdb update qualification, holiday calendar, catch-up, tenant fairness/daily quota, external-provider quota와 worker/alert runtime은 deployment policy로 남습니다.
  • database, auth, queue, event, AI crate는 independent optional integrations입니다. 현재 release status와 provider-specific limitation은 지원 현황 매트릭스가 단일 기준입니다.

Support statement

first source baseline 전에는 어떤 crate도 Supported 또는 Enterprise-qualified로 선언하지 않습니다. F1 candidate, Experimental, Contract-verified는 implementation과 contract evidence의 상태이며 public production adoption promise가 아닙니다. tag가 만들어질 때 대상 crate, supported Rust version, platform evidence와 support level을 이 항목에 명시합니다.

Known limitations to retain at release

  • direct TLS, HTTP/2, WebSocket/protocol upgrade, generic ORM, universal queue facade와 automatic schema migration은 initial framework scope 밖입니다.
  • TLS certificate, CDN cache/purge, edge compression, origin isolation과 panic restart는 framework가 아니라 application/deployment 책임입니다.
  • external provider credential, billable AI invocation, production IAM/KMS/ACL topology는 CI green check만으로 qualification되지 않습니다.

Release evidence to attach

final note는 exact source tag, published crate version/checksum, qualification workflow, SBOM/provenance artifact, dependency advisory result, support-matrix delta와 migration guidance를 연결합니다. exact procedure는 release checklist를 따릅니다.

후속 release 작성 규칙

  • 각 version에는 release date, source tag, publish 대상 crate와 checksum verification result를 씁니다.
  • Added, Changed, Fixed, Security, Deprecated, Removed, Known limitations와 support-level delta를 독립 항목으로 기록합니다.
  • breaking change는 affected public type/feature/configuration, migration destination, rollback limit을 migration guide의 versioned section으로 연결합니다.
  • provider feature를 Supported 또는 Enterprise-qualified로 올릴 때는 real backend/topology evidence와 operator procedure를 함께 연결합니다.
