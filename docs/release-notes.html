Release Notes

Record Public Changes and Support Commitments Together

Release notes describe what was published, which contracts changed, what support is claimed, and which qualification or operational limitations remain.

v0.1.0

  • Establishes the Rustee core HTTP, routing, server, middleware, configuration, observability, OpenAPI, static delivery, compression, test, and macro boundaries.
  • Publishes optional integration boundaries for SQLx, Redis, MongoDB, authentication, durable jobs, Kafka event streams, AI application features, MCP, and related operational helpers.
  • Documents examples, support levels, release evidence, migration expectations, and explicit non-goals.
  • Provider, topology, edge, external identity, and live AI qualification remain evidence-gated and must be read through the support matrix and qualification register.

Rules for Future Releases

  • Include version, date, source/tag, public packages, user-visible changes, breaking changes, migration steps, MSRV/dependency changes, support-level changes, known limitations, and provenance.
  • Link directly to focused documentation, ADRs, migration procedures, qualification records, and package inventory changes.
  • Do not include secrets, raw payloads, credentials, private endpoints, or unreviewed incident data.
