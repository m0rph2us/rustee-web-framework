Event Schema Rollout

source-controlled JSON Schema artifact와 application-owned registry adapter를 사용해 event version을 배포하는 절차입니다.

운영 전제

rustee-events-schema는 registry service가 아닙니다. typed Event::TYPE/VERSION, subject, declared compatibility, exact JSON Schema source와 fingerprint를 local catalog로 검증하고 registry adapter의 acknowledgement가 정확히 같은 artifact인지 확인합니다. remote compatibility semantics, endpoint/credential, topic mapping, schema ID wire header와 runtime registration timing은 application deployment가 정합니다. optional rustee-events-schema-confluent는 Confluent-compatible REST contract를 구현하지만 deployment authority를 가져오지 않습니다.

  • subject는 하나의 stable event type에만 연결합니다. version duplicate와 subject의 event type/compatibility policy drift는 catalog build에서 거부됩니다.
  • fingerprint는 format identifier와 exact schema source bytes의 SHA-256입니다. whitespace-only 변경도 reviewed artifact change로 취급합니다.
  • Confluent adapter는 non-loopback HTTPS endpoint, bounded per-request timeout과 redacted Basic/bearer authentication을 요구합니다. effective compatibility policy를 local declaration과 비교하고 exact lookup, absent artifact register, exact relookup을 수행하지만 registry config를 mutation하지 않습니다.
  • schema definition에는 product field가 드러날 수 있습니다. source artifact는 review 가능해야 하지만, raw definition을 generic log, metric label이나 incident ticket에 무제한 복사하지 않습니다.
  • schema registry 성공은 consumer upcaster, external side-effect idempotency, replay safety 또는 Kafka offset correctness를 보장하지 않습니다.

배포 순서

  1. event type, subject, source/current version, compatibility direction, affected topic/consumer groups, retention window와 rollback deadline을 change record에서 승인합니다.
  2. JSON Schema artifact와 typed EventSchema declaration을 source control에서 함께 변경하고 catalog unit test로 subject/version/policy drift와 registry acknowledgement mismatch를 확인합니다.
  3. non-production registry에서 application adapter를 이용해 compatibility check/register-or-verify를 실행합니다. Confluent adapter는 effective policy, lookup/register/relookup의 subject/version/exact source evidence를 남깁니다. registry ACL/credential scope와 prior artifact inventory도 함께 남깁니다.
  4. backward-compatible 변경은 new consumer와 explicit EventUpcaster를 먼저 배포하고 current/older retained record를 replay group에서 dry-run 합니다. forward-only 또는 full policy는 old consumer fleet, separate topic 또는 additional migration plan을 명시적으로 검토합니다.
  5. production registry verification을 approved deployment phase에서 실행한 뒤 producer를 전환합니다. Rustee는 consumer loop 중 자동 등록, topic 생성, schema header 삽입 또는 source group offset reset을 수행하지 않습니다.
  6. rollout 동안 decode failure, upcast rejection, consumer lag, retry/DLQ age, downstream duplicate suppression을 확인하고 rollback deadline을 넘기기 전에 producer/consumer compatibility window를 닫습니다.

Rollback과 Replay

  • schema artifact를 원격 registry에서 임의 삭제하거나 subject compatibility policy를 in-place로 낮추지 않습니다. retained record를 읽는 consumer와 replay group이 기존 artifact를 계속 요구할 수 있습니다.
  • producer rollback은 retained newest payload를 old consumer가 해석할 수 있는지와 downstream idempotency를 먼저 확인합니다. 검증되지 않은 경우 new consumer group 또는 versioned topic으로 isolate합니다.
  • replay는 source topic, partition/offset range, schema versions, upcaster, registry artifact fingerprints, consumer group, side-effect idempotency key와 rate limit을 승인 record에 남깁니다.
  • registry outage는 application deployment policy에 따라 schema rollout을 멈추거나 pre-verified immutable artifact로 제한합니다. framework가 cached schema를 성공으로 추측하거나 provider retry policy를 선택하지 않습니다.

Confluent live qualification

rustee-events-schema-confluent에는 실제 Confluent-compatible registry를 위한 ignored contract test가 있습니다. 이 test는 unique rustee-live-qualification-*-value subject에 version 1 JSON Schema를 등록하고 삭제하지 않습니다. approval된 non-production registry와 subject write/read, configuration read 권한이 있는 credential에서만 실행합니다. 

RUSTEE_CONFLUENT_SCHEMA_REGISTRY_LIVE=1 \
RUSTEE_CONFLUENT_SCHEMA_REGISTRY_URL=https://registry.example.test/ \
RUSTEE_CONFLUENT_SCHEMA_REGISTRY_API_KEY=... \
RUSTEE_CONFLUENT_SCHEMA_REGISTRY_API_SECRET=... \
cargo test -p rustee-events-schema-confluent --test confluent_live_contract -- --ignored
  • Basic key/secret 대신 RUSTEE_CONFLUENT_SCHEMA_REGISTRY_BEARER_TOKEN 하나를 사용할 수 있습니다. 두 방식은 같이 설정하지 않습니다.
  • test는 effective compatibility가 BACKWARD인지를 먼저 확인합니다. 다른 global/subject policy를 쓰는 환경은 이 test를 변경하지 말고 해당 policy의 reviewed catalog와 별도 qualification case를 만듭니다.
  • registry URL, credential 값, raw schema source를 CI log나 ticket에 출력하지 않습니다. provider/version, subject, policy, test run ID, result와 retained-subject cleanup/retention owner만 release evidence로 남깁니다.

증거와 소유자

항목필요한 증거소유자
artifacttyped declaration, exact fingerprint, compatibility direction, source reviewevent producer owner
registryprovider version, subject/ACL/credential scope, local HTTP contract와 non-production live qualification, production verification resultmessaging platform owner
consumerolder-record upcast/decode suite, consumer-first rollout, rollback window and lag/DLQ observationprojection owner
replayapproved range, isolated-group dry-run, downstream idempotency and reconciliation resultapplication and domain owner

Confluent-compatible local HTTP contract가 있어도 실제 registry provider/version, credential lifecycle, remote compatibility semantics, wire format and schema ID, multi-region replication evidence가 없으면 integration은 Contract-verified보다 높게 선언하지 않습니다.
