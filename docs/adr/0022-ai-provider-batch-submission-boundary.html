ADR 0022

AI provider batch submission boundary

Status: Accepted. Date: 2026-08-03.

Context

Provider asynchronous batch APIs have different upload, idempotency, cancellation, partial-result, billing and retention semantics. Serializing a raw prompt set into a generic queue payload or retrying an uncertain submission can disclose data or create duplicate provider charges.

Decision

Batch is a content-free control-plane reference plus an atomic submission ledger, not a generic async loop.

  • AiBatchReference contains only opaque tenant/policy scope, catalog ID and stable run key. The application catalog loads raw work after worker authorization; Rustee never serializes the work.
  • AiBatchSubmitter reserves the exact reference before catalog load and submits at most once. A recorded receipt is returned to duplicate delivery without provider contact.
  • Provider error leaves the reservation pending. Rustee does not automatically retry, cancel, poll, infer billing or resubmit. Application reconciliation chooses provider-specific recovery.
  • Receipt-record failure exposes only a safe provider batch ID for reconciliation. Provider adapters own native idempotency headers, limits, upload format, polling, partial result retrieval, cancellation and billing semantics.

Consequences

  • Production needs a durable atomic ledger and a catalog authorization/retention/erase procedure. The initial in-memory ledger is only for deterministic local tests.
  • Queue adapters may carry the reference and run key, never raw batch work. Job retry is safe only because the ledger returns existing receipt or pending ambiguity rather than resubmitting.
  • Exact-key response cache and evaluation remain separate contracts. Batch does not introduce automatic tool execution, cache warming, semantic memory or provider retry.

Alternatives

대안판단
raw prompt set을 rustee-jobs JSON payload로 저장queue retention과 authorization boundary가 흐려져 채택하지 않는다.
provider error 뒤 즉시 retryaccepted-but-unacknowledged batch의 duplicate cost를 만들 수 있어 채택하지 않는다.
provider polling/cancel/result API를 core trait으로 강제provider별 lifecycle과 billing 의미가 달라 adapter별 후속 contract로 둔다.

Follow-up

  • rustee-ai-batch은 reference, receipt, catalog, atomic ledger, no-retry submitter와 in-memory test ledger를 구현한다.
  • rustee-ai-batch-jobs은 reference-only durable job과 run-key validation handler를 구현한다.
  • first provider adapter adds upload/poll/result/cancel/partial failure/billing/reconciliation live evidence without widening the core contract.
