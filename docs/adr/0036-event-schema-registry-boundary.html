ADR 0036

Event Schema Registry Boundary

schema artifact의 typed identity와 registry verification을 제공하되, provider protocol과 rollout authority는 application deployment에 둡니다.

Status: Accepted | Date: 2026-08-04

Context

versioned event envelope의 decode/upcast contract만으로 producer와 consumer fleet의 schema change를 안전하게 배포할 수는 없습니다. subject, version, compatibility direction, source artifact, registry response와 retained record의 rollout window를 함께 검토해야 합니다. 반면 framework가 특정 registry endpoint를 고정하거나 consumer loop에서 schema를 자동 등록하면 credential ownership, startup failure, broker wire format, topic lifecycle과 release ordering을 hidden side effect로 만들게 됩니다.

Decision

rustee-events-schema는 Event type에 묶인 JSON Schema artifact, format-plus-exact-source SHA-256 fingerprint, stable subject/version catalog와 object-safe EventSchemaRegistry adapter contract를 제공합니다. catalog는 duplicate version과 subject의 event type/declared compatibility policy drift를 거부하고, registry acknowledgement의 subject/version/fingerprint가 local artifact와 정확히 일치하는지만 확인합니다.

registry adapter implementation, remote compatibility semantics, endpoint/credential/ACL, publication and verification timing, topic mapping, schema ID/header serialization, consumer-first rollout과 rollback authority는 application deployment가 소유합니다. Rustee는 schema를 자동 publish하지 않고, Kafka topic을 만들거나, source offset을 변경하거나, JSON Schema 두 문서의 의미적 compatibility를 추론하지 않습니다.

첫 provider adapter인 optional rustee-events-schema-confluent는 Confluent-compatible REST endpoint의 effective policy를 local declaration과 equality check하고 exact lookup, absent artifact registration, exact relookup을 수행합니다. external endpoint는 HTTPS이고 request는 bounded하며 Basic/bearer credential은 Debug surface에서 redacted됩니다. 이 adapter도 registry policy mutation, Kafka wire header, serializer, topic/offset management와 automatic retry를 제공하지 않습니다.

Consequences

  • artifact는 source control과 typed Rust event version에서 함께 review됩니다. format identifier와 exact source bytes가 fingerprint input이므로 whitespace-only 변경도 explicit review가 필요합니다.
  • declared Backward, Forward, Full, None policy는 local catalog에서 stable하지만, semantic enforcement는 remote registry adapter와 provider qualification의 책임입니다.
  • registry success는 older payload upcast, retained record replay, Kafka offset correctness 또는 external side-effect exactly-once를 보장하지 않습니다. consumer-first deployment, replay dry-run과 idempotency evidence가 계속 필요합니다.
  • adapter error detail은 generic framework error text/metric label로 흘리지 않습니다. application은 provider audit, credential rotation과 incident retention을 별도 policy로 정합니다.
  • 현재 artifact format은 JSON Schema입니다. Avro, Protobuf 또는 provider-specific normalization은 별도 typed contract와 compatibility evidence가 준비된 뒤 검토합니다.
  • Confluent adapter는 local HTTP contract로 policy mismatch, lookup/register/relookup과 credential redaction을 검증합니다. explicit ignored live qualification은 approved non-production registry의 unique retained subject와 effective BACKWARD policy를 요구합니다. 실제 provider version, ACL/credential rotation, outage, multi-region behavior와 consumer rollout은 deployment qualification이 필요합니다.

Alternatives

대안판단
Kafka producer가 provider registry를 직접 호출하고 header를 자동 삽입publish latency, credential, provider wire format과 failure policy를 framework core에 고정하므로 채택하지 않습니다.
framework가 두 JSON Schema를 비교해 compatibility를 판정provider semantics와 language feature 차이를 일반 비교기로 잘못 단순화하므로 채택하지 않습니다.
consumer handler가 시작될 때 schema를 등록read path에 external mutation과 startup ordering을 숨기므로 채택하지 않습니다.
schema fingerprint에 parsed JSON canonical form을 사용source artifact의 실제 변경과 provider normalization 차이를 감추므로 채택하지 않습니다.
