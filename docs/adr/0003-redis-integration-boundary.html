ADR 0003: Redis Integration Boundary

Status: Accepted

Context

Redis is useful for caching, opaque sessions, rate limits, and Streams, but hides important consistency and availability choices when treated as framework global state.

Decision

Provide optional client, state-store, rate-limit, session, and Streams job integrations. Require visible namespaces, TTLs, bounded readiness, and explicit failure policy.

Consequences

Rustee does not provide an automatic HTTP cache or universal distributed lock. Applications own topology, TLS, credentials, invalidation, retention, retries, and degraded-service behavior.
