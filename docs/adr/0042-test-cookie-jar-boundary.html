TestApp cookie jar boundary

in-process session test에는 작은 opt-in cookie jar를 제공하지만, browser semantics나 production session policy를 재구현하지 않습니다.

Context

Rustee session manager는 login/rotation에서 Set-Cookie를 append하고 logout에서 Max-Age=0을 반환합니다. 기존 TestApp은 request와 bounded response를 빠르게 검증하지만 response cookie를 보존하지 않아 login 뒤 protected route, rotation, logout 흐름이 매번 raw Cookie header 조립을 요구했습니다. 반대로 in-process URI에는 browser origin과 transport가 없으므로 browser jar를 흉내 내면 잘못된 보안 보장을 만들 수 있습니다.

Decision

  • TestApp::with_cookie_jar()로만 stateful jar를 켭니다. 기본 TestApp은 기존처럼 stateless이며 clone은 enabled jar를 공유합니다.
  • jar는 response Set-Cookie의 valid ASCII name/value first pair만 보존하고, Max-Age=0을 deletion으로 해석합니다.
  • 한 jar는 최대 64 entries와 combined name/value 8 KiB로 고정합니다. malformed cookie와 bound 초과는 value를 render하지 않는 sanitized error로 반환합니다.
  • response body가 configured bound 안에서 완전히 read된 뒤에만 모든 cookie update를 한 번에 적용합니다. failed body read, oversized body, malformed cookie와 capacity error는 prior jar state를 유지합니다.
  • caller가 request Cookie header를 직접 넣으면 jar는 merge하거나 덮어쓰지 않습니다. explicit header가 test의 security/input intent를 소유합니다.
  • Domain, Path, Secure, HttpOnly, SameSite, Expires, nonzero Max-Age, redirect, origin, port와 cross-site policy는 평가하지 않습니다. production cookie/session implementation도 소유하지 않습니다.

Consequences

  • session-style happy path와 logout/rotation test는 raw cookie parsing 없이 concise하게 유지되며, malformed response와 failed bounded response가 state를 남기지 않는 contract를 갖습니다.
  • TestCookieJar은 clear/entry count만 public inspection으로 제공하고 stored name/value를 debug 또는 convenience API로 노출하지 않습니다.
  • secure transport, same-site CSRF behavior, cookie path/domain matching, expiration timing, redirect delivery와 browser interop은 real TCP/browser suite가 계속 증명합니다.

Alternatives

대안판단
기본 TestApp에서 항상 cookie를 유지기존 stateless request test에 보이지 않는 state를 추가하고, raw cookie security test의 의도를 흐립니다.
full browser cookie implementationorigin, TLS, clock, redirect와 same-site context가 없는 in-process client가 browser security behavior를 보장하는 것처럼 보이게 합니다.
session crate가 TestApp 전용 adapter를 제공published test helper와 session policy를 결합시키고 generic cookie response test를 막습니다.
unbounded map과 public cookie value accessortest helper가 resource/secret retention surface가 되는 것을 피할 수 없습니다.

Follow-up

browser-policy emulation, redirect-aware test client 또는 public cookie-value inspection을 검토할 때에는 HTTPS/origin model, deterministic clock, security semantics, API compatibility와 real browser/wire evidence를 포함한 새 ADR이 필요합니다.
