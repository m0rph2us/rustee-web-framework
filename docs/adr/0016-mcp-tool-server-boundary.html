ADR 0016

MCP server boundary

Status: Accepted. Date: 2026-08-03.

Context

Rustee application의 typed tool과 read-only contextual data는 internal model loop뿐 아니라 external MCP client에게도 노출될 수 있다. 하지만 tool definition은 caller authorization, tenant scope, user confirmation 또는 side-effect idempotency를 설명하지 않는다. unauthenticated tools/list은 privileged capability inventory를 노출할 수 있고, client-selected JSON-RPC ID를 external action idempotency key로 쓰면 replay 또는 collision을 application이 통제할 수 없게 된다.

Decision

rustee-mcp::McpServer은 App::nest에 mount할 수 있는 stateless Streamable HTTP JSON server다. 2025-11-25 initialize, initialized notification, tools/list, tools/call을 제공하며, constructor는 application McpToolAccessPolicy, ToolApprovalPolicy, ToolExecutionAuditSink를 모두 요구한다. optional McpContextProvider는 explicit read-only resources/list, resources/templates/list, resources/read, prompts/list, prompts/get만 제공할 수 있다.

  • access policy는 verified authentication middleware가 넣은 request extension에서 caller를 읽어 visible registered tool만 선택한다. server는 permitted set 밖 tool을 목록과 execution 양쪽에서 거부한다.
  • server는 Origin header가 없는 native MCP request만 default로 다음 policy에 넘긴다. header가 있으면 configured canonical HTTP(S) allowlist에 없을 때 403으로 거부한다. allowlist는 DNS rebinding defense이며 authentication이나 CORS response policy가 아니다.
  • access policy는 application-created ToolExecutionContext를 만든다. JSON-RPC ID, caller argument, remote metadata는 idempotency key source가 아니다.
  • visible call은 ToolRegistry::execute_with_execution_audit로만 실행한다. approval audit은 handler 전, terminal outcome audit은 handler 후에 기록된다. terminal audit failure는 rollback으로 표현하지 않는다.
  • context provider는 authenticated request를 직접 받고 tenant/user/data authorization을 수행한다. tool visibility 또는 execution context를 재사용해 context access를 허용하지 않으며, context access도 tool execution capability를 만들지 않는다.
  • provider가 선언한 capability만 initialize response에 광고한다. server는 no-pagination list, selected read URI equality, duplicate identifier, configured item bound와 successful response byte bound를 검증하고 raw provider failure를 반환하지 않는다.
  • raw access/approval/audit/handler error, hidden tool name detail, tool output은 failure response에 넣지 않는다. denied 또는 failed call은 generic MCP isError result를 반환한다.
  • request와 successful response는 configured byte bound를 갖는다. JSON response error는 small fixed payload로 남겨 observability와 client behavior를 예측 가능하게 한다.
  • access policy는 synchronous request-time decision이다. async identity lookup은 auth middleware나 request extension materialization 단계에서 완료해 streaming request body를 await 경계로 잡지 않는다.

Consequences

  • external MCP client도 existing Rustee tenant/approval/audit path를 우회할 수 없다.
  • application은 resource/prompt metadata와 body를 remote client에 공개해도 되는 데이터로 명시적으로 선별해야 하며, model/provider context로의 별도 채택에는 ADR 0017의 selection, redaction, budget policy가 계속 필요하다.
  • application은 endpoint authentication, caller-to-tool mapping, semantic-action idempotency key, audit retention/reconciliation과 browser deployment의 CORS policy를 deployment policy로 명시해야 한다.
  • server는 session lifecycle, Streamable HTTP SSE GET, stdio, resource/prompt subscription/completion, sampling/elicitation, OAuth authorization, dynamic inventory notification을 아직 제공하지 않는다.
  • server integration은 core HTTP/router에 MCP protocol type을 넣지 않고 optional crate/Tower service로 유지된다.

Alternatives

대안판단
모든 registry definition을 모두에게 노출privileged capability inventory가 새므로 application access policy로 필터링한다.
모든 Origin header를 허용하거나 wildcard allowlistlocal MCP endpoint의 DNS rebinding risk를 키우므로 header-present request는 exact normalized allowlist가 없으면 거부한다.
JSON-RPC ID를 tool idempotency key로 재사용caller-controlled replay key가 되므로 application이 trusted semantic key를 만든다.
audit 없는 direct tool executionexternal capability의 side effect reconciliation을 약화하므로 terminal audit sink를 constructor requirement로 둔다.
access policy를 async request future로 노출Rustee streaming body가 Sync가 아니며 request lifetime/cancellation을 흐리므로 prior middleware materialization을 요구한다.

Follow-up

  • session/SSE GET과 stdio는 cancellation, process lifecycle, backpressure, auth failure contract를 별도로 구현한다.
  • resource/prompt subscription/completion, OAuth authorization와 dynamic inventory notification은 caller authorization, credential rotation, compatibility/rollback matrix가 정해진 뒤 검토한다.
  • Supported 승격에는 real transport interoperability matrix, endpoint auth/rotation procedure, audit reconciliation runbook과 upgrade evidence가 필요하다.
