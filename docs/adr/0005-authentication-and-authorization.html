ADR 0005: Authentication and Authorization Boundary

Status: Accepted

Context

Authentication transports vary, while authorization and tenant isolation need stable, provider-neutral service contracts.

Decision

Normalize verified identity into Principal; keep bearer, JWT, JWKS, OIDC, opaque-token, session, and API-key adapters optional; apply explicit permission/role policy and verified tenant resolution after authentication. Principal identity fields have fixed byte bounds, each authorization value and set has a fixed bound, and serde restoration revalidates the same contract. Principal and authorization-policy Debug output retains only safe aggregate counts rather than identity, scope, role, or permission values.

Consequences

Store outages fail closed. Oversized or malformed verified claims and persisted principal data are rejected before request use. Application and deployment own issuer/key policy, identity lifecycle, resource ownership, data-layer isolation, advanced authorization, credentials, and provider qualification.
