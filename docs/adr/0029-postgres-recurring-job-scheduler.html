ADR 0029

PostgreSQL recurring job scheduler의 경계

Status: Accepted. Date: 2026-08-03.

Context

one-time delay는 outbox row의 available_at으로 durable하게 처리할 수 있지만, recurring job은 template, next occurrence, process restart와 multi-replica ownership을 별도로 보장해야 합니다. memory timer는 restart에 state를 잃고, cron callback이 broker에 직접 publish하면 next-run update와 publish 사이에 dual-write gap이 생깁니다. 같은 job envelope ID를 반복해서 쓰면 broker/consumer idempotency semantics도 깨집니다.

Decision

optional rustee-jobs-cron-sqlx crate를 채택합니다. deployment는 outbox migrations 뒤 0001_rustee_recurring_jobs.sql을 적용하고 governor를 쓸 때 0002_rustee_recurring_job_rate_governor.sql을 뒤이어 적용합니다. typed payload, job name/version, destination, cron expression, priority와 next run을 PostgreSQL에 저장하고, application-owned PostgresRecurringJobs supervisor가 bounded fire_due pass를 호출합니다.

각 pass는 PostgreSQL clock을 읽고 due schedule을 FOR UPDATE SKIP LOCKED로 lock합니다. lock된 row마다 fresh JobId와 schedule occurrence idempotency key를 가진 envelope을 rustee-outbox-sqlx에 stage하고, next run 및 last-fired timestamp를 같은 transaction에서 갱신합니다. commit 전 error 또는 cancellation은 stage와 advance를 함께 rollback합니다. application key의 identical re-registration만 idempotent하게 허용하고, definition drift는 explicit conflict로 거부합니다.

Consequences

  • 여러 scheduler replica는 due row를 중복 materialize하지 않고, crash 뒤 committed schedule/outbox state만 다시 처리합니다.
  • late schedule은 schedule당 한 fresh job만 stage하고 database clock 뒤의 첫 occurrence로 advance합니다. 모든 missed tick을 replay하지 않습니다.
  • IANA time-zone/DST calendar는 ADR 0033을 따릅니다. holiday calendar와 tenant-specific calendar policy는 framework가 추측하지 않습니다.
  • pause는 future selection만 막습니다. resume는 paused 기간의 tick을 replay하지 않고 database clock 다음 local occurrence로 다시 시작합니다. 어느 쪽도 이미 committed outbox row를 retract하거나 downstream worker를 cancel하지 않으므로 application cancellation policy가 별도로 필요합니다.
  • scheduler는 worker, relay, metrics exporter, polling cadence 또는 alert threshold를 자동으로 시작하지 않습니다. readiness, backoff, capacity와 shutdown은 deployment가 소유합니다.
  • outbox priority는 local relay claim order만 바꾸며 fairness 또는 broker-level ordering을 제공하지 않습니다. shared-key fixed-window scheduler governor는 ADR 0030의 별도 PostgreSQL transaction boundary이며, tenant fairness와 external-provider quota를 제공하지 않습니다. priority 경계는 ADR 0028과 함께 해석합니다.

Alternatives

대안판단
process-local cron timerrestart, multi-replica ownership과 transaction rollback에서 schedule state가 사라져 채택하지 않습니다.
cron callback이 broker에 직접 publishnext occurrence update와 broker publish가 atomic하지 않고 outbox boundary를 우회하므로 채택하지 않습니다.
provider별 recurring queue APINATS, Redis Streams, RabbitMQ와 SQS의 capability와 calendar semantics를 하나의 promise로 숨기므로 채택하지 않습니다.
automatic all-missed-occurrence replayoutage 뒤 downstream 폭주와 external side effect duplication risk를 기본값으로 만들므로 채택하지 않습니다. catch-up은 explicit future policy여야 합니다.
host-local time zone/DST를 framework default로 설정지역, tenant와 domain마다 다른 configuration을 host setting에 숨기므로 채택하지 않습니다. stored IANA zone과 explicit DST policy는 ADR 0033을 따릅니다.

Last updated: 2026-08-04. ADR 0030 adds the fixed-window governor; ADR 0033 supersedes this record's UTC-only time-zone limitation. Catch-up policy와 framework-owned scheduler runtime은 여전히 별도 ADR이 필요합니다.
