ADR 0032

Job delivery Prometheus exporter 경계

Status: Accepted. Date: 2026-08-03.

Context

NATS, Redis Streams, RabbitMQ와 SQS worker는 동일한 JobDeliveryObserver lifecycle과 JobMetrics collector를 사용하지만, application마다 ad-hoc exporter를 만들면 outcome, histogram, label escaping과 cache policy가 달라질 수 있습니다. worker delivery의 payload, queue route, receipt handle과 raw error는 metric에 포함되어서는 안 됩니다.

Decision

rustee-jobs-observability-prometheus를 JobMetrics의 optional text 0.0.4 adapter로 둡니다. encode/encode_snapshot과 explicit metrics_response만 제공하며, response는 Cache-Control: no-store를 갖습니다.

exporter는 started/in-flight/completed, collector가 이미 열여섯 값으로 제한한 provider와 fixed outcome, global delivery duration histogram만 내보냅니다. provider label은 Prometheus text escaping을 적용합니다. registry, listener, automatic route, authentication, alert threshold, broker health check나 DLQ replay는 만들지 않습니다.

Consequences

  • NATS, Redis Streams, RabbitMQ와 SQS worker가 하나의 exporter contract를 공유하되 broker-specific backlog/visibility/consumer signal은 각 adapter 운영 문서에 남습니다.
  • job ID, job type/version, delivery attempt, idempotency key, queue/stream URL/name, payload, receipt handle, trace carrier, tenant와 raw handler/broker error는 label 또는 metric value로 내보내지 않습니다.
  • application은 protected 또는 network-isolated scrape route를 명시적으로 mount하고, alert owner/threshold와 retention을 deployment evidence로 관리합니다.

Alternatives

대안판단
각 broker adapter가 독자 Prometheus registry를 제공중복 lifecycle과 inconsistent label/retention policy를 만들므로 채택하지 않습니다.
job type, route 또는 message ID를 label로 exportunbounded cardinality와 payload/business topology 노출을 만들므로 채택하지 않습니다.
exporter가 broker probe, alert와 automatic replay를 수행credential, topology와 side-effect authority를 framework가 소유하게 되므로 채택하지 않습니다.
