ADR 0031

PostgreSQL scheduler pass observability 경계

Status: Accepted. Date: 2026-08-03.

Context

recurring scheduler는 due row를 transaction 안에서 outbox로 materialize하거나 rate window가 가득 찼을 때 defer합니다. 운영자는 pass failure, cancellation, backlog pressure와 governor defer를 확인해야 하지만 schedule key, destination, tenant, payload 또는 PostgreSQL error를 metric label로 쓰면 cardinality와 data-exposure 경계가 무너집니다.

Decision

rustee-jobs-cron-sqlx에 panic-isolated, cancellation-safe RecurringJobFireObserver lifecycle을 추가하고, rustee-jobs-cron-observability와 rustee-jobs-cron-observability-prometheus를 optional exporter boundary로 둡니다. application은 PostgresRecurringJobs::with_fire_observer로 collector를 명시적으로 연결합니다.

collector는 started/in-flight/completed pass, fixed succeeded/failed/abandoned outcome, aggregate claimed/staged/rate_limited count와 global duration histogram만 보관합니다. Prometheus adapter는 explicit text 0.0.4 no-store response만 만들며 registry, listener, authentication, route, alert threshold 또는 retry action을 자동으로 만들지 않습니다.

Consequences

  • caller cancellation은 silent loss가 아니라 abandoned pass로 기록됩니다. failed 또는 abandoned transaction의 row count는 durable completion으로 오해하지 않도록 기록하지 않습니다.
  • observer panic은 catch되어 schedule registration, outbox stage, governor consume/defer와 next-run advance에 영향을 주지 않습니다.
  • schedule key, cron expression, destination, job name, payload, occurrence ID, tenant, rate-limit key, database endpoint/credential와 raw error는 observer/event/metric label에 포함하지 않습니다.
  • alert owner, sustained failure/defer threshold, polling cadence, PostgreSQL outage response, downstream idempotency와 scrape-route network isolation은 application/deployment qualification으로 남습니다.

Alternatives

대안판단
schedule key와 destination을 Prometheus label로 exportunbounded series와 business topology/data exposure를 만들므로 채택하지 않습니다.
scheduler가 global registry와 /metrics route를 자동 생성listener ownership, scrape authentication과 application route policy를 침범하므로 채택하지 않습니다.
scheduler가 alert 또는 automatic pause/retry를 수행outage, capacity, side effect와 tenant policy를 framework가 추측하게 되므로 deployment supervisor 책임으로 둡니다.
outbox relay metric만 scheduler health로 사용outbox materialization 전의 failure, claimed backlog와 governor defer를 볼 수 없으므로 별도 pass lifecycle을 둡니다.
