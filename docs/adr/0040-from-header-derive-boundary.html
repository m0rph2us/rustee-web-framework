FromHeader derive boundary

선택적 derive는 existing extractor trait을 구현할 뿐, HTTP semantics나 route metadata를 추론하지 않습니다.

Context

typed header extractor에는 header name 선언, text decoding, FromStr parsing과 safe bad-request mapping이 반복됩니다. macro가 handler signature를 해석하거나 route를 등록하기 시작하면 extractor, authorization, error status와 public API stability의 ownership이 서로 섞입니다. Rustee의 macro-free API는 이미 이 경계를 명시적으로 표현합니다.

Decision

  • rustee-macros는 candidate crate이며 facade macros feature를 통해 opt-in re-export합니다.
  • #[derive(FromHeader)]는 explicit #[rustee(header = "...")] attribute가 있는 one-field tuple newtype만 받습니다.
  • field는 FromStr를 구현해야 하고 generated implementation은 existing rustee::FromHeader, Error, Result와 http::HeaderValue path를 통해 parse failure를 bad_request로 매핑합니다.
  • header name은 macro expansion 전에 검증합니다. missing attribute, invalid name과 unsupported type shape는 stable trybuild compile-fail fixture로 관리합니다.
  • macro output은 facade crate rename을 해석하며 workspace-only consumer fixture가 이 contract를 검증합니다. hidden re-export는 generated code 전용이고 normal application code는 documented Rustee facade API를 사용합니다.

Consequences

  • manual FromHeader implementation이 canonical contract로 유지되어 custom validation과 domain-specific error mapping을 막지 않습니다.
  • derive input grammar와 diagnostic text/span은 developer experience의 compatibility surface가 됩니다. 변경에는 fixture review와 release note가 필요합니다.
  • route registration, handler/extractor inference, authorization, OpenAPI/schema generation, multi-value header policy와 custom parsing trait은 이 결정의 범위 밖입니다.
  • runtime regression은 valid numeric parse와 invalid value의 400 mapping을, compile regression은 valid/misuse fixture를 확인합니다.

Alternatives

대안판단
route attribute와 handler registration을 같은 macro crate에 추가routing/error/authorization semantics를 early lock-in하고 non-macro API보다 더 넓은 behavior를 만들므로 채택하지 않습니다.
struct name에서 header name을 자동 유도public wire name의 surprise와 rename drift를 만들므로 explicit attribute를 선택합니다.
all struct shapes와 custom parser attribute를 처음부터 지원error ownership과 generic bound surface를 불필요하게 넓히므로 minimal newtype boundary부터 검증합니다.
runtime reflection으로 header mapping을 구현Rust compile diagnostics와 zero-cost typed extractor contract를 잃으므로 채택하지 않습니다.

Follow-up

future macro proposal은 target user workflow, macro-free parity, generated code hygiene, feature/dependency cost, diagnostic compatibility, security/HTTP ownership과 migration plan을 포함한 ADR을 추가합니다.
