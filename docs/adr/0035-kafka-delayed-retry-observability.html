ADR 0035

Kafka Delayed-Retry Observability

relay pass와 backlog를 구분해 aggregate-only로 관찰하되, query cadence와 운영 판단은 application이 소유합니다.

Status: Accepted | Date: 2026-08-04

Context

Kafka delayed-retry relay는 PostgreSQL lease, Kafka acknowledgement, PostgreSQL confirmation을 한 pass에서 수행합니다. pass failure 또는 cancellation의 원인에는 endpoint, topic, row ID, payload, key와 raw backend error가 섞일 수 있어 이 값을 label이나 generic metric event에 넣을 수 없습니다. 반면 unpublished/due/leased row와 oldest due age는 database query가 필요한 current-state 값입니다. relay hot path가 이를 매 pass 자동 query하거나 framework가 listener와 alert를 만들면 delivery latency, connection ownership, scrape security와 deployment policy를 한 adapter가 임의로 결정하게 됩니다.

Decision

rustee-events-kafka-sqlx에 panic-isolated, cancellation-safe KafkaDelayedRetryRelayObserver와 KafkaDelayedRetryBacklog query를 둡니다. observer는 only started/in-flight lifecycle, fixed terminal outcome, fully successful pass의 confirmed publish count와 global duration을 전달합니다. backlog()는 PostgreSQL database clock으로 unpublished/due/leased/oldest-due aggregate만 읽으며 row detail을 반환하지 않습니다.

rustee-events-kafka-sqlx-observability는 exporter-neutral collector이고, rustee-events-kafka-sqlx-observability-prometheus는 explicit Prometheus text 0.0.4 Cache-Control: no-store response helper입니다. application이 collector를 relay에 연결하고 자기 timeout/cadence로 backlog()를 호출해 latest snapshot을 record하며, route, registry, listener, database query loop, health inclusion, scrape authentication/network isolation, alert/backoff, retention과 incident owner를 결정합니다.

Consequences

  • metric label은 fixed succeeded/failed/abandoned outcome과 fixed backlog state뿐입니다. topic, row ID, event key, payload, endpoint, credential, tenant와 raw error는 collector와 Prometheus text에 넣지 않습니다.
  • failed 또는 abandoned pass는 partial Kafka acknowledgement 뒤 confirmation failure를 포함할 수 있으므로 publish count를 제공하지 않습니다. missing count를 no-publish evidence로 해석하지 않습니다.
  • backlog snapshot은 last-recorded gauge입니다. application은 query timeout/failure/staleness와 SLO를 자기 health/alert policy에 포함하고 stale snapshot을 healthy queue로 해석하지 않습니다.
  • observer panic은 delivery를 바꾸지 않고 억제됩니다. observer implementation은 synchronous non-blocking aggregate 또는 bounded handoff만 수행해야 합니다.
  • collector와 exporter는 optional rdkafka feature이며 Kafka adapter를 core framework dependency로 만들지 않습니다.

Alternatives

대안판단
relay가 모든 pass에서 backlog를 자동 queryhot path에 불필요한 database work를 추가하고 cadence/timeout을 숨기므로 채택하지 않습니다.
topic, exception, row ID를 Prometheus label로 사용cardinality와 secret/payload 유출 위험을 만들므로 채택하지 않습니다.
framework가 global registry와 /metrics route를 제공scrape 접근 제어와 deployment topology를 일반 API가 결정하게 되므로 채택하지 않습니다.
relay failure에서 confirmed publish count를 0으로 기록acknowledgement와 confirmation 사이 duplicate 가능성을 잘못 숨기므로 채택하지 않습니다.
