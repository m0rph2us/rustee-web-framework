철학 구조 데이터베이스 Redis MongoDB 인증 Queue Event AI Test 운영 로드맵 AI 유지관리 ADR
ADR 0009

테스트와 검증 전략

Status: Accepted. Date: 2026-08-01.

Context

Rustee는 router와 HTTP server뿐 아니라 async cancellation, optional feature, database/state store, broker, event stream, identity, AI provider를 연결한다. unit test만으로 wire protocol, process lifecycle, real backend semantics를 증명할 수 없고, 모든 test를 container나 cloud에서 실행하면 개발 feedback이 너무 느리고 flaky해진다. 또한 macro와 type-safe public API는 compile error 자체가 사용자 경험의 일부다.

Decision

Rustee는 unit, in-process integration, real TCP end-to-end, Testcontainers dependency contract, compile/docs, property/fuzz, scheduled performance/soak의 계층형 전략을 사용한다. 기본 runner는 stable cargo test이고, fast workspace test binary는 cargo-nextest로 실행하며 doctest는 별도 Cargo 단계로 실행한다.

  • rustee-test는 small published dev helper다. TestApp은 validated request/JSON/header, bounded buffered response와 redacted assertion을 in-process로 제공한다. opt-in with_cookie_jar()는 session-style valid name/value carry와 Max-Age=0 deletion만 제공하고, fixed 64-entry/8 KiB bound와 successful buffered response 뒤 atomic update를 지킨다. browser origin/path/secure/same-site/expiry/redirect semantics, HTTP version, SSE와 cancellation은 wire/browser suite에 남긴다. rustee-test-support는 workspace-only fixture/container helper다.
  • 실제 TCP/HTTP test와 실제 backend contract test는 in-process test를 보완하며, 둘 중 하나로 다른 하나를 없애지 않는다.
  • time-dependent behavior는 Tokio paused time 또는 explicit synchronization으로 검증하며 wall-clock sleep을 사용하지 않는다.
  • optional crate와 provider는 독립 feature profile 및 contract suite를 갖는다. --all-features 단일 성공으로 호환성을 주장하지 않는다.
  • Testcontainers dependency contract와 lifecycle/security regression은 영향을 받은 crate의 required Linux pull-request integration lane에서 실행한다. 비용이 드는 cloud provider test만 opt-in/scheduled로 분리한다.
  • macro/API misuse는 trybuild compile-fail test로, router/parser/state machine은 property/fuzz test로 확장한다.
  • cloud credential, 비용 발생 provider, long soak/fuzz는 일반 pull request가 아닌 opt-in/scheduled environment에서 실행한다.

Consequences

  • 일상 변경은 빠른 feedback을 받고, high-risk adapter와 lifecycle은 real system contract로 검증된다.
  • provider별 test setup과 CI 비용이 늘어나지만 실제 ack, visibility, offset, transaction, cancellation 차이가 숨겨지지 않는다.
  • public compile error와 example이 release 전 검증되어 Rust 사용자 경험이 더 안정적이다.
  • test fixture의 namespace, time, port, cleanup을 설계해야 하므로 초기 test code가 늘어난다.
  • coverage는 보조 지표가 되며, observable behavior와 failure mode가 주요 release 판단 기준이 된다.

Alternatives

대안 판단
unit test만 사용 socket, protocol, shutdown, driver/backend 상호운용성의 failure mode를 놓치므로 채택하지 않는다.
모든 test를 container/cloud에서 실행 feedback이 느리고 infrastructure flake가 개발 loop를 지배하므로 채택하지 않는다.
mock framework를 public core abstraction으로 제공 framework 내부 설계를 고정하고 user application test에 불필요한 DSL을 강요하므로 작은 helper와 explicit fake를 우선한다.
coverage percentage를 release gate로 사용 중요 failure path보다 구현 세부사항을 테스트하게 만들 수 있으므로 행동 contract와 risk-based matrix를 우선한다.
flaky test를 자동 retry로 통과 race와 resource leak을 숨기므로 infrastructure failure 진단을 제외하고 채택하지 않는다.

Follow-up

  • Stage 1에서 workspace test convention, fast CI profile, fixture support crate를 구성한다.
  • Stage 2에서 TCP fixture를, Stage 3에서 lifecycle/proxy deployment regression suite를, Stage 4에서 bounded rustee-test::TestApp과 opt-in session-style cookie jar, example/doctest와 rustee-macros::FromHeader의 valid/missing-attribute/wrong-shape/invalid-header-name trybuild suite를 추가했다. route macro와 broader derive는 별도 결정으로 추가한다.
  • 각 integration crate가 추가될 때 canonical Testcontainers contract와 failure/cancellation test를 함께 추가한다.
  • Stage 9C에서 rustee-ai-test의 deterministic recorded-stream contract와 content-free invocation record를 구현했다. Stage 10에서 rustee-router parser/precedence property contract와 independent route_pattern libFuzzer target을 추가했다. header/query/body/range/state-machine target, soak/performance와 full platform/provider release matrix는 계속 확장한다.
