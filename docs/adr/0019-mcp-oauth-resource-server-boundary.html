ADR 0019

MCP OAuth resource-server boundary

Status: Accepted. Date: 2026-08-03.

Context

MCP HTTP client OAuth와 MCP server bearer authorization은 반대 방향의 credential lifecycle이다. client는 user consent, state/PKCE와 resource-bound token store를 소유하지만 server는 access token을 발급하거나 저장하지 않고 accepted resource, authorization-server issuer, audience와 scope를 공개하고 검증해야 한다. 기존 rustee-auth는 검증된 Principal 경계를 제공하지만 MCP protected-resource metadata와 challenge 형식은 소유하지 않는다.

Decision

optional rustee-mcp-oauth를 추가한다. 이 crate는 public protected-resource metadata service와 mounted rustee-mcp service에 적용하는 bearer/scope layer만 제공한다. JWT/JWKS/introspection, issuer와 exact resource audience 검증은 계속 application-configured rustee-auth::BearerAuthenticator 가 맡는다.

  • McpOAuthResourceServerConfig은 canonical MCP resource URL, public metadata URL, bounded explicit authorization-server issuer allowlist와 optional required scopes를 갖는다. HTTPS만 허용하고 local contract를 위한 loopback HTTP만 예외로 둔다.
  • McpOAuthProtectedResourceMetadata는 resource, authorization_servers, scopes_supported, header bearer method만 unauthenticated JSON으로 제공한다. tool, context, tenant, principal, token과 policy detail은 노출하지 않는다.
  • McpOAuthResourceServerLayer는 missing/invalid token에 401 WWW-Authenticate: Bearer resource_metadata=..., insufficient verified scope에 403 plus insufficient_scope challenge를 만든다. verified Principal issuer도 normalized authorization-server allowlist와 대조한다. verifier outage는 issuer/token detail 없는 503으로 끝낸다.
  • layer는 validated Principal만 request extension에 넣는다. McpToolAccessPolicy, McpContextProvider, tenant resolver, approval과 terminal audit은 그대로 application-owned authorization boundary다.
  • application은 issued access token의 aud가 config의 exact resource URL인지 verifier에서 강제하고, configured issuer allowlist와 verifier trust/key source가 일치하는지 deployment configuration으로 검토한다.

Consequences

  • server는 client-side token store, refresh, dynamic registration, consent UI나 automatic request replay를 소유하지 않는다. 이는 ADR 0018의 client lifecycle과 의도적으로 분리된다.
  • JWT static key, remote JWKS 또는 introspection adapter를 선택할 수 있지만 resource-server deployment는 token algorithm, issuer/key rotation, audience, scope mapping, clock skew와 outage policy를 명시해야 한다.
  • metadata endpoint와 MCP endpoint의 externally visible HTTPS URL은 reverse proxy/base URL configuration과 같아야 한다. internal bind address나 untrusted forwarded header에서 자동으로 추론하지 않는다.

Alternatives

대안판단
generic AuthLayer만 MCP endpoint에 적용generic 401은 MCP client가 authorization metadata를 발견할 수 없으므로 채택하지 않는다.
rustee-mcp core가 JWT/JWKS와 token parsing까지 직접 소유application identity trust와 server protocol adapter가 결합되고 OIDC/introspection 선택이 경직되므로 채택하지 않는다.
access token만 있으면 모든 MCP tool/context를 허용OAuth scope는 application resource authorization과 side-effect approval을 대체할 수 없으므로 채택하지 않는다.
metadata URL/resource를 incoming Host 또는 forwarded header에서 생성proxy trust misconfiguration이 discovery와 audience를 바꿀 수 있으므로 canonical config URL만 사용한다.

Follow-up

  • in-process contract는 metadata GET/method gate, no-token/invalid-token challenge, required-scope 403, validated principal handoff와 verifier outage 503을 고정한다.
  • Supported 승격 전에는 external authorization-server version matrix, JWT/JWKS/introspection outage and key rotation contract, reverse-proxy canonical URL check, scope/tenant authorization review, opt-in live credentials와 operator revoke/incident procedure를 추가한다.
  • MCP Streamable HTTP session/SSE server lifecycle과 metadata cache/CORS deployment policy는 별도 protocol and operations ADR에서 확장한다.
