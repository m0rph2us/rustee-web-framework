Keyed API-key fingerprint store boundary

production API-key store에는 raw credential이 아니라 deployment-held pepper로 만든 HMAC fingerprint만 전달합니다.

Context

ApiKeyLayer는 header grammar와 HTTP failure contract를 처리하지만, production identity store까지 raw API key를 전달하면 persistence, audit, diagnostics 경로가 credential exposure surface가 됩니다. bare digest는 leaked database record에 대한 offline guessing을 막지 못합니다. 반대로 Rustee가 특정 database schema나 secret manager를 강제하면 provider의 transaction, availability, retention ownership을 framework로 옮기게 됩니다.

Decision

  • ApiKeyPepper는 application이 protected secret delivery로 공급하는 32-byte, non-zero deployment secret입니다. serializable/displayable하지 않고 Debug에서 redacted되며 drop 시 memory를 zeroize합니다.
  • KeyedApiKeyAuthenticator는 valid raw key에서 HMAC-SHA-256 ApiKeyFingerprint를 만들고 ApiKeyFingerprintStore에는 opaque binary fingerprint만 전달합니다. existing ApiKeyAuthenticator contract를 구현하므로 HTTP layer의 response semantics는 바꾸지 않습니다.
  • store는 active/revoked/expired 판정과 principal mapping을 소유합니다. successful lookup, last-used update와 audit append를 provider transaction에서 원자적으로 처리할 수 있으며 unknown/revoked/expired는 RejectedApiKey, provider failure는 ProviderUnavailable으로 반환합니다.
  • client-key rotation은 하나의 principal에 복수 active fingerprint를 잠시 매핑하고 revoked fingerprint를 store에서 거부합니다. pepper rotation은 application-owned secret migration이며, retained prior pepper, dual lookup window, backfill/rollback과 retirement 시점을 deployment가 명시합니다. framework는 automatic fallback을 제공하지 않습니다.
  • Rustee는 generic database schema, secret manager/KMS, audit retention, rate-limit fingerprint, event delivery, provider-specific lookup implementation을 규정하지 않습니다. rustee-auth-sqlx는 PostgreSQL reference schema/adapter를 별도 crate로 제공하며 production store는 raw key와 fingerprint를 일반 log/trace에 남기지 않습니다.

Consequences

  • provider store API의 credential input이 fixed 32-byte binary value로 제한되고 fake store로 authentication contract를 unit test할 수 있습니다.
  • pepper는 database backup과 독립적으로 보호하고 rotation을 실제 운영 절차로 검증해야 합니다. HMAC fingerprint는 password hashing policy나 API-key entropy policy를 대체하지 않습니다.
  • key ID/prefix는 diagnostic이나 routing 힌트가 될 수 있지만 authorization 결정이나 secret value의 대체물로 자동 사용하지 않습니다.

Alternatives

대안판단
bare SHA-256 lookupleaked lookup table에 대한 offline guessing 저항을 deployment-held secret에 결속하지 못하므로 채택하지 않습니다.
raw key를 generic store trait로 전달database/audit adapter까지 credential lifetime을 넓히므로 채택하지 않습니다.
Rustee가 database table, rotation job, KMS를 자동 제공topology, transaction, retention과 secret ownership을 숨기므로 채택하지 않습니다.

Verification and follow-up

unit contract는 deterministic fingerprint, distinct input separation, fixed length, all-zero pepper rejection, redacted debug, invalid-key pre-store rejection과 principal handoff를 확인합니다. optional PostgreSQL adapter contract는 active/revoked/expired behavior, duplicate non-overwrite, no-overlap client-key rotation와 atomic success audit를 확인합니다. pepper rotation and rollback, secret delivery, retention, outage recovery는 별도 gate로 기록합니다.
