API-key header authentication boundary

service API key를 explicit header와 provider-neutral principal verifier로 지원하되, key storage와 rotation policy는 application에 남깁니다.

Context

machine-to-machine endpoint에는 API key가 여전히 쓰이지만 OpenAPI apiKey metadata만으로 request credential을 안전하게 검증할 수는 없습니다. query credential은 URL/log/cache에 남기기 쉽고 cookie credential은 browser scope와 CSRF semantics를 요구합니다. repeated HTTP field가 comma로 결합될 수 있으므로 one opaque key를 여러 field value에서 임의로 선택하거나 결합해서는 안 됩니다.

Decision

  • ApiKeyLayer::header는 application이 명시한 valid HTTP field name 하나만 사용합니다. query/cookie source와 OpenAPI-driven auto-configuration은 제공하지 않습니다.
  • layer는 exactly one header value만 받고, blank, whitespace, non-printable/non-ASCII 또는 4 KiB 초과 value를 provider 호출 전에 fail-closed 합니다. raw key와 configured header name은 response, request extension, handler parameter, Debug, trace에 넣지 않습니다.
  • ApiKeyAuthenticator는 bounded raw key를 받아 validated Principal만 반환합니다. missing/invalid/rejected key는 sanitized 401 with WWW-Authenticate: ApiKey, provider outage는 detail 없는 503으로 렌더링합니다.
  • StaticApiKeyAuthenticator는 tests/local examples만을 위한 raw in-memory mapping입니다. production provider는 derived secret lookup, constant-time comparison where applicable, tenant mapping, revocation/rotation, audit and retention policy를 application deployment에서 소유합니다.
  • API-key authenticated principal은 existing scope/permission/tenant policy와 조합할 수 있지만, key string이나 header만으로 tenant authority 또는 authorization grant를 추론하지 않습니다.
  • unit header-map test와 real loopback HTTP/1.1 contract는 duplicate field가 parser를 거쳐도 401로 fail-closed하고 response가 어떤 raw key도 echo하지 않는지 확인합니다.

Consequences

  • service API는 bearer/OIDC/session과 같은 Principal 기반 authorization surface를 공유합니다.
  • ambiguous duplicate header, invalid wire value와 provider outage를 별도의 safe response로 관찰할 수 있습니다.
  • static mapping의 편의는 production credential store/security model을 대신하지 않으며, matching provider integration test와 rotation runbook 없이는 Supported가 될 수 없습니다.

Alternatives

대안판단
OpenAPI apiKey declaration이 authentication middleware를 자동 생성document와 credential storage/rotation/authorization owner를 섞으므로 채택하지 않습니다.
query/cookie/header를 하나의 automatic extractor로 지원URL exposure와 browser semantics를 normal path로 만들므로 채택하지 않습니다.
repeated header를 first/last value로 선택하거나 comma로 결합intermediary behavior와 key identity가 모호해지므로 채택하지 않습니다.
static raw key map을 production default provider로 선언comparison, hashing, rotation, revocation과 audit ownership을 감추므로 채택하지 않습니다.

Follow-up

hashed database/secret-manager provider, key ID/prefix policy, rotation/revocation propagation, tenant/permission mapping, rate-limit fingerprint, audit retention, real provider outage and external OpenAPI route/runtime drift evidence는 separate integration ADR과 release gate에서 다룹니다.
