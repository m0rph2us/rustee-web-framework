ADR 0011

MSRV와 통합 지원선

Status: Accepted. Date: 2026-08-03.

Context

Rustee의 선택적 integration은 core와 분리되지만, 공식 지원 crate는 같은 workspace MSRV와 CI release gate를 공유한다. 최신 MongoDB Rust driver, async-nats JetStream client와 AWS SDK for SQS는 같은 workspace MSRV에서 검증해야 한다. SQS SDK의 최신 security-maintained line은 Rust 1.94.1을 요구한다. Rust 1.88을 유지하면 오래된 AWS TLS line을 유지하거나 SQS를 공식 지원에서 제외해야 하며, 이는 security fix와 provider API 유지보수 비용을 높인다.

Decision

Rustee workspace의 MSRV는 Rust 1.94.1로 정한다. Cargo.toml의 rust-version과 CI MSRV lane은 이 값을 사용하며, 공식 integration은 이 지원선에서 현재 security-maintained driver line을 사용한다. SQS는 AWS SDK 1.105.0과 default HTTPS client의 AWS-LC TLS 경로를 사용하며 legacy Rustls compatibility feature를 켜지 않는다.

  • rustee-mongodb는 MongoDB Rust driver 3.8 line을 사용한다.
  • rustee-jobs-nats는 async-nats 0.50 line을 사용한다.
  • rustee-redis는 Redis client 1.5 line을 사용한다.
  • rustee-jobs-sqs는 AWS SDK for SQS 1.105.0 line을 사용한다.
  • MSRV 상향은 minor 또는 major release에서만 수행하고, release note와 migration guide에 명시한다.

Consequences

  • 공식 adapter가 최신 driver의 버그 수정, TLS, provider API 개선을 따라갈 수 있다.
  • Rust 1.94.0 이하 환경은 Rustee의 공식 support matrix 밖에 있으므로 deploy toolchain 업그레이드가 필요하다.
  • CI는 Rust 1.94.1과 stable을 모두 검사하며, optional crate도 MSRV lane에 포함한다.
  • 새 integration을 채택할 때는 그 dependency의 MSRV와 maintenance status를 architectural decision으로 검토한다.

Alternatives

대안판단
Rust 1.88 유지최신 SQS SDK/TLS line을 공식 지원에서 제외하거나 알려진 취약 의존성을 유지해야 하므로 채택하지 않는다.
core와 integration마다 별도 MSRV사용자-facing facade와 workspace release 검증이 복잡해지고 지원 약속이 불명확해지므로 초기에는 채택하지 않는다.
최신 driver integration을 공식 지원에서 제외엔터프라이즈 확장 목표와 맞지 않으므로 채택하지 않는다.

Follow-up

  • Rust 1.94.1 toolchain으로 workspace 전체 build, lint, test를 검증한다.
  • provider version 또는 MSRV가 바뀌면 architecture, testing, roadmap과 이 ADR의 후속 결정을 함께 갱신한다.
