ADR 0021

AI response-cache isolation boundary

Status: Accepted. Date: 2026-08-03.

Context

response 또는 semantic cache는 provider 비용을 줄일 수 있지만 stale answer, cross-tenant disclosure, prompt/completion retention, cache outage 때의 hidden provider retry를 만들 수 있다. provider-neutral AiPipeline이 request content를 자동으로 fingerprint하면 canonicalization, secret salt, authorization scope, template/policy/data revision의 ownership이 framework에 섞인다.

Decision

cache는 explicit, exact-key, non-streaming response adapter로 제공한다. framework는 raw prompt를 fingerprint하거나 cache를 AiPipeline에 자동 장착하지 않는다.

  • AiCacheKey은 application-generated opaque tenant scope와 fixed lower-case SHA-256 fingerprint만 받는다. scope에는 tenant, model alias, template/policy/data revision 등 재사용 의미를 바꾸는 identity를 포함해야 한다. raw prompt, user identifier, unsalted sensitive-content hash를 넣지 않는다.
  • AiCachedCompletion은 application-governed executor를 한 번 호출한다. declared tool, prior tool result, model tool-call response와 stream은 cache 대상이 아니다. tool loop, approval, budget/usage ledger, advisor와 tenant authorization은 executor의 기존 경계에 남는다.
  • cache read failure는 explicit fail-closed 또는 bypass policy를 선택한다. bypass는 visible status를 남기고 한 번의 provider call만 수행한다. successful completion 뒤 write failure는 status로 보고할 뿐 response를 error/retry로 바꾸지 않는다.
  • invalidation은 exact key만 제공한다. tenant-wide wildcard delete/scan은 제공하지 않으며 application이 exact erase를 보관하거나 versioned scope를 전진시키고 TTL을 기다린다. default TTL은 5분이며 core policy는 최대 24시간이다.
  • cache hit은 explicit status로 application usage/observability policy가 account한다. cache adapter는 hit을 provider usage 또는 budget settlement로 위장하지 않는다.

Consequences

  • application은 key derivation, secret salt/key rotation, tenant erase, encryption/TLS, retention, stale-answer user experience와 cache outage policy를 문서화한다.
  • first cache is an in-memory deterministic adapter. Redis or another durable store requires its own namespace/serialization/size/outage contract and production encryption/deployment evidence.
  • semantic similarity search, cross-session chat memory, distributed stampede coordination, refresh-ahead, global cache clearing과 provider async batch는 이 adapter의 범위가 아니다.

Alternatives

대안판단
모든 AiPipeline completion을 prompt hash로 자동 캐시tenant, authorization, model/policy revision과 tool state를 framework가 오판할 수 있어 채택하지 않는다.
cache write failure를 provider error로 반환caller retry가 second provider charge를 만들 수 있으므로 채택하지 않는다.
tenant namespace 전체를 scan/delete 하는 framework APIbackend 비용과 erase authorization이 숨겨지므로 exact key 또는 scope versioning만 제공한다.
tool-call response와 tool-result continuation 캐시interaction/action state가 stale 또는 cross-request로 재사용될 수 있어 채택하지 않는다.

Follow-up

  • rustee-ai-cache은 key/config/eligibility, executor adapter, hit/write-failure status, exact invalidation과 bounded in-memory contract를 구현한다.
  • Redis adapter는 versioned namespace, serialized entry size bound, TTL conversion, exact delete와 Redis outage contract를 별도 crate로 구현한다.
  • provider batch adapter는 cache와 별도로 catalog reference, idempotency, partial completion, cancellation, billing/reconciliation contract를 다룬다.
