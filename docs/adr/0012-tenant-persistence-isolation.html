ADR 0012

tenant persistence isolation

Status: Accepted. Date: 2026-08-02.

Context

route-level tenant authorization만으로는 repository가 predicate를 빠뜨렸을 때 다른 tenant row를 읽거나 쓸 위험을 막지 못한다. 그러나 Rustee는 SQL, document database, ORM을 하나의 repository trait로 평준화하지 않기로 이미 결정했다. persistence 경계는 provider의 실제 보안 기능을 활용하면서도 handler의 transaction lifetime을 숨기지 않아야 한다.

Decision

trusted TenantContext를 provider-neutral rustee-tenant crate로 분리한다. rustee-auth는 이 type을 기존 경로로 re-export하고, PostgreSQL service는 rustee-sqlx::begin_tenant_transaction으로 transaction-local rustee.tenant_id setting을 설정한다.

  • application migration은 tenant-protected PostgreSQL table마다 ENABLE ROW LEVEL SECURITY, 필요한 경우 FORCE ROW LEVEL SECURITY, current_setting('rustee.tenant_id', true)를 비교하는 USING/WITH CHECK policy를 정의한다.
  • application runtime role은 superuser나 BYPASSRLS role이 아니어야 하며, tenant-facing query는 helper가 만든 transaction 안에서 실행한다.
  • helper는 transaction을 자동 commit, rollback, retry하지 않는다. use case가 lifetime과 error policy를 계속 소유한다.
  • Rustee는 RLS migration, tenant column, policy naming, global admin query, cross-tenant reporting을 자동 생성하지 않는다.
  • MongoDB, Redis, event store, ORM은 PostgreSQL RLS와 동등하다고 가정하지 않는다. 각 provider의 credential, database/collection layout, filter 또는 policy 모델은 별도 integration release gate에서 증명한다.

Consequences

  • authentication과 persistence가 같은 typed tenant scope를 사용하되, core가 database driver에 의존하지 않는다.
  • PostgreSQL RLS policy가 application query의 실수를 한 번 더 방어하므로 read와 write 모두 database contract로 검증할 수 있다.
  • 사용자는 RLS schema, runtime role, migration review를 운영 책임으로 관리해야 한다.
  • 다른 storage provider는 편의 facade를 서둘러 추가하지 않고 별도 위협 모델과 실제 backend test를 요구한다.

Alternatives

대안판단
handler middleware가 모든 query에 tenant predicate 자동 삽입raw SQL, ORM, aggregation, background work를 완전하게 가로챌 수 없고 누락을 숨기므로 채택하지 않는다.
database-neutral tenant repository traitSQL RLS와 document database의 capability를 평준화하고 기존 database boundary를 깨므로 채택하지 않는다.
connection-global PostgreSQL settingpool reuse에서 다른 tenant로 누출될 수 있으므로 transaction-local set_config(..., true)를 사용한다.
모든 MongoDB collection을 같은 helper로 감싸기aggregation, sharding, credential model의 요구가 확정되지 않아 독립 provider contract 전에는 채택하지 않는다.

Follow-up

  • PostgreSQL 16 container contract에서 RLS-protected cross-tenant read가 빈 결과이고 write가 거부되는지 계속 확인한다.
  • external IdP revocation lifecycle과 MongoDB tenant isolation model을 실제 backend release gate로 추가한다.
  • global administrator, reporting, support access가 필요하면 explicit bypass/audit policy를 별도 ADR로 정한다.

Last updated: 2026-08-02. Supersede this ADR if Rustee adopts a different trusted tenant context or persistence isolation model.
