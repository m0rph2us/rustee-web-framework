ADR 0023

OpenAI Batch lifecycle adapter

Status: Accepted. Date: 2026-08-03.

Context

rustee-ai-batch deliberately owns only content-free reference reservation and receipt recording. The OpenAI Batch API adds provider-specific input-file IDs, endpoint selection, status, cancellation, output/error file IDs, and a 24-hour completion window. Treating the raw JSONL payload or returned result file as a generic framework value would widen durable-data retention and make duplicate submission recovery unsafe.

Decision

rustee-ai-openai implements explicit bounded input-row/file upload, create, retrieve, cancel, file download, and structural output-row parsing, while keeping application result handling outside the adapter.

  • OpenAiBatchInputRow/OpenAiBatchJsonlBuilder construct the generic custom_id/POST/endpoint/body JSONL envelope. They require unique safe IDs, one endpoint, object body, and bounded row/file count. OpenAiBatchInputRow::from_chat_request is the opt-in typed /v1/responses path and reuses the existing Rustee ChatRequest text/function/tool-result mapping. from_embedding_inputs is the opt-in typed /v1/embeddings path and preserves a non-empty ordered EmbeddingInput list. Provider-only fields still require an explicit application-owned body.
  • OpenAiBatchInputJsonl is a non-serializable, non-cloneable, redacted short-lived byte value. upload_batch_input() uploads it with Files purpose batch and returns only a validated file ID; it creates no durable job, cache entry, batch request, or result record.
  • OpenAiBatchRequest accepts only a bounded provider input-file ID and a supported /v1/responses or /v1/embeddings endpoint. OpenAiBatchProvider implements the generic one-time submission trait by creating /v1/batches requests with completion window 24h and the stable Rustee run key as provider metadata. The core ledger still owns duplicate receipt reuse and pending ambiguity.
  • Retrieve and cancel expose a normalized status, request counts, and optional output/error file IDs. download_batch_file() is a separate caller-selected operation. Its bounded JSONL iterator validates safe custom_id, response status/request ID, or failure code; provider error messages are not retained. A caller that explicitly consumes a response body may use into_chat_response() for the validated /v1/responses shape or into_embeddings(expected_count) for a validated ordered /v1/embeddings response. Domain validation, partial-result routing, and all side effects remain application-owned.
  • Batch JSON and file references are fail-closed: recognized lifecycle state, bounded identifiers, required counts, the invariant completed + failed <= total, Batch-purpose upload response, configured file-size limit, JSONL row bound, and mutually exclusive response/error shape are required before data is retained.

Consequences

  • Applications own authorized JSONL construction, row shape, prompt handling, file retention/erase, and model-specific limits. The adapter transmits only one explicitly supplied bounded in-memory value and does not serialize or log it.
  • Applications explicitly choose whether to download or delete a selected input/output/error file, then select whether to consume raw response bodies, validate domain meaning, route partial results, evaluate them, reconcile usage/billing, and retain or erase provider artifacts. Delete requires an exact provider acknowledgement and never schedules a retry.
  • Local TCP and parser contract tests cover multipart upload request shape, create/retrieve/cancel/delete paths, content-free submission, safe decoding, explicit bounded download, structural JSONL iteration, row-limit/malformed-row failure, and redacted debug output. Live credentials, provider quota, outage, and version evidence remain opt-in release gates.

Alternatives

대안판단
framework가 raw JSONL row를 만들고 durable payload에 보관prompt retention, application authorization, file ownership과 model-specific row construction을 침범하므로 채택하지 않는다.
polling 결과를 자동 다운로드하고 response cache/evaluation에 주입partial-result, tenant authorization, retention, cost, replay 의미를 숨기므로 채택하지 않는다.
provider 상태를 generic batch core trait에 강제다른 provider의 lifecycle, cancellation, billing 모델을 잘못 평준화하므로 adapter API로 둔다.

Output Expiration

OpenAiBatchOutputExpiration optionally sends the provider-supported output_expires_after policy with an explicit one-hour through 30-day whole-second duration. It covers only generated output/error files, is anchored by the provider at batch creation, and does not delete input files, settle billing, or replace application retention and reconciliation decisions.

Follow-up

  • Streaming file transfer, production artifact retention/erase, model-specific input-body validation, response semantics beyond the explicit Responses/Embeddings conversions, and application partial-result routing require separate contracts.
  • Production durable ledger/catalog, worker retry/DLQ, billing reconciliation, live provider/outage qualification, and model/provider compatibility matrix remain release gates.
