ADR 0014

AI provider usage reservation

Status: Accepted. Date: 2026-08-03.

Context

provider 호출 전 quota를 검사하는 것만으로는 실패, HTTP retry, stream consumer drop 뒤 실제 호출과 token usage를 구분할 수 없다. transport error는 provider가 요청을 받지 않았다는 증거가 아니며, stream body가 중단되면 terminal usage도 알 수 없다. 이 상태에서 framework가 provider를 재시도하거나 reservation을 자동 refund하면 중복 호출, 이중 청구 또는 quota bypass를 만들 수 있다.

Decision

durable AI 경로는 verified tenant/subject, content-free request metadata와 application-owned stable key로 AiUsageReservation을 만든다. AiUsageLedger가 Reserved를 반환한 호출만 provider를 한 번 시작할 수 있다. non-stream response 또는 stream Completed(Usage)가 도착하면 같은 reservation에 actual usage를 terminal settlement로 기록한다. advisor와 함께 쓰는 path는 advisor가 만든 final request를 reserve하고 raw terminal usage를 response/event advisor hook 전에 settle한다.

  • same key의 pending reservation은 PendingReconciliation, completed reservation은 AlreadySettled로 provider 호출 전에 차단한다.
  • provider transport failure, incomplete stream, browser/body drop은 usage나 refund를 추측하지 않고 pending으로 남긴다.
  • completion 뒤 ledger write가 실패하면 response를 포함한 reconciliation error 또는 stream error를 반환하며, framework는 provider를 재시도하지 않는다.
  • rustee-ai-audit-sqlx은 PostgreSQL pending/completed usage ledger, replay-safe same usage settlement, changed identity/usage rejection, bounded pending query를 제공한다.
  • 가격표, token-to-currency conversion, quota 기간, hard limit과 reservation의 atomic admission은 application-owned ledger implementation 또는 service transaction이 소유한다.

Consequences

  • framework는 provider-neutral 경계를 유지하면서 provider attempt의 불확실성을 숨기지 않는다.
  • application은 pending row를 provider idempotency lookup, policy timeout 또는 manual review로 처리해야 한다.
  • prompt, completion, model alias, identity와 idempotency key는 ledger Debug와 tracing default field에 노출하지 않는다.
  • legacy BudgetAdvisor는 content-free pre-admission hook으로 남고, durable accounting은 ledger-aware pipeline API를 명시해 사용한다.

Alternatives

대안판단
provider error 때 자동 refund요청이 provider에 도달했는지 알 수 없어 quota bypass 또는 이중 호출을 만들 수 있으므로 채택하지 않는다.
response ID만 idempotency key로 사용response ID는 provider 호출 뒤에만 생기며 pre-call duplicate 차단을 할 수 없으므로 채택하지 않는다.
framework가 가격과 quota 기간을 표준화model, 계약, currency, tenant policy를 일반화할 수 없으므로 content-free lifecycle contract만 제공한다.
모든 AI 호출에 durable ledger 강제ephemeral 내부 기능과 custom billing store를 막으므로 opt-in explicit pipeline 경로로 둔다.

Follow-up

  • application은 provider idempotency capability, pending reservation SLA, refund/manual-review procedure를 release gate에 기록한다.
  • quota admission과 usage reservation을 함께 보장할 필요가 있으면 application ledger implementation에서 한 durable transaction으로 처리한다.
  • live provider credential contract에는 spend limit과 terminal usage/reconciliation observability를 추가한다.
