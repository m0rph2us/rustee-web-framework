ADR 0033

Recurring Job IANA Time-Zone Calendar

durable schedule은 host-local time이 아니라 저장된 IANA zone과 명시적 DST 규칙으로 해석합니다.

Status: Accepted | Date: 2026-08-04 | Supersedes: ADR 0029의 UTC-only time-zone 제한

Context

UTC-only recurrence는 transaction safety는 단순하지만, local business hour에 실행해야 하는 billing, notification과 regional workflow에는 application 별 wrapper를 강요합니다. host local time을 기본으로 삼으면 replica마다 설정이 달라질 수 있고, DST의 gap과 overlap을 scheduler가 우연히 두 번 또는 한 번 실행할 위험이 있습니다.

Decision

rustee-jobs-cron-sqlx는 schedule definition마다 validated IANA RecurringJobTimeZone을 저장합니다. RecurringJob::new의 default는 UTC이고, with_time_zone으로 명시합니다. 0003_rustee_recurring_job_time_zone.sql은 기존 row를 UTC로 forward-migrate합니다. migration은 base schedule 뒤에 적용하며, optional governor migration을 쓴 deployment는 이를 먼저 적용합니다.

cron fields는 stored IANA wall clock로 계산하지만, next_run_at, occurrence idempotency key와 PostgreSQL locking은 UTC instant를 계속 사용합니다. forward DST transition의 존재하지 않는 local time은 skip합니다. backward transition의 ambiguous local time은 더 이른 UTC instant만 materialize하고, 같은 wall-clock time의 나중 instant는 materialize하지 않습니다. pause, resume과 late pass는 all-missed catch-up을 하지 않고 database clock 뒤의 첫 허용 occurrence로 advance합니다.

Consequences

  • same key의 IANA zone 변경은 definition drift이며 registration conflict가 됩니다. deployment는 changed schedule을 새 key 또는 explicit migration으로 관리합니다.
  • host OS zone, process locale와 PostgreSQL session zone은 recurrence 의미를 바꾸지 않습니다.
  • bundled chrono-tz tzdb version은 future local occurrence를 바꿀 수 있습니다. dependency/tzdb update는 affected schedule inventory, DST boundary test, migration/rollback plan과 operator approval을 포함한 qualification gate입니다.
  • holiday/business calendar, tenant-specific exception, alternate overlap policy, all-missed replay, polling runtime와 alert threshold는 application/deployment policy로 남습니다.
  • outbox stage/next-run update와 shared fixed-window governor의 PostgreSQL atomicity는 ADR 0029와 ADR 0030의 경계를 유지합니다.

Alternatives

대안판단
host-local time defaultreplica/region 차이와 deployment configuration drift를 schedule semantics로 만들므로 채택하지 않습니다.
DST overlap을 두 번 fireexternal side effect가 의도치 않게 중복될 기본값이 되므로 채택하지 않습니다. 필요한 domain은 distinct explicit schedules를 둡니다.
DST gap을 앞/뒤 시각으로 이동사용자가 쓰지 않은 wall-clock time을 추측하므로 채택하지 않습니다.
time zone을 cron expression에 embedparser portability와 durable definition comparison을 불명확하게 하므로 separate typed field를 사용합니다.
