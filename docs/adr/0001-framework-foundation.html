ADR 0001

프레임워크 기반 선택

Status: Accepted. Date: 2026-08-01.

Context

Rustee는 Rust 웹 프레임워크로서 작은 시작 경험과 장기적인 엔터프라이즈 확장성을 동시에 목표로 한다. HTTP 파서, async runtime, 미들웨어 생태계를 모두 직접 만드는 것은 초기 품질과 유지보수성에 큰 부담을 준다.

Decision

Rustee는 초기 기반으로 Tokio runtime, Hyper HTTP stack, Tower-compatible Service/Layer 모델을 채택한다. 프레임워크는 이 위에 작고 안정적인 core API, 라우터, 서버 어댑터, 미들웨어, 선택적 매크로를 구성한다.

Consequences

  • Tower 생태계의 timeout, tracing, rate limit, load shedding 같은 패턴을 재사용할 수 있다.
  • Tokio/Hyper에 묶이는 대신 Rust 서버 생태계의 검증된 기반 위에서 빠르게 품질을 확보한다.
  • core API는 transport 세부사항을 숨기되, 고급 사용자가 필요하면 낮은 수준으로 내려갈 수 있게 해야 한다.
  • runtime 독립성은 초기 목표가 아니다. 나중에 필요하면 adapter 계층에서 별도 ADR로 재검토한다.

Alternatives

대안 판단
HTTP server를 직접 구현 학습 가치는 있으나 보안, 성능, 표준 호환성 부담이 크므로 초기 목표에서 제외한다.
Actix Web 스타일 독자 생태계 성능과 완성도는 매력적이지만 Tower 호환성을 잃으면 확장성이 좁아질 수 있다.
Rocket 스타일 매크로 중심 API DX는 좋지만 Rustee는 macro-free API를 먼저 안정화한 뒤 선택적으로 매크로를 얹는다.
풀스택 MVC 프레임워크로 시작 Loco 같은 생산성 모델은 장기 참고 대상이지만, Rustee의 첫 목표는 composable web core다.

Follow-up

  • Stage 1에서 core trait의 최소 형태를 실제 코드로 검증한다.
  • Stage 2에서 Hyper adapter와 Tower Service 변환 경계를 검증한다.
  • runtime 독립성 요구가 생기면 별도 ADR로 재검토한다.

Last updated: 2026-08-02. Supersede this ADR if Rustee changes its runtime, HTTP, or middleware foundation.
