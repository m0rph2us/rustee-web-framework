ADR 0050 · Accepted · 2026-08-04

PostgreSQL keyed API-key store

optional SQLx adapter가 fingerprint-only credential record, rotation/revocation과 successful-auth audit을 database transaction으로 제공합니다.

Context

ADR 0049의 generic store boundary는 raw credential exposure를 줄이지만, application마다 last-used update와 audit append를 따로 구현하면 partial success, duplicate fingerprint overwrite, expired/revoked key acceptance가 생길 수 있습니다. PostgreSQL은 Rustee의 existing SQLx support line에 포함되어 있어 concrete reference adapter가 가장 작은 운영 증거가 됩니다.

Decision

  • rustee-auth-sqlx는 optional crate입니다. application이 API_KEY_STORE_MIGRATION_SQL을 deployment migration sequence에 넣으며 HTTP startup에서 migration을 실행하지 않습니다.
  • credential row에는 32-byte fingerprint, serialized Principal, active/revoked state, optional expiry, created/revoked/last-used metadata만 저장합니다. raw API key, pepper, header name은 schema와 adapter API에 없습니다.
  • authenticate는 database clock으로 active/expiry condition을 만족하는 row 하나를 update하고 principal을 읽은 뒤 success audit row를 append하고 commit합니다. 어느 단계든 실패하면 sanitized unavailable response가 되고 successful authentication을 반환하지 않습니다.
  • unknown, revoked, expired fingerprint는 rejected result이며 audit row를 만들지 않습니다. success audit은 fingerprint가 아니라 opaque record UUID만 참조합니다.
  • register는 duplicate fingerprint를 overwrite하지 않습니다. clone_active_record는 replacement fingerprint에 database-clock active/unexpired source principal/expiry를 lock-protected transaction으로 copy하고 source/replacement audit을 만들지 않습니다. rotate도 database-clock active/unexpired previous record만 one transaction에서 revoke하며, revoke는 idempotent state transition입니다.
  • adapter는 PostgreSQL restore/outage, migration ordering, backup access, serialized principal evolution, retention, RLS policy, pepper/KMS dual-read migration과 client-key issuance를 소유하지 않습니다.

Consequences

  • application은 auth layer와 PostgreSQL store를 바로 조합할 수 있고 client key plaintext를 database write path로 전달하지 않습니다.
  • rotation API는 no-overlap replacement를 제공하고, clone_active_record는 authorized application flow가 derived fingerprint만 전달하는 overlap migration을 돕습니다. deployment는 retained window, replacement fingerprint derivation/backfill과 old record revocation을 명시적으로 수행합니다.
  • stored principal JSON은 application-owned identity data입니다. role/scope/tenant semantics 또는 schema evolution을 변경할 때 migration, access review, rollback plan을 같이 검증합니다.

Alternatives

대안판단
generic rustee-sqlx crate에 identity schema를 추가pool/lifecycle helper와 identity storage ownership을 섞으므로 채택하지 않습니다.
HTTP startup에서 migration 자동 실행privilege, deployment ordering과 rollback control을 server process에 숨기므로 채택하지 않습니다.
unknown attempt도 fingerprint로 audituntrusted input retention과 write amplification을 normal authentication path로 만들므로 채택하지 않습니다.

Verification and follow-up

PostgreSQL 16 container contract는 active last-used/audit atomicity, duplicate fingerprint non-overwrite, expired/revoked rejection, database-clock active/unexpired-source only rotation and metadata clone/no clone audit, repeated revocation, stopped database에서 bounded/redacted store readiness failure와 restart 뒤 requalification을 확인합니다. migration/restore drill, backup/RLS access, KMS/pepper rotation, audit retention과 alert owner는 qualification register의 deployment-owned gate입니다.
