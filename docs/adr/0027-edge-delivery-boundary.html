ADR 0027

Edge delivery와 cache-control의 소유 경계

Status: Accepted. Date: 2026-08-03.

Context

Rustee는 cleartext HTTP/1.1 origin, explicit trusted proxy restoration, static validators와 opt-in compression을 제공합니다. 그러나 public TLS, CDN cache key, compression, purge, certificate lifecycle과 origin shielding은 vendor-specific operational state입니다. 이를 framework feature로 보이면 application cache policy와 edge configuration의 책임이 섞이고, shared cache를 통한 tenant data leak 또는 stale error masking 위험이 커집니다.

Decision

Rustee는 edge vendor abstraction, purge API, certificate manager를 만들지 않습니다. application/deployment가 named edge vendor와 versioned config를 소유하며, origin에는 edge direct peer CIDR만 trusted proxy로 설정합니다. cacheability는 origin route가 explicit Cache-Control/Vary로 의도하고, edge cache key, compression owner, purge scope, TLS/IAM, telemetry retention은 deployment qualification으로 증명합니다.

구체적 policy와 release evidence는 edge delivery policy에 기록합니다.

Consequences

  • F1은 vendor-neutral origin framework로 유지하며, chosen edge topology의 Supported 선언은 별도 evidence가 있어야 합니다.
  • dynamic compression은 origin과 edge 중 하나만 소유하고, Vary: Accept-Encoding representation 분리를 integration test로 확인합니다.
  • authenticated, tenant-scoped, health, error response는 explicit cache policy 없이는 shared cache에 두지 않습니다.
  • purge와 certificate rotation은 application release/operator procedure의 audit 대상이며 Rustee service future가 호출하지 않습니다.
  • origin shutdown은 edge traffic drain과 함께 검증해야 하며, local Nginx test만으로 public CDN behavior를 선언하지 않습니다.

Alternatives

대안판단
framework universal CDN clientprovider별 cache, credential, purge, audit semantics를 숨기므로 채택하지 않습니다.
origin이 모든 response를 public cacheable로 지정authenticated data와 operational response를 shared cache로 노출할 수 있으므로 채택하지 않습니다.
local proxy contract를 vendor CDN support 선언으로 사용certificate, edge routing, purge, cache key, IAM을 증명하지 못하므로 채택하지 않습니다.
first release부터 direct TLS/HTTP/2 origin을 추가transport compatibility와 lifecycle 범위가 커지므로 별도 ADR까지 채택하지 않습니다.
