데이터베이스 Queue Redis 로드맵 ADR
ADR 0030

PostgreSQL scheduler rate governor

Status: Accepted. Date: 2026-08-03.

Context

rustee-rate-limit와 Redis adapter는 trusted HTTP identity를 위한 atomic fixed-window check입니다. recurring scheduler는 PostgreSQL row lock, fresh outbox stage, next-run update를 한 transaction으로 처리합니다. scheduler가 Redis check를 그 transaction 안에서 호출하면 Redis permit은 사용됐지만 PostgreSQL transaction은 rollback될 수 있고, 반대로 external store outage/fail-open policy가 durable job release를 예측하기 어렵게 만듭니다.

Decision

rustee-jobs-cron-sqlx는 forward-only PostgreSQL migration으로 schedule rate key와 fixed-window policy, key당 one-row current-window state를 추가합니다. due row와 rate state의 consume, fresh outbox stage, next occurrence update 또는 window-boundary defer를 한 PostgreSQL transaction에서 수행합니다.

permit이 없으면 scheduler는 same cron occurrence를 무한 busy-loop하지 않고 next eligible window boundary로 defer합니다. policy key와 fixed-window parameters가 같은 schedule만 capacity를 공유하며, mismatched policy는 explicit registration conflict가 되어야 합니다. 이 결정은 broker publish, worker execution, tenant fairness, daily quota 또는 external API quota를 globally exactly-once로 만들지 않습니다.

Consequences

  • HTTP/Redis rate limit과 scheduler governor는 failure와 atomicity boundary가 다른 별도 product로 유지합니다.
  • current window state는 key당 one row로 보관해 per-window history accumulation을 만들지 않습니다. retention/audit history는 application data model의 별도 책임입니다.
  • initial policy는 PostgreSQL-clock fixed window로 한정합니다. sliding window, token bucket, GCRA, weighted cost, calendar quota와 fairness는 explicit future ADR 없이는 추가하지 않습니다.
  • application은 shared key topology, defer latency SLO, alert, pause/resume procedure와 downstream idempotency/capacity를 운영해야 합니다.
  • RecurringJobRateLimit, with_rate_limit, RECURRING_JOB_RATE_GOVERNOR_MIGRATION_SQL과 PostgreSQL 16 contract는 implemented입니다. baseline scheduler migration 다음에 governor migration을 deployment migration set에 추가해야 합니다.

Alternatives

대안판단
existing Redis RateLimitStore를 fire_due에서 호출cross-store permit leak, uncertain retry semantics와 storage failure policy를 scheduler atomicity에 숨기므로 채택하지 않습니다.
process-local token bucketreplica, restart와 deployment scale-out에서 global capacity가 달라지므로 채택하지 않습니다.
broker queue quota로 대신 제한outbox materialization 이전의 cron occurrence defer와 provider-neutral semantics를 제공하지 못하므로 채택하지 않습니다.
generic multi-algorithm distributed governor를 먼저 제공quota, fairness와 persistence guarantees를 과도하게 약속하므로 fixed-window PostgreSQL first path 뒤 별도 contract로 확장합니다.

Last updated: 2026-08-03. The crate and PostgreSQL contract implement the migration, exact policy-conflict behavior, and atomic defer/stage boundary. Deployment owners still provide alert thresholds and an operational runbook.
