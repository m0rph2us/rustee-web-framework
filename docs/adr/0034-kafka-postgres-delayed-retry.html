ADR 0034

Kafka PostgreSQL Delayed Retry

Kafka source offset은 durable retry intent가 PostgreSQL에 기록된 뒤에만 commit하고, due row만 별도 relay가 Kafka retry topic으로 되돌립니다.

Status: Accepted | Date: 2026-08-04

Context

Kafka retry topic의 publish는 즉시 전달됩니다. process-local sleep은 worker restart, rebalance와 horizontal scale에서 사라지며, generic event outbox delay는 Kafka source offset, retry attempt, failure reason, original topic/partition/offset header를 함께 보존하지 않습니다. source record를 먼저 commit하면 delay scheduler 장애 때 event를 잃을 수 있습니다.

Decision

optional rustee-events-kafka-sqlx를 둡니다. PostgresKafkaDelayedRetryRouter는 retry가 가능한 decode/handler failure를 PostgreSQL database clock 기준 available_at row로 stage하고, 성공한 stage 뒤에만 KafkaEventConsumer::run_with_failure_routing가 source offset을 commit하게 합니다. terminal DLQ는 기존 acknowledged Kafka publisher가 즉시 처리합니다.

PostgresKafkaDelayedRetryRelay::relay_once는 due row를 FOR UPDATE SKIP LOCKED lease로 claim하고, stored retry topic과 retry-attempt/failure/origin headers를 보존해 Kafka broker acknowledgement를 기다립니다. acknowledgement 뒤에만 published_at을 기록합니다. Kafka publish가 실패하면 이 pass의 unpublished claim을 configured delay 후 다시 eligible하게 만듭니다. KafkaDelayedRetryReadinessConfig과 readiness는 retry table select와 retry/DLQ topic metadata를 bounded하게 확인합니다. KafkaDelayedRetryRelayLoopConfig과 shutdown-aware run_until은 empty pass 뒤에만 bounded idle delay를 두고, shutdown 뒤에는 새 pass를 시작하지 않습니다. application이 migration, relay supervisor, alert와 backoff를 소유합니다. pass telemetry와 aggregate backlog export의 별도 경계는 ADR 0035에서 관리합니다.

Consequences

  • migration 0001_rustee_kafka_delayed_retries.sql은 consumer runtime보다 먼저 forward-only로 적용합니다. source topic/partition/offset/retry attempt unique key는 source commit 재시도 중 같은 delayed retry intent를 하나로 유지합니다.
  • delay, lease, broker publish acknowledgement, Postgres confirmation을 하나의 distributed transaction으로 만들지 않습니다. broker acknowledgement 뒤 database confirmation이 실패하거나 process가 죽으면 retry event가 중복 publish될 수 있으므로 consumer idempotency는 계속 필수입니다.
  • stored retry topic은 stage 당시의 destination을 보존합니다. 나중의 deployment configuration 변경이 이미 commit된 row를 다른 topic으로 조용히 보내지 않습니다.
  • readiness는 migration 실행, topic provisioning, relay backlog/lag 또는 external side effect를 확인하지 않습니다. application deployment가 readiness inclusion과 alert/runbook을 결정합니다.
  • relay loop report는 completed pass와 broker-confirmed publish count만 제공합니다. pass observer, aggregate backlog query, scrape/export, alert threshold, migration/restore, retention과 approved replay runbook은 deployment qualification의 일부이며 framework가 자동으로 수행하지 않습니다.
  • payload/key는 durable row와 Kafka wire record에 필요하지만 relay debug output과 metric label에 넣지 않습니다. raw handler error는 failure_kind로 축약된 decode/handler 값으로 대체합니다.
  • rustee-outbox-sqlx::stage_event_after는 여전히 generic database-to-event delay에 적합하지만, Kafka source-offset delayed retry를 대체하지 않습니다.
