ADR 0020

AI evaluation, cache, and batch boundary

Status: Accepted. Date: 2026-08-03.

Context

AI evaluation, response cache, and batch execution 모두 prompt, expected answer, completion 또는 access-controlled application data를 오래 보관하거나 더 넓은 scope로 재사용할 위험이 있다. rustee-ai의 provider call, budget/usage ledger, advisor와 RAG ACL은 이미 application-owned authorization boundary를 갖지만 evaluation fixture, cache fingerprint, batch payload를 core가 임의로 만들면 tenant/data retention과 provider billing semantics가 흐려진다.

Decision

평가, cache, batch를 하나의 hidden AI convenience layer로 합치지 않는다. 각각 optional crate와 explicit application-owned catalog/store/executor boundary로 도입한다.

  • rustee-ai-eval은 generic target과 trusted grader를 가진 bounded in-memory suite를 실행한다. report는 safe case ID, normalized pass/fail score/label, model alias와 usage만 가진다. request, target, completion은 serialization, Debug, telemetry report에 넣지 않는다.
  • evaluation executor는 application-governed pipeline wrapper여야 한다. evaluator는 hidden provider retry, parallel fan-out, budget bypass, usage settlement 또는 automatic tool loop를 제공하지 않는다. case failure는 later case를 시작하지 않고 fail-fast 한다.
  • future response/semantic cache는 application-generated tenant namespace와 opaque versioned fingerprint, explicit TTL, erase/invalidate policy, cache-hit accounting과 fail-closed/bypass policy를 요구한다. tool-call response, shared chat memory, prompt/content hash와 cross-tenant reuse를 default로 만들지 않는다.
  • future durable batch는 raw suite/case/conversation이 아니라 application catalog reference, trusted run key, bounded scope와 idempotency metadata만 rustee-jobs payload에 보관한다. worker가 catalog를 authorized load하고 evaluator executor를 선택한다.

Consequences

  • application은 grading target semantics, human/LLM grader trust, cache encryption/retention, tenant erase, catalog authorization, batch scheduling/concurrency, pricing/reconciliation을 문서화해야 한다.
  • evaluation report가 observability 또는 release comparison에 적합한 content-free record가 되며 fixture content는 application test data에 남는다.
  • first implementation은 deterministic local evaluation contract다. distributed cache stampede control, durable evaluation catalog, provider async batch API, live grader spend limit과 comparative/online evaluation evidence는 release gate로 남는다.

Alternatives

대안판단
prompt/completion을 framework evaluation report 또는 job JSON으로 직접 직렬화retention, privacy, tenant erase와 queue exposure가 숨겨지므로 채택하지 않는다.
모든 AiPipeline completion에 automatic semantic cache 적용tool result, tenant authorization, stale answer와 cost accounting을 혼합하므로 채택하지 않는다.
evaluation failure를 provider retry로 자동 해결model output/charge ambiguity를 증가시키므로 application이 explicit run policy를 결정한다.
provider-specific async batch API를 core contract로 가정cancel/partial result/retry/billing semantics가 provider마다 달라 optional adapter로 분리한다.

Follow-up

  • rustee-ai-eval은 unique/bounded suite, generic trusted grader, sequential no-retry executor, content-free case report/usage summary와 deterministic fake-provider contract를 구현한다.
  • cache adapter는 namespace/fingerprint/TTL/erase/failure-mode and tool-result eligibility contract를 별도 ADR로 추가한다.
  • batch catalog/job adapter는 durable reference/idempotency, scoped worker load, partial failure/retry/cancel/reconciliation, provider async batch evidence를 별도 ADR로 추가한다.
