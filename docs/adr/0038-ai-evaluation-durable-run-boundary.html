ADR 0038

AI Evaluation Durable Run Boundary

AI evaluation을 durable worker로 전달하되, raw suite와 model result를 payload/ledger에 넣지 않고 ambiguous run을 자동 재실행하지 않습니다.

Status: Accepted | Date: 2026-08-04

Context

rustee-ai-eval의 in-memory runner는 application-owned prompt, target, executor와 grader를 안전하게 순차 실행하지만, long-running suite는 durable job과 restart-safe idempotency가 필요합니다. raw suite를 job JSON이나 shared ledger에 넣으면 prompt, expected target, completion, grader metadata의 retention/tenant erase/access policy가 framework에 숨어듭니다. 반대로 failure 뒤 provider call을 다시 실행하면 usage charge, model nondeterminism과 report sink ambiguity를 만들 수 있습니다.

Decision

AiEvaluationReference는 bounded scope, catalog_id, run_key만 보관합니다. authorized application AiEvaluationCatalog가 worker 시작 뒤 raw suite를 load하고, AiEvaluationRunLedger가 scoped run key를 atomic reserved, completed, pending 상태로 관리합니다. rustee-ai-eval-jobs은 run key와 동일한 job idempotency key를 요구하고, rustee-ai-eval-sqlx은 PostgreSQL에 reference/status만 durable하게 저장합니다.

AiEvaluationSubmitter는 prior completion이면 catalog/model/grader를 호출하지 않습니다. catalog load, executor, grader 또는 completion record 단계의 failure는 reservation을 pending으로 남깁니다. automatic release/retry, report persistence, provider usage refund, catalog authorization, human/LLM grader spend 및 report retention은 application이 소유합니다.

Consequences

  • durable payload와 PostgreSQL ledger에는 prompt, target, completion, grader detail, provider endpoint, report body를 넣지 않습니다. pending query는 redacted reference만 reconciliation code에 돌려줍니다.
  • 같은 (scope, run_key)를 다른 catalog ID에 재사용하면 fail-closed 합니다. completed run은 idempotent하게 acknowledge하지만 report를 다시 load하거나 model을 재호출하지 않습니다.
  • provider or grader failure 후 broker delivery가 재시도되어도 ledger가 pending을 반환하므로 second model call은 발생하지 않습니다. 재평가가 안전한 경우만 application이 audit/reconciliation 뒤 새 run key로 새 job을 enqueue합니다.
  • PostgreSQL CI는 pending preservation, completion reuse, exact identity conflict와 pending reference debug redaction을 검증합니다. local default test는 database container 없이 unit contract만 실행합니다.
  • 이 경계는 comparative baseline, live provider qualification, human/LLM grader authorization/cost/redaction, report retention/erase, semantic cache와 batch partial-result reconciliation을 Supported로 올리지 않습니다.

Alternatives

대안판단
raw suite 또는 report를 job payload/ledger에 직렬화retention, authorization, tenant erase와 provider-content exposure를 framework가 암묵적으로 소유하게 되므로 채택하지 않습니다.
failure 시 같은 run key로 model/grader를 자동 재실행provider usage, nondeterministic output과 report completion ambiguity를 감추므로 채택하지 않습니다.
completed run에서 prior report를 generic ledger가 반환report authorization/retention/data shape는 application마다 다르므로 ledger는 completion state만 보관합니다.
job idempotency와 run key를 독립적으로 둠duplicate delivery가 다른 run identity로 model call을 반복할 수 있으므로 채택하지 않습니다.
