ADR 0004

MongoDB 통합 경계

Status: Accepted. Date: 2026-08-01.

Context

MongoDB의 BSON document, collection, aggregation, replica set, change stream은 SQL database와 다른 모델과 운영 특성을 갖는다. 이를 SQLx 또는 공통 repository trait에 맞추면 document model의 장점과 중요 제약이 숨겨진다. 반면 MongoDB Rust driver 자체의 client/pool, schema evolution, transaction, worker lifecycle에 대한 공식 경로가 없으면 서비스별 구현 품질이 달라질 수 있다.

Decision

MongoDB는 Stage 7에서 공식 async mongodb Rust driver를 사용하는 선택적 rustee-mongodb integration으로 지원한다. mongodb::Client는 long-lived application state로 주입하고, driver의 내장 connection pool을 그대로 사용한다.

  • rustee-core는 MongoDB 또는 BSON에 의존하지 않는다.
  • Rustee는 driver의 collection, aggregation, transaction API를 새 generic trait로 감싸지 않는다.
  • BSON persistence document와 HTTP request/response DTO는 분리한다.
  • index, validator, data backfill은 배포 pipeline의 명시적 작업으로 관리하고 server startup에서 자동 실행하지 않는다.
  • multi-document transaction은 ClientSession에서 명시적으로 관리하며, 기본 extractor나 요청 단위 자동 transaction을 제공하지 않는다.
  • change stream은 resume token과 restart 전략을 갖는 background worker로 다루며, HTTP handler에 직접 결합하지 않는다.
  • opaque resume token은 ChangeStreamCheckpointStore로 durable storage를 선택하고, PostgreSQL 환경에는 선택적 rustee-mongodb-checkpoint-sqlx adapter와 database-clock writer lease를 제공한다. deployment는 고유 lease owner identity, renewal schedule, token invalidation과 recovery를 명시한다.
  • tenant-owned document는 shared trusted TenantContext에서 만든 MongoTenantScope로 outer-AND tenant_id filter, document/update boundary와 target collection first-match aggregation pipeline을 적용한다. 이는 MongoDB RLS가 아니며 raw driver, aggregation의 $lookup/$unionWith와 change stream pipeline의 tenant policy를 자동으로 강제하지 않는다.

Consequences

  • MongoDB를 쓰지 않는 서비스의 core dependency와 compile time이 늘지 않는다.
  • driver가 제공하는 pool, topology monitoring, replica set 기능을 중복 구현하지 않는다.
  • API response가 persistence 세부사항에 고정되지 않아 document schema를 점진적으로 변경할 수 있다.
  • schema evolution, transaction, change stream의 운영 책임이 명시적으로 남아 production behavior를 검토할 수 있다.
  • generic CRUD의 초기 편의성은 포기하지만, authorization, index, aggregation, API versioning이 숨겨지지 않는다.
  • MongoDB는 PostgreSQL RLS와 다른 application-level tenant boundary를 갖는다. raw collection handle을 HTTP handler에 넓게 주입하지 않고, administration/migration은 별도 access review와 운영 권한으로 분리해야 한다.
  • checkpoint adapter는 restart 뒤 duplicate event를 줄이고 opt-in writer lease는 stale concurrent checkpoint writer를 거부하지만 exactly-once를 주장하지 않는다. handler idempotency와 lease owner/renewal 운영이 gate로 남는다.

Alternatives

대안 판단
MongoDB를 SQLx backend로 취급 query/model/transaction의 본질이 달라 적절하지 않으며 채택하지 않는다.
MongoDB dependency를 core에 포함 모든 서비스에 필요한 기능이 아니므로 core 안정성과 dependency budget을 해쳐 채택하지 않는다.
별도 connection pool을 기본으로 추가 공식 driver Client가 내부 pool을 관리하므로 중복 계층을 만들지 않는다.
collection 자동 CRUD route와 BSON response 제공 authorization, schema, internal field, query 비용을 숨기므로 채택하지 않는다.
startup 때 index와 migration 자동 실행 대용량 index와 data change가 배포 가용성을 해칠 수 있어 채택하지 않는다.

Follow-up

  • Stage 7에서 rustee-mongodb의 configuration, readiness, shutdown integration을 구현한다.
  • typed collection과 DTO mapping, duplicate key/error mapping, schema evolution example을 integration test로 검증한다.
  • replica set을 사용하는 transaction과 change-stream resume test를 추가한다.
  • trusted-context tenant BSON scope의 A/B read/update/delete isolation과 tenant-field mutation rejection을 replica-set contract로 검증한다.
  • PostgreSQL adapter의 opaque token load/upsert/corruption rejection 및 database-clock lease contention/renewal/expiry/stale-writer rejection, stopped checkpoint-store readiness failure/recovery contract를 추가하고 MongoDB outage는 별도 release gate로 검증한다.
  • Stage 10에서 sharding, read preference, retry, event delivery 요구가 생기면 workload와 함께 별도 ADR 및 release gate로 확장한다.
