ADR 0018

MCP OAuth client boundary

Status: Accepted. Date: 2026-08-03.

Context

MCP 2025-11-25 HTTP authorization은 protected MCP server에 대한 OAuth 2.1 client flow다. 기존 rustee-auth-oidc browser login은 Rustee application 사용자를 principal/session으로 만드는 흐름이므로, MCP server용 access/refresh token을 application session이나 generic bearer verifier에 섞으면 audience, consent, rotation 및 tenant ownership이 불명확해진다. stdio credential은 deployment environment가 소유하며 이 OAuth flow 대상이 아니다.

Decision

HTTP MCP authorization은 rustee-ai-mcp-oauth optional adapter로 분리한다. 이 adapter는 explicit application configuration과 user-facing callback integration을 요구하며, rustee-ai-mcp core의 tool approval, no-replay transport, context adoption boundary를 바꾸지 않는다.

  • adapter는 401 WWW-Authenticate: Bearer challenge의 quoted resource_metadata와 scope를 bounded하게 parse하고, 없으면 endpoint path-specific, root protected-resource metadata URI 순서로 discovery한다. discovered URL과 response는 HTTPS/trust/size policy를 통과해야 한다.
  • selected authorization server에서 OAuth authorization-server metadata와 OIDC discovery fallback을 정해진 순서로 조회한다. issuer, authorization endpoint, token endpoint, PKCE S256 declaration과 registration capability를 typed, redacted model로 검증한다.
  • application은 pre-registered client ID, exact redirect URI와 scope selection을 명시한다. opaque automatic dynamic registration/client metadata document publishing은 first release에 넣지 않는다.
  • authorization-code flow는 URL-safe high-entropy state와 PKCE verifier를 application-owned atomic transaction store에 짧은 TTL로 저장한다. callback은 state를 exchange 전에 consume하고 authorization/token request 모두 canonical MCP URI를 resource parameter로 보낸다.
  • access token, refresh token과 authorization code는 Debug, error, audit attribute, URL 및 ordinary Rustee session cookie에 절대 넣지 않는다. token store encryption, tenant/user binding, retention, revocation, key rotation과 concurrent refresh single-flight는 application-owned McpOAuthTokenStore contract로 둔다.
  • authorized MCP HTTP client는 selected resource용 token만 Bearer header로 보낸다. 401/403 insufficient-scope는 sanitized authorization result와 explicit step-up input으로 끝나며 failed tool/discovery/read/prompt request를 자동 replay하지 않는다.
  • rustee-mcp server-side protected-resource metadata, challenge emission, access-token audience validation은 별도 resource-server release gate다.

Consequences

  • application이 consent UI, callback route, token persistence와 operator revoke procedure를 명시해야 하므로 credential source와 data exit가 숨겨지지 않는다.
  • OAuth token은 remote tool approval이나 tenant/data authorization을 대체하지 않는다. token을 얻어도 discovered tool, resource, prompt 또는 SSE notification이 자동 채택되지 않는다.
  • 401 discovery, metadata validation, state/PKCE, exchange, refresh, scope step-up, expiry/revocation, redaction과 no-replay contract는 local fixture와 representative provider matrix로 검증해야 한다.

Alternatives

대안판단
generic application OIDC browser-login session을 MCP bearer token으로 재사용token audience와 resource binding을 잃고 MCP token을 ordinary browser session에 노출할 수 있어 채택하지 않는다.
endpoint URL에서 authorization server를 추측하거나 임의 issuer를 허용confused deputy와 token exfiltration 위험이 있으므로 protected-resource metadata discovery를 강제한다.
401/403 뒤 original MCP request를 자동 재전송tool call의 side effect를 판단할 수 없으므로 authorization 준비만 반환하고 application이 explicit next action을 결정한다.
첫 release에 dynamic client registration을 자동 사용client identity publishing/trust/rollback policy가 필요하므로 pre-registration과 분리한다.

Follow-up

  • rustee-ai-mcp-oauth는 bounded client discovery, PKCE transaction, authorization-code/explicit refresh exchange, redacted token-store traits와 no-replay handoff를 구현했다. package/loopback contract는 resource binding, callback state consume, provider rejection의 no-exchange와 implicit refresh 금지를 고정한다.
  • rustee-ai-mcp-oauth-redis는 AES-256-GCM envelope, purpose/full-key authenticated binding, active/retired decryption-key rotation, transaction TTL/GETDEL과 token retention을 구현했다. user consent/callback example, tenant/user key/KMS procedure, supported authorization-server matrix, live opt-in contract, cross-instance refresh와 revocation/rotation runbook은 release gate로 추가한다.
  • rustee-mcp resource-server metadata/challenge/audience validation은 application authentication middleware와 deployment auth policy를 포함하는 별도 ADR에서 다룬다.
