Official Examples

Runnable Examples for the Supported Application Path

Examples are small applications with a stated contract. They compile in the workspace and represent the intended API shape; they do not replace provider or deployment qualification.

Example Map

Example Shows Boundary
hello-world JSON greeting and OpenAPI document quickstart In-process behavior, not a public deployment
json-api Typed path, query, JSON, state, and invalid-input flow Domain persistence remains application-owned
middleware Explicit CORS, request ID, panic boundary, and compression composition Production proxy and alert policy remain deployment-owned
security-jwt HMAC JWT bearer authentication boundary Key distribution and identity-provider operations are not demonstrated
jobs Typed publish, registry decode, and handler delivery metadata Local publishing is not broker durability
ai-pipeline OpenAI-backed HTTP pipeline with a deployment-configured model Recorded behavior is not billable live-provider qualification

Running

cargo +1.94.1 run --locked -p hello-world
cargo +1.94.1 run --locked -p json-api
cargo +1.94.1 run --locked -p middleware-example
JWT_HMAC_SECRET=change-me cargo +1.94.1 run --locked -p security-jwt
cargo +1.94.1 run --locked -p jobs-example
OPENAI_API_KEY=... OPENAI_MODEL=your-provider-model-id cargo +1.94.1 run --locked -p ai-pipeline

Only the AI example contacts a provider when its endpoint is invoked. Its credentials, spending limit, tenant policy, output retention, and outage qualification remain deployment-owned.

Running and Verifying

cargo +1.94.1 check --locked --workspace --all-targets
cargo +1.94.1 test --locked --workspace --all-targets

Examples are binary workspace members, so --all-targets compiles and tests them alongside the framework. --locked uses the committed dependency graph while still allowing a first checkout to download missing crates; maintainer or CI environments with a warm cache may additionally use --offline. Each example must have bounded, deterministic representative tests. An example that needs a provider credential, broker, database, public edge, or billable model call documents an explicit opt-in qualification path instead of making that call part of ordinary CI.

Change Rules

  • Update an example in the same change as any public API it demonstrates.
  • Do not add production credentials, secrets, unbounded payloads, raw prompts, or live-provider assumptions.
  • Keep the example focused on a single workflow and link to a focused integration document for operational details.
  • Update the support matrix and release evidence when a documented example changes the support claim.
