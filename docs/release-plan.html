Release Plan and Support Policy

Release a Small Core First; Support Integrations Only to the Proven Level

Rustee release claims are evidence-based. Optional adapters retain their own support level and do not inherit production support from the core.

Support Levels

Level Meaning
Experimental Public design/implementation exists, but a complete compatibility matrix is absent.
Supported Documented contract, supported-version matrix, targeted automated tests, operational guidance, and maintainer ownership are present.
Enterprise-qualified deployment An adopter has selected a provider and topology, then recorded approved recovery/rollback, observability, security review, and on-call evidence for that deployment.

Release Tracks

  • The core track includes the facade, foundational shared packages, core HTTP path, router, server, selected middleware, configuration, observability, OpenAPI, tests, and examples.
  • Integration tracks cover database, Redis, MongoDB, identity, jobs, events, AI, MCP, and edge delivery independently.
  • Security advisories, MSRV changes, supported dependency changes, provider versions, and breaking contracts receive explicit release notes and migration guidance.

v1 Boundary

v1 requires a stable documented core API, compatible MSRV policy, focused tests, documentation, source/release evidence, and an intentional support statement. It does not require a framework maintainer to operate every optional provider or an adopter's enterprise topology.

Change Control

  • Update the release inventory, support matrix, release notes, migration guide, and qualification register with a changed framework or deployment claim.
  • Do not promote a framework contract based only on unit tests, a mock, a local container, or a successful compile.
  • Block a generic release on unresolved critical advisories, unreviewed breaking changes, missing provenance, failed required contract lanes, or missing maintainer approval.
  • An Enterprise-qualified deployment claim additionally requires that adopter's qualification register to pass qualified-record verification with current evidence.
  • Follow the release checklist for source and publication evidence.
