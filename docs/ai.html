AI Application Integration

Make Model Calls a Safe Service Capability

Rustee provides optional, provider-neutral AI contracts for chat, streaming, structured output, retrieval, tools, usage, and tests. The framework supplies enforcement points; applications own domain policy and side effects.

Design Rules

  • Model output, retrieved content, and tool requests are untrusted input. They never become authority by themselves.
  • Every provider request passes through final-request policy. Verified tenant and subject context, budgets, approval, audit, redaction, and idempotency are explicit inputs.
  • Tool execution is deny-by-default. A typed registry, approval decision, terminal audit, and application-created execution context precede an approved handler.
  • Raw prompts, completions, secrets, bearer tokens, and retrieved private content are not default logs, trace attributes, metrics labels, cache keys, or evaluation reports.
  • Rustee does not bundle a model-provider SDK, API key, prompt template, vector database, automatic agent loop, or autonomous tool execution in the core crate.

Pipeline and Advisor Model

let response = AiPipeline::new(provider)
    .complete_with_advisor(request, &advisor)
    .await?;

An advisor can enrich a final request and observe request, response, and stream lifecycle. Applications compose ordered budget, retrieval, or other policies into one explicit AiAdvisor when a call needs more than one. Advisors cannot silently create tenant authority, ignore an approval decision, or bypass a content-free usage reservation. Pipeline, advisor, and stream diagnostics retain safe categories while exposing application sources only through trusted error handling. Structured output is parsed into an application-selected type after the provider response crosses the boundary.

Tenant and access

Use verified tenant and subject context for budget, tool approval, audit, and document access. Domain authorization remains application policy.

RAG

Revalidate tenant and document ACLs during retrieval. Rustee bounds search-query input, ACL allowlist size, and requested candidate counts before a vector-store call. RAG debug output redacts search text, scope identifiers, and injected adapter configuration; retrieval, ingestion, advisor, and durable ingestion-job error display and debug output stay content-free. Source loaders own document-read limits; Rustee bounds provider-bound chunks and splits embedding calls by explicit input and byte limits before one atomic index upsert. A conforming index makes the complete batch visible together rather than reporting a partial replacement as success. Adapter sources remain explicit application diagnostics. Ingestion, source authorization, vector-store choice, retention, and erase behavior are application-owned.

Conversation state

Conversation memory is not a framework global. The application defines identity, retention, redaction, and persistence.

Usage and budgets

Reserve before a provider attempt and settle usage afterward. Budget admission and content-free reservation, settlement, and stream-lifecycle diagnostics remain one internal module, separate from provider orchestration. Pricing, refunds, quotas, and cross-service atomicity remain deployment policy.

Tools and MCP

  • Typed tools receive an explicit ToolExecutionContext with the verified identity and application idempotency key shared by the handler and audit sink. Approval and audit errors expose content-free categories by default while retaining their application sources for trusted handling.
  • rustee-ai-mcp supports bounded MCP Streamable HTTP JSON/SSE and stdio initialization, discovery, approved calls, explicit close, and capability-gated read-only resources, templates, and prompts. Its configured HTTP deadline applies to every request, including application-injected clients.
  • HTTP session invalidation does not replay a tool call. Optional bounded recovery performs a new handshake only; valid SSE resumption uses GET with Last-Event-ID and never retransmits an origin POST or tool call.
  • Stdio deadlines discard the connection and use bounded graceful or forced close. Explicit or bounded automatic restart starts a new handshake and does not replay a prior call.
  • Returned MCP context and notifications require application and user selection, authorization, redaction, and token-budget policy before becoming provider input. They are never injected automatically.
  • rustee-mcp mounts an MCP JSON server with exact-one Origin and standard application JSON Content-Type admission, exact-one protocol-version admission for non-initialization requests, bounded access-filtered discovery, approval, and mandatory terminal audit. Server-initiated requests, subscriptions, sampling, elicitation, and completion are not implemented.

MCP OAuth

rustee-ai-mcp-oauth is a separate client-side authorization boundary: protected-resource and authorization-server discovery, PKCE S256, atomic one-time state/verifier handling with a whole-second one-hour maximum TTL, at most 32 scopes, bounded canonical resource and callback URLs, an 8 KiB authorization redirect, redacted token sets, content-free OAuth diagnostics, and optional AES-256-GCM Redis envelopes with decryption-key rotation plus versioned length-delimited transaction and token record keys. rustee-mcp-oauth serves public protected-resource metadata and fail-closed Bearer challenges and hands off a verified principal; it does not issue, store, or refresh tokens.

Production KMS delivery, consent and revocation runbooks, cross-instance refresh coordination, authorization-server qualification, canonical proxy URLs, and live deployment evidence are release gates.

Streaming, Evaluation, Cache, and Batch

  • The web adapter exposes redacted, bounded SSE and NDJSON responses. Each configured frame limit includes JSON and transport framing; any pipeline stream failure, terminal completion, or an oversized event stops the upstream stream. An oversized event produces one generic terminal error. Client disconnect and cancellation are observable outcomes, not opportunities to expose provider bodies.
  • Evaluation suites are unique and bounded, run sequentially without automatic retries, and report content-free grade/model/usage data. Runner, reference-submission, and durable job diagnostics retain only safe outcome categories while preserving application source chains for trusted handling. Human or LLM grader trust and spend are not framework defaults.
  • The response cache uses an application-generated tenant-scoped opaque SHA-256 exact key, explicit TTL of at most 24 hours, tool-interaction exclusion, exact invalidation, and matching read/write entry-size limits for its Redis adapter. A bypassed cache-read failure completes through the provider once without attempting a cache write. Cache adapter display and debug errors retain only outcome categories while preserving explicit error sources for application handling. A poisoned local adapter fails closed and renders retained-entry state as unavailable, never as an empty cache. Fingerprint policy, tenancy erase, stale-answer UX, outage policy, and stampede control are application-owned.
  • Batch submission stores tenant scope, catalog and run-key references, reservation receipts, and safe artifact references without durable raw batch content. Submission and artifact-reconciliation display and debug errors retain outcome categories while preserving explicit application error sources. A poisoned local ledger fails closed and renders retained-record state as unavailable, never as zero records. Row-level custom_id idempotency, domain processing, retention/delete schedules, billing reconciliation, and operator recovery remain application responsibilities.

Release Boundary

Live model credentials, provider outages, document or vector-provider contracts, pricing accuracy, audit retention, side-effect reconciliation, and human approval operations require opt-in deployment evidence. A compile-checked or recorded example is not live-provider qualification.
