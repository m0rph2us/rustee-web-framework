OpenAPI Does Not Guess Route Implementation

rustee-openapi is an optional explicit document builder. It validates and converts Rustee route patterns but leaves operation semantics, schemas, descriptions, and security ownership with the application.

Boundary

  • Rustee route :parameter segments convert to OpenAPI {parameter} paths only after validation. The shared grammar rejects ambiguous repeated path separators.
  • Applications explicitly attach operations, request/response schemas, tags, descriptions, and security requirements. Raw schema objects are byte-admitted before storage, and duplicate component names, operation IDs, method/path pairs, parameter locations, and response status codes are rejected rather than overwritten. Header parameter names must be valid HTTP field names and compare case-insensitively.
  • OpenAPI metadata documents an API contract; it does not create handlers, validate live authorization, infer error behavior, or change application routing.

Minimal Path

use rustee::{
    StatusCode,
    openapi::{
        OpenApiDocument, OpenApiMethod, OpenApiOperation, OpenApiRoute, OpenApiSchema,
        OpenApiSecurityRequirement, OpenApiSecurityScheme,
    },
};

let document = OpenApiDocument::new("Rustee API", "1.0.0")?
    .security_scheme("bearerAuth", OpenApiSecurityScheme::http_bearer())?
    .operation(
        OpenApiRoute::from_rustee("/users/:id")?,
        OpenApiMethod::Get,
        OpenApiOperation::builder("get_user")
            .path_parameter("id", OpenApiSchema::string())
            .security_requirement(OpenApiSecurityRequirement::scheme("bearerAuth")?)
            .empty_response(StatusCode::OK, "User")
            .build()?,
    )?;

Use explicit schemas and descriptions for public APIs. Security metadata can describe bearer, OAuth2, mutual TLS, and API-key requirements, but it does not configure the authentication middleware or validate provider policy.

Verification and Non-Goals

  • Test route conversion, duplicate and malformed path rejection, operation attachment, schema references, and security metadata independently.
  • Property and fuzz tests exercise route/OpenAPI parser boundaries. They complement explicit regression cases.
  • Do not derive arbitrary handler semantics, database models, error status, CORS policy, authentication behavior, or provider credentials from a route.
  • See ADRs 0039 and 0043 through 0047.
