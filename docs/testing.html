Testing Strategy

동작 계약을 빠르고 실제에 가깝게 검증합니다

Rustee의 테스트는 line coverage를 늘리는 활동이 아니라, HTTP와 async lifecycle, feature 조합, 외부 의존성의 observable behavior를 안정적으로 고정하는 계약입니다. 빠른 피드백과 실제 transport/dependency 검증을 분리해 개발 속도와 신뢰성을 함께 지킵니다.

결정 요약

기본 test runner는 stable Rust의 cargo test입니다. workspace의 빠른 test binary 실행은 cargo nextest run으로 병렬화하고 doctest는 별도로 cargo test --doc로 실행합니다. rustee-test는 application과 integration crate를 위한 in-process test client를 제공하지만, 실제 TCP/HTTP end-to-end test를 대체하지 않습니다.

모든 public behavior에는 가장 싼 층의 test를 먼저 둡니다. protocol, cancellation, shutdown, network backpressure, broker/client interoperability처럼 in-process test로 증명할 수 없는 위험만 실제 socket 또는 container-backed test에서 다룹니다. test 범위와 비용은 crate feature별로 독립적으로 관리합니다.

출하 게이트와 CI lane

출하 계획의 지원 단계는 단일 cargo test 결과로 승격하지 않습니다. 빠른 pull request gate, provider contract gate, release qualification을 분리하고 각 lane이 어떤 약속을 증명하는지 기록합니다.

rustee-test는 dev-dependency로 사용 가능한 작은 helper crate입니다. TestApp은 in-process request, JSON/header/body construction, bounded buffered response, JSON/text decode와 body/header value를 render하지 않는 status/header assertion을 제공합니다. TestApp::with_cookie_jar()는 session-style test를 위해 response Set-Cookie의 valid ASCII name/value만 보존하여 다음 request의 Cookie로 보냅니다. Max-Age=0 삭제, 64개/합계 8 KiB bound, successful response buffer 뒤 atomic update와 explicit request Cookie header 우선만 지원합니다. jar는 value를 debug/inspection API에 노출하지 않습니다. Domain, Path, Secure, SameSite, Expires, redirect, HTTP version, SSE와 cancellation은 wire/browser contract에 남기며 사용자의 production API를 흉내 내는 거대한 DSL은 만들지 않습니다. rustee-test-support는 공개 API가 아니며 test fixture와 container setup을 한곳에 둡니다.

rustee-router는 96-case proptest contract로 accepted route grammar, parameter value preservation과 static-route precedence를, rustee-openapi는 accepted Rustee template의 parameter set과 rendered OpenAPI path를 fast test lane에서 확인합니다. fuzz/는 publishable Cargo workspace와 분리되어 있으며, route_pattern target은 arbitrary UTF-8 input을 App::try_route/App::try_nest에, openapi_route target은 OpenApiRoute::from_rustee에, openapi_security_scheme target은 header 위치의 OpenApiSecurityScheme::api_key에 전달합니다. seed corpus는 review 가능한 input만 유지하고 artifact/target output은 ignore합니다. sanitizer 실행은 nightly와 C++ standard library header가 필요하므로 local toolchain이 없으면 Fuzz CI의 bounded Linux run을 사용합니다. 범위와 crash-to-regression 절차는 ADR 0044에서 관리합니다.

결정론과 async 규칙

  • test는 wall-clock sleep과 순서 우연에 의존하지 않습니다. timeout, retry, delayed job은 Tokio paused time 또는 명시적 synchronization signal로 제어합니다.
  • 시간, random ID, port, 환경 변수, network client는 subsystem의 test construction에서 대체할 수 있게 하되, production 사용자에게 범용 mock trait를 강요하지 않습니다.
  • 병렬 test는 tenant/namespace, database/schema, Redis key prefix, topic/queue name, temp directory를 고유하게 생성하고 cleanup을 검증합니다.
  • flaky test를 retry로 숨기지 않습니다. CI retry는 container startup 같은 infrastructure failure의 진단 보조에만 쓰고, product race는 재현 fixture와 원인 수정으로 해결합니다.
  • cancellation, panic, timeout, graceful shutdown 뒤에는 task leak, unacked job, uncommitted offset, connection leak이 없는지 observable outcome으로 확인합니다.

기능별 필수 계약

HTTP Core

direct route와 longest-prefix nesting precedence, prefix-stripped URI/query, full route template, child-owned fallback/405, percent-decoding, body limit, malformed request, extractor rejection, response header/body, middleware short-circuit와 content-coding cache variation을 다룹니다.

Server

실제 listener와 client로 keep-alive, concurrent request, disconnect cancellation, readiness, zero-downtime drain과 Nginx를 통과한 active request drain을 확인합니다.

Security

401/403 mapping, real loopback HTTPS transport failure에서 JWKS/opaque introspection이 raw token/endpoint 없이 반환하는 provider-unavailable 503, issuer/audience/signature/JWKS cache와 unknown-kid rotation, opaque introspection의 active/time/revocation-cache 경계, OIDC discovery/PKCE/state replay/nonce/session issuance, Redis TTL/GETDEL transaction consume, session rotation/CSRF, direct permission/role grant bypass, configured-host tenant resolution의 mismatch/unknown/duplicate/outage와 PostgreSQL tenant RLS read/write isolation을 integration test로 고정합니다.

Storage

migration은 deployment step으로 검증하고, connection failure/readiness/transaction/TTL/index 정책은 real backend contract에서 확인합니다.

Jobs and Events

duplicate delivery, retry/backoff, DLQ, drain, outbox, consumer reclaim과 Kafka rebalance/offset/replay 및 PostgreSQL durable delayed retry relay를 provider별 실제 backend에서 다룹니다.

AI

rustee-ai-test의 deterministic provider script/recorded stream과 application fake store로 structured output, tool permission, budget, RAG citation/ACL을 결정론적으로 검증하고 provider protocol test는 opt-in으로 둡니다.

Feature와 provider matrix

--all-features 한 번의 성공을 전체 호환성 증명으로 보지 않습니다. 각 optional integration crate는 default feature 없이 compile/test하고, facade의 지원 feature profile과 dependency adapter의 contract profile을 따로 실행합니다. 지원하지 않는 feature 조합은 Cargo.toml compile error와 compile-fail test로 명시합니다.

  • core: Rust 1.94.1 MSRV, stable latest, --no-default-features, default facade
  • integration: SQLx, Redis, MongoDB, auth, each job provider, Kafka, AI adapter를 독립 package/profile로 실행
  • request correlation and metrics contract: rustee-observability은 generated UUID request ID의 request extension/response header 연결과 untrusted inbound ID 무시를 in-process layer와 real TCP server test로 검증합니다. rustee-observability-opentelemetry는 in-memory SDK exporter로 server span kind, correlation ID, method/status/bounded route attribute와 raw query string 미노출을 검증하고, valid W3C remote parent가 request span의 직접 parent가 되는지와 explicit outbound child injection을 확인합니다. duplicate traceparent는 new root trace가 되고 incoming tracestate를 forward하지 않아야 합니다. rustee-router는 configured RouteTemplate을 handler request와 response layer에 전달하고, nested app에서도 prefix를 포함한 template, child-owned fallback/405와 raw URI 없는 reserved RouteClassification을 남기는지 검증합니다. MetricsLayer는 완료 요청의 status-class/router-classification/total-duration 집계, strictly increasing bounded latency bucket과 cancelled future의 in-flight 회수를 검증합니다. rustee-observability-prometheus는 text 0.0.4 syntax, histogram _bucket/_sum/_count, content type/cache header, label escaping, raw unmatched path 미노출을 검증합니다. rustee-server은 transport peer ConnectionInfo injection을 real TCP로 검증합니다. rustee-middleware는 default ForwardedX-Forwarded-* mode의 trusted CIDR, bounded chain, family isolation, duplicate/missing/malformed rejection을 in-process로 검증합니다. Linux CI의 nginx:1.30.4-alpine contract는 Nginx가 client-supplied Forwarded를 덮어쓴 뒤 Rustee가 trusted context만 복원하고, proxy_cache가 gzip/identity Vary: Accept-Encoding representation을 섞지 않는지 확인합니다. vendor CDN purge/TLS/cache-control test는 별도 release gate입니다.
  • OTLP Collector contract: CI는 pinned otel/opentelemetry-collector:0.153.0 HTTP receiver와 debug exporter를 .github/fixtures/otel-collector.yaml으로 실행합니다. rustee-observability-opentelemetry의 ignored test는 opentelemetry-otlp HTTP binary exporter로 request span을 batch flush하고, workflow는 Collector log의 HTTP request까지 확인합니다. 로컬도 Docker daemon과 RUSTEE_OTLP_ENDPOINT로 같은 suite를 opt-in 실행합니다.
  • OIDC transport outage contract: rustee-auth-oidc은 비어 있는 loopback HTTPS port를 실제로 호출해 JWKS fetch와 opaque introspection 양쪽이 authentication_unavailable 503으로 fail-closed되고 response body가 bearer credential 또는 provider address를 포함하지 않는지 확인합니다. external IdP의 revocation lifecycle은 별도 provider release gate입니다.
  • static file contract: rustee-static은 configured prefix의 GET/HEAD content type, length, cache and nosniff header, weak ETag/Last-Modified, If-None-Match/If-Modified-Since 304와 ETag precedence, single/multipart bytes 206/416, If-Range date와 normalized range set을 검증합니다. multipart는 exact Content-Length, per-part header, HEAD empty body, malformed/excessive set 416을 확인합니다. opt-in precompressed variant는 quality negotiation, missing preferred sibling fallback, representation validator/304와 Range identity fallback을 검증합니다. opt-in streaming은 large full/single-range/selected variant body가 bounded chunk로 전송되고 header contract를 유지하는지 검증합니다. prefix 밖과 non-GET/HEAD는 inner service로 전달하며, decoded traversal, directories, canonical root 밖 symlink target과 maximum-size 초과는 filesystem detail 없이 404가 되어야 합니다.
  • response compression contract: CompressionLayer는 actual gzip/Brotli decode, quality negotiation, identity representation의 Vary: Accept-Encoding, existing coding 보존, Range/HEAD/no-transform bypass, Content-Length 제거와 trailer 전달을 in-process로 검증합니다. Nginx proxy_cache integration은 gzip과 identity 표현의 MISS/HIT separation을 확인하며 vendor CDN purge/TLS/cache-control test는 별도 gate로 남습니다.
  • runtime panic boundary contract: PanicCatchLayer의 in-process와 real TCP suite는 handler panic이 fixed internal_error 500 body로 바뀌고 private panic text가 response에 없음을 확인합니다. post-commit body panic, panic = "abort", global panic hook redaction과 process restart는 application/deployment test가 소유합니다.
  • OpenAI adapter contract: rustee-ai-openai은 local ephemeral TCP server로 Responses request authorization/body, completed response, SSE text/usage normalization과 Embeddings batch authorization/body, provider index reordering 및 duplicate/missing rejection을 credential 없이 검증합니다. 실제 OpenAI call은 opt-in secret과 spending limit을 가진 별도 profile로 추가합니다.
  • AI pipeline advisor contract: rustee-ai unit suite는 advisor-enriched request가 final input policy를 다시 통과해야 provider가 호출되는지, non-streaming response와 every stream event가 advisor hook을 지나는지 확인합니다. combined advisor/usage-ledger path는 final enriched request metadata를 reserve하고 raw terminal stream usage를 advisor output 전에 settle하는지 고정합니다.
  • AI budget, usage ledger and tool-audit contract: rustee-ai unit suite는 blank tenant/subject와 blank tool/provider idempotency key를 거부하고 trusted context의 Debug redaction, budget denial 시 provider 미호출과 content-free AiBudgetRequest, usage reservation 뒤 completed response/stream의 actual Usage만 settle되는지, pending retry가 provider 전에 차단되는지, settlement failure가 response 또는 stream reconciliation error로 반환되는지 확인합니다. 또한 approval identity와 handler/audit key 전달, approved audit persistence가 handler보다 먼저이고 audit 실패 시 side effect handler가 호출되지 않는지, terminal Succeeded/Failed outcome이 handler 뒤 기록되는지도 검증합니다.
  • PostgreSQL AI audit and usage contract: CI의 rustee-ai-audit-sqlx suite는 deployment migration 뒤 approval-only row가 oldest-first pending query에 나타나는지, same tenant/idempotency action의 duplicate approval/outcome이 멱등인지, 다른 call identity가 handler 전 거부되는지, first terminal outcome이 이후 다른 outcome으로 바뀌지 않는지 확인합니다. 같은 suite는 usage reservation이 one provider attempt만 허용하고 completed usage를 durable하게 기록하며, settled duplicate의 재호출 차단, same usage replay, changed usage/identity rejection, pending usage query와 redaction도 확인합니다.
  • AI observability contract: rustee-ai은 in-memory OpenTelemetry exporter에서 completion/stream/tool span의 client/internal kind, aggregate request count/character count, usage, risk class, normalized outcome을 확인합니다. 같은 exporter가 prompt, completion, model alias, tenant/subject, provider/call ID, idempotency key, tool name와 tool result를 전혀 포함하지 않는지 고정합니다. stream consumer drop은 terminal outcome을 추측하지 않습니다.
  • AI recorded provider contract: rustee-ai-test은 queued completion/stream event/error의 FIFO replay, stream-open failure와 prompt/completion을 보관하지 않는 invocation metadata를 확인합니다.
  • AI web stream contract: rustee-ai-web은 in-process body collection으로 SSE/NDJSON content type, framing, usage event와 provider error redaction을 검증합니다.
  • MCP remote-tool/context contract: rustee-ai-mcp은 HTTP JSON/SSE와 local stdio subprocess의 initialize/discovery/approved tool execution/close, response/message bound와 error redaction을 검증합니다. HTTP는 session 404 invalidation, DELETE close를 고정하며 opt-in automatic recovery fixture가 bounded replacement initialize/notification을 준비해도 expired list request를 재전송하지 않고 next explicit request만 새 session으로 보내는지 확인합니다. opt-in SSE resumption fixture는 valid event ID 뒤 Last-Event-ID GET이 protocol/session header를 보존하는지, result 수신 및 bounded retry 종료, GET 404 뒤 session clear를 확인하며 origin POST를 재전송하지 않습니다. explicit standalone GET fixture는 initialized session/protocol header, untrusted notification 전달과 Debug redaction, event-ID reconnect의 POST 미재전송, server request 거부와 GET 404 session clear를 확인합니다. stdio는 newline JSON-RPC, bounded command/request/shutdown configuration, approved execution, request timeout 뒤 connection discard와 prior tool call을 replay하지 않는 explicit restart를 fixture process로 확인합니다. opt-in automatic restart fixture는 failed tool call을 원래 오류로 끝내고, bounded backoff의 replacement handshake가 완료돼도 call을 재전송하지 않으며 다음 explicit request만 새 process에 전달하는지 확인합니다. 같은 HTTP/stdio fixture는 negotiated capability 뒤 bounded resource list/template list/read와 prompt list/get, URI/cursor/session propagation, decoded data Debug redaction, capability 없는 server에 context request를 보내지 않는 contract를 확인합니다. Rust fixture integration test는 macOS/Windows CI에서 initialize/discovery/approved execution/close 공통 경로를 실행합니다. server-initiated request와 Windows advanced stdio lifecycle은 별도 contract가 필요합니다.
  • MCP server contract: rustee-mcp은 in-process Tower service에서 initialize/notification, protocol header, absent Origin pass-through와 explicit Origin allowlist/default 403, access-filtered tools/list, approved tools/call의 pre/post terminal audit, denied/hidden/handler-failed call의 generic isError, request bound, nested App::nest prefix stripping을 검증합니다. opt-in authenticated McpContextProvider는 capability advertisement, resources/list/resources/templates/list/resources/read와 prompts/list/prompts/get, default denial, item-limit와 read-URI mismatch rejection까지 고정합니다. session/SSE GET, stdio, subscription/completion와 OAuth authorization은 아직 지원하지 않습니다.
  • RAG retrieval and ingestion contract: rustee-ai-rag은 non-empty tenant/document scope, bounded context, store가 반환한 out-of-scope chunk의 fail-closed rejection과 citation retention을 deterministic fake store로 검증합니다. ingestion suite는 content-free durable request Debug/serialization, revision metadata preservation, vector capability declaration, embedding count mismatch가 index upsert를 막는지를 확인하고 rustee-ai-rag-jobs는 typed job payload에 원문을 넣지 않으며 job idempotency context를 runner로 전달하는지 검증합니다. rustee-ai-rag-advisor는 application-rendered context만 request에 추가하고 scope violation이면 renderer 전에 fail-closed 하는지 확인합니다.
  • Redis contract: CI는 redis:7-alpine container에서 rustee-redis의 PING, JSON cache round trip, atomic GETDEL, delete와 rustee-auth-session-redis의 opaque session write/read 및 HTTP restoration suite를 실행합니다. rustee-rate-limit-redis는 concurrent fixed-window check가 limit만 허용하고 나머지를 deny하는 Lua atomic contract를, rustee-auth-oidc-redis는 one-time transaction consume을 같은 container에서 확인합니다. CI는 Redis를 중지한 뒤 500ms bounded/redacted initial connect failure를 확인하고, 재시작 뒤 이 전체 Redis adapter suite를 다시 실행합니다. 로컬도 Docker daemon과 RUSTEE_REDIS_URL로 같은 suite를 opt-in 실행합니다.
  • Job observability contract: rustee-jobs-observability unit suite는 start/finish, cancellation drop의 unsettled outcome, in-flight 회수, bounded duration histogram과 invalid histogram configuration을 확인합니다. rustee-jobs-observability-prometheus suite는 bounded provider/fixed outcome label, provider escaping, duration histogram과 no-store response만 인코드하는지 확인합니다. NATS/Redis Streams/RabbitMQ/SQS의 real broker contract는 success settlement 뒤 acknowledged 1회, retry budget exhaustion 뒤 retried 1회와 dead-lettered 1회를 각각 assertion합니다. settlement error 또는 abort는 unsettled로 남겨야 합니다. metric에는 provider/outcome/global duration만 남고 payload, job ID/type, queue route, receipt handle, trace carrier, idempotency key와 raw error가 없어야 합니다.
  • NATS job contract: CI는 nats:2.10-alpine JetStream container에서 rustee-jobs-nats의 typed success ack, retry-to-DLQ, unknown registry job의 acknowledged DLQ publish, graceful drain ignored contract suite를 실행합니다. core unit suite는 bounded W3C job carrier round-trip/context 전달, strict current-version decode, explicit older-payload upcast와 newer-version rejection, registry duplicate rejection, provider attempt injection, unknown/malformed envelope의 sanitized outcome을 확인합니다. rustee-jobs-opentelemetry는 in-process exporter로 valid carrier가 handler span의 parent가 되는지 확인합니다. 로컬도 Docker daemon과 RUSTEE_NATS_URL로 같은 suite를 opt-in 실행합니다.

Authentication Contract

rustee-auth unit suite는 bearer와 header-only API-key layer가 validated Principal만 handler에 전달하고, missing/repeated/malformed API key를 provider 호출 전에 sanitized 401로, provider outage를 credential detail 없는 503으로 처리하는지 확인합니다. 별도 real loopback HTTP/1.1 contract는 duplicate X-API-Key field가 transport parser를 지나도 401로 거부되고 어느 raw key도 response에 echo되지 않는지 고정합니다. API-key header name은 configuration 시 HTTP field-name으로 검증하고 value는 exactly one printable ASCII entry at most 4 KiB로 제한합니다. keyed authenticator test는 same key의 stable 32-byte fingerprint, distinct key separation, non-zero pepper requirement, redacted Debug, invalid key pre-store rejection과 fake fingerprint store의 principal handoff를 확인합니다. optional rustee-auth-sqlx PostgreSQL 16 contract는 active lookup의 last-used/audit atomicity, duplicate fingerprint non-overwrite, expired/revoked rejection, no-overlap rotation와 repeated revocation을 확인합니다. cargo-nextest는 빠른 test binary 실행과 CI reporting에 사용하지만 doctest는 지원하지 않으므로 별도 Cargo 단계로 유지합니다. coverage는 변경 위험을 읽는 보조 지표로 기록하되, 줄 수치만을 release gate로 삼지 않습니다.

의도적으로 하지 않는 것

  • 모든 test를 mock으로만 수행하고 실제 socket/broker/database protocol 검증을 생략하는 것
  • sleep, shared port, shared queue, 실행 순서에 의존하는 flaky test
  • coverage percentage만 맞추려고 내부 구현 세부사항을 고정하는 snapshot
  • 사용자의 public application test API를 깨뜨릴 수 있는 거대한 assertion DSL을 성급히 안정화하는 것
  • 실제 cloud credential이나 비용이 드는 provider call을 일반 pull request에서 실행하는 것
  • compile-fail diagnostic 변경을 검토 없이 자동 승인하는 것

Kafka delivery-observer contract

PostgreSQL Recovery Contract

Redis Streams Deadline Contract

rustee-jobs-redis의 Redis 7 contract는 normal ack/retry/reclaim/DLQ와 별도로 CLIENT PAUSE로 backend command 처리를 의도적으로 멈춥니다. 500ms operation deadline의 readiness가 endpoint 또는 credential을 포함하지 않는 RedisStreamsError::Readiness로 끝나는지 확인한 뒤 pause가 자동 해제된 상태에서 fixture를 정리합니다. 이 검증은 injected connection manager의 reconnect policy가 아니라 Rustee command boundary를 증명합니다. 의도적 outage/pause 계약은 CI가 해당 RUSTEE_*_EXPECT_* 환경 변수를 줄 때만 fault injection을 수행하므로, 정상 backend의 전체 ignored suite는 healthy container를 중단시키지 않습니다. CLIENT PAUSE는 server-global이므로 CI는 이 계약을 filtered single test로 실행합니다.

  5. 각 optional integration Stage에서 Testcontainers-backed contract suite와 failure/cancellation test를 함께 추가합니다.
  6. Stage 9C에서 rustee-ai-test deterministic recorded-stream helper를 구현했습니다. Stage 10의 rustee-jobs-redis는 Redis 7 CI에서 success ack, delayed retry-to-DLQ, abandoned pending reclaim의 cumulative attempt, unknown registry job DLQ와 paused-backend command deadline/redaction을 실행합니다. rustee-jobs-rabbitmq는 RabbitMQ 4.3 CI에서 manual success ack, native delayed retry-to-DLQ, unknown registry DLQ를 실행합니다. rustee-jobs-sqs는 LocalStack CI에서 Standard delete/retry-direct-DLQ/unknown-registry-DLQ와 FIFO route, stopped-backend deadline/redaction/restart recovery를 실행합니다. router는 PR property contract와 weekly/manual libFuzzer parser run을 시작했고 header/query/body/range/state machine target, soak/benchmark, full provider/platform/release matrix를 계속 확장합니다.
