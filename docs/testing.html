Testing and Verification

Verify Observable Contracts Quickly and Realistically

Rustee combines deterministic unit tests with real HTTP and backend contracts. The target is user-observable behavior across cancellation, failure, recovery, and feature combinations.

Rules for Deterministic Async Tests

  • Use bounded timeouts and explicit synchronization. Do not use arbitrary sleeps to prove a state transition.
  • Local socket fixtures signal readiness explicitly and close completed responses with a transport shutdown; they do not keep a connection open for a guessed delay.
  • Inject clocks, IDs, ports, and provider fakes where a deterministic contract needs them.
  • Every task started by a test must be drained, joined, or cancelled. A passing test must not leak a background task.
  • Test cancellation, shutdown, and recovery as first-class outcomes. Retries must not mask flaky behavior.
  • When a container contract resets a shared durable table, serialize that package's tests or isolate the schema explicitly. Test-runner timing must not determine the observed storage behavior.
  • Run feature-sensitive coverage in an explicit matrix; a default-feature build does not prove an optional adapter.

Required Contract Coverage

HTTP core and server

Route matching, method behavior, extraction failures, response conversion, service nesting, graceful shutdown, trusted proxy handling, compression, and static delivery.

Security

Authentication success and fail-closed outage paths, authorization, tenant mismatch, session/CSRF behavior, secret redaction, and API-key rotation.

Storage

Bounded readiness, tenant isolation, transaction boundaries, migration assumptions, delayed relay recovery, and checkpoint behavior.

Jobs and events

Success settlement, retry, DLQ, malformed input, drain, duplicate redelivery, offset commit, schema rollout, and approved replay procedures.

AI

Deterministic provider streams, approval and audit ordering, RAG ACL revalidation, budget reservations, cache behavior, batch reconciliation, and no-replay MCP behavior.

CI and Release Gates

  • Every pull request runs the supported MSRV workspace build, formatter, warning-free Clippy, all-feature bans on panic-prone unwrap() across library and first-party binary targets, explicit content-safe Debug for public errors that retain a source, warning-free and complete public Rustdoc build across every workspace feature, targeted unit and integration checks, incomplete-source-marker checks, a workspace-member plus root-policy lint check, and HTML link plus document-structure checks.
  • Feature, native, container, sanitizer, and platform lanes are explicit. CI runs default and all-feature workspace Clippy, test, and doctest matrices, including the application-facing facade quick-start compile check, plus one public Rustdoc build with every workspace feature enabled. macOS and Windows validate workspace compilation and MCP stdio fixture lifecycle; Linux hosts required container and native lanes. CI rejects an ignored provider-contract package unless a workflow invokes it with --ignored, keeps the scheduled fuzz matrix aligned with the fuzz manifest, and requires a non-empty seed corpus for every target.
  • Container suites verify recovery as well as the happy path: bounded and redacted stopped-backend failure, restart, and the full contract after recovery.
  • Benchmark recording uses the committed dependency graph so a baseline can be reproduced from the reviewed lockfile.
  • Release qualification validates the exact inventory-approved source archives before their checksums and attestations are created; release promotion also requires documented support status, compatibility evidence, operational runbook, rollback guidance, and owner approval. It does not infer production support from a mock suite.
  • External provider, edge, and cloud evidence stays in the qualification register and is reviewed against the release plan. Live OpenAI Batch and Confluent Registry workflows are manual, environment-protected, and opt in to a provider side effect.

Intentional Limits

  • Line coverage is not a release criterion by itself.
  • Mock-only tests do not replace wire-level or real-backend contracts where a provider's semantics matter.
  • A container suite does not qualify a real managed provider, identity provider, model provider, CDN, or production network topology.
  • Weekly fuzzing covers route patterns, OpenAPI route/security grammar, public query, path, and JSON extractors, the public test-cookie path, the public static-service byte-range path, the trusted-proxy Forwarded and X-Forwarded-* paths, strict and compatible event/job envelope restoration, bounded MCP client SSE and stdio JSON-RPC parsing, MCP server JSON-RPC request parsing, OpenAI SSE and Batch JSONL parsing, and MCP OAuth WWW-Authenticate challenge admission. Fuzzing complements deterministic regression tests; it does not replace a documented contract or a minimized regression case.
  • The manual route-dispatch benchmark reports a baseline only. Follow the benchmark recording rules before comparing results.
  • Automatic retries do not make a flaky test acceptable.
