Roadmap

MVP에서 엔터프라이즈까지

Rustee의 로드맵은 기능 목록이 아니라 안정성의 순서입니다. 먼저 계약을 세우고, 그다음 사용자 경험, 운영 기능, 엔터프라이즈 확장을 쌓습니다.

이 로드맵을 읽는 방법

Stage는 구현 의존성을 보여 주지만 모든 Stage가 직렬로 끝나야 v1이 되는 checklist는 아닙니다. v1 범위, optional adapter의 지원 단계, enterprise qualification은 출하 계획과 지원 정책이 정합니다. 이 문서는 기능별 evidence와 남은 작업을 기록합니다.

현재 우선순위는 새 provider를 늘리는 일이 아니라 F0 release governance, F1 framework baseline, 그리고 이미 Contract-verified인 integration의 failure/operation evidence를 닫는 일입니다. I1/I2에서는 모든 adapter를 병렬로 승격하지 않고, owner가 명시한 하나의 reference deployment를 먼저 qualification합니다. Kafka는 delayed retry, schema, delivery observer와 consumer readiness의 code/contract 범위가 있으므로 다음 작업은 real provider 운영 evidence입니다. Stage 10의 cluster, protocol expansion, additional AI provider는 각자의 Supported gate가 생길 때까지 v1 blocker가 아닙니다.

Stage 4: 개발자 경험과 API schema

Status: in progress

  • Path, Query, Json, Header, State extractor, request extension, custom error/fallback
  • rustee-test의 TestApp in-process client: validated request URI/header, JSON body, configurable bounded response buffer, JSON/text decode와 redacted status/header assertion을 구현했습니다. opt-in with_cookie_jar()는 session-style Set-Cookie name/value carry, Max-Age=0 deletion, 64개/8 KiB bound, explicit Cookie override와 successful buffered response 뒤 atomic update를 제공합니다. Domain/Path/Secure/SameSite/Expires/redirect browser semantics, HTTP version, SSE/cancellation은 별도 scope입니다.
  • rustee-macros의 opt-in routes! builder와 #[derive(FromHeader)]: routes!는 existing App registration chain에 standard HTTP method와 dynamic path expression을 연결하고 custom method는 App::route에 남깁니다. derive는 explicit header name과 single-field tuple newtype의 FromStr parsing만 생성합니다. valid runtime/alias, unsupported method/no-route, missing header attribute/wrong shape/invalid header-name trybuild contract를 구현했습니다. attribute route macro, automatic OpenAPI/schema derive와 handler signature inference는 별도 설계가 필요합니다.
  • rustee-openapi의 OpenAPI 3.1 공개 경로: Rustee-style :parameter template를 {parameter}로 검증·변환하고, explicit operation의 path parameter/response/schema consistency와 JSON document response를 구현했습니다. named HTTP Basic/Bearer, API key(header/query/cookie), safe OpenID Connect discovery, Authorization Code/Client Credentials OAuth2 flow, static mutualTLS component, operation OR/AND requirement, document-wide default와 anonymous/clear operation override를 explicit하게 검증·렌더링합니다. mutualTLS는 TLS handshake, certificate validation 또는 principal mapping이 아닌 metadata입니다. handler/extractor/authorization/response를 추론하거나 schema derive를 강제하지 않으며 implicit/password flow, runtime token lifecycle, direct TLS/client certificate handling, richer derive와 external schema validation은 별도 ADR이 필요합니다.

완료 기준: 일반적인 JSON API를 내부 타입 노출 없이 작성하고, public example과 compile diagnostics, API schema를 검증할 수 있습니다.

Stage 9A: durable background jobs

Status: in progress

  • rustee-jobs의 typed job envelope, registry, worker lifecycle, concurrency, graceful drain, retry/DLQ, tracing과 metrics. 현재 versioned envelope, bounded W3C JobTraceContext와 rustee-jobs-opentelemetry current-span capture/handler-parent wrapper, rustee-jobs-observability의 bounded provider/outcome/global duration collector, strict current-version decode와 explicit old-version JobUpcaster, typed publish/dispatch, immutable-after-startup typed registry, retry/DLQ decision, worker configuration과 provider delivery-attempt 주입 구현
  • NATS JetStream 기반 rustee-jobs-nats: pre-provisioned durable pull consumer, bounded concurrency/drain, explicit ack, delayed NAK backoff, acknowledged DLQ relay와 stopped-broker bounded/redacted initial-connect failure 및 restart recovery contract를 구현했습니다. rustee-outbox-sqlx는 same-transaction job stage, PostgreSQL clock 기반 one-time delayed stage, 0-255 durable OutboxPriority local relay ordering, destination lease relay와 explicit shutdown-aware relay loop/report를 제공하며, rustee-outbox-observability가 fixed kind/outcome/count/duration collector를 제공합니다. rustee-jobs-cron-sqlx는 durable IANA recurrence를 due-row SKIP LOCKED lock, DST gap skip/overlap-earlier-once, fresh job outbox stage와 next occurrence update의 one-transaction boundary로 제공합니다. PostgreSQL contract도 추가했습니다.
  • PostgreSQL database side effect는 PostgresInbox receipt로 duplicate를 suppress합니다. recurring scheduler는 late schedule당 한 번만 fire하고 current database clock 다음 occurrence로 advance합니다. RecurringJobTimeZone은 UTC default와 durable IANA name을 제공하며 DST forward gap을 skip하고 backward overlap의 earlier UTC occurrence만 fire합니다. RecurringJobFireObserver는 scheduler pass의 success/failure/cancellation을 fixed terminal outcome과 aggregate count/global duration으로 기록하며, optional Prometheus helper는 explicit no-store response만 제공합니다. RecurringJobRateLimit은 Redis HTTP store를 재사용하지 않는 PostgreSQL same-transaction shared-key fixed-window governor를 제공하며, full window는 outbox 없이 next boundary로 defer하고 policy drift는 registration에서 거부합니다. tzdb update qualification, holiday calendar, external side-effect idempotency, tenant fairness, daily quota와 external provider quota는 별도 contract입니다. 상세 boundary는 ADR 0030, ADR 0031과 ADR 0033에서 관리합니다. priority는 broker/global fairness를 의미하지 않으며 ADR 0028의 local outbox ordering만 제공합니다.

완료 기준: HTTP service가 durable job을 안전하게 enqueue하고, NATS worker가 duplicate delivery와 장애를 견디며 실패 작업을 추적하고 재처리할 수 있습니다.
