Release Checklist

Separate Reproducible Source Evidence from Approved Publication

A release begins with an intentional source snapshot and ends only after approved publication and post-release verification. External qualification is a separate required input where claimed.

1. Scope and Approval

  • Confirm target version, package inventory, support level, changelog, release notes, migration guide, and owner approvals.
  • Review changes for breaking contracts, feature flags, MSRV, security advisories, dependencies, and qualification implications.
  • Freeze or explicitly record any exception that is not part of the release.

2. Source Preflight

  • Use a clean, reviewed source state and record commit, branch/tag candidate, toolchain, lockfile, and package inventory.
  • Run required formatting, tests, feature/platform/container lanes, documentation/link checks, security checks, release inventory validation, and Cargo verification of every reassembled candidate source package.
  • Generate and review source checksums, SBOM/provenance artifacts, and package metadata without leaking secrets.

3. Tag Qualification

  • Create and verify the approved tag against the exact source evidence.
  • Associate support-matrix state, qualification-register records, release notes, migration guidance, and supply-chain artifacts with the tag.
  • Stop if a required release gate, owner signature, or critical dependency review is missing.

4. Publish and Post-Release

  • Publish only the approved inventory using the documented credentials and registry policy.
  • Publish foundational candidate crates before dependents, wait for registry indexing, and stop if the registry cannot resolve the exact approved version.
  • Verify registry version, package content, checksums, metadata, docs links, and intended release visibility.
  • After registry indexing completes, manually run published-release-consumer-verification.yml from the same tag with publication approval. It resolves every candidate from the registry and compiles a neutral consumer on the supported MSRV.
  • Record the publication result, provenance location, known limitations, and post-release monitoring owner.

Stop Conditions

Do not continue publication after an unreconciled source mismatch, failed contract lane, missing qualification evidence, unresolved critical advisory, package-inventory drift, missing approval, or leaked secret. Preserve evidence and resolve the condition before repeating the relevant step.

Last updated: 2026-08-20. Execute this checklist for every public release.
