Response Compression

Compression Preserves Representation Negotiation and Cache Semantics

The compression layer is opt-in and negotiates gzip and Brotli for eligible responses while maintaining cache separation through Vary: Accept-Encoding.

Application

  • Compose response compression as an explicit middleware layer.
  • Negotiate only supported encodings and leave an identity representation available where required.
  • Respect existing Content-Encoding, unsuitable response types, and body semantics rather than double-compressing.
  • Stream bodies with bounded buffering behavior; a compression layer must not silently turn a streaming contract into an unbounded in-memory response.

Response Contract

  • Compressed and identity representations are distinct cache variants and include Vary: Accept-Encoding.
  • Content length, range behavior, validators, and headers follow the final representation contract.
  • Proxy and CDN cache keys must preserve encoding variation. An origin layer cannot prove an edge cache is configured correctly.

Intentional Bypasses

Applications may bypass compression for already-compressed media, tiny responses, sensitive payloads, streaming protocols, or routes whose latency/CPU budget requires identity representation. The selection is explicit policy, not a framework guess.

Verification

  • Test gzip, Brotli, identity fallback, unacceptable encoding, existing content encoding, and Vary behavior.
  • Test proxy/CDN qualification separately, including cache-variant isolation and origin behavior after edge failure.
  • Do not treat a local unit test as evidence for public CDN compression or cache correctness.
