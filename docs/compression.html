HTTP Response Compression

응답 압축은 표현 협상과 cache 계약을 함께 지킵니다

rustee-middleware::CompressionLayer는 gzip과 Brotli를 명시적으로 협상하는 streaming Tower layer입니다. 응답 전체를 메모리에 모으지 않고, 원래 body의 오류와 HTTP trailers를 끝까지 전달합니다.

적용

use rustee_middleware::{CompressionLayer, ServiceBuilder};

let service = ServiceBuilder::new()
    .layer(CompressionLayer::new())
    .service(app);

기본값은 br와 gzip 모두를 사용하며 같은 quality에서는 Brotli를 고릅니다. with_brotli(false) 또는 with_gzip(false)로 배포 환경에 맞춰 하나를 끌 수 있습니다. Accept-Encoding가 없거나 두 coding의 quality가 0이면 응답은 원본 그대로입니다. 

let service = ServiceBuilder::new()
    .layer(CompressionLayer::new())
    .layer(files.layer())
    .service(app);

정적 파일도 origin에서 압축하려면 compression layer가 static layer의 바깥에 있어야 합니다. CDN 또는 reverse proxy가 이미 compression을 소유한다면 origin layer를 추가하지 않고, 해당 infrastructure의 Vary와 cache key 정책을 사용합니다.

응답 계약

항목동작이유
codingbr, gzip quality negotiationbrowser와 proxy가 허용한 표현만 보냅니다.
media typetext/*, JavaScript, JSON, XML, SVG 및 +json/+xml이미 압축된 binary format을 기본으로 다시 압축하지 않습니다.
cache headergzip/Brotli response는 Content-Encoding을 설정하고 Content-Length를 제거합니다. transform 가능한 identity response를 포함한 모든 negotiated representation에는 Vary: Accept-Encoding을 추가합니다.중간 cache가 gzip/Brotli와 identity 표현을 섞지 않게 합니다.
streambody frame을 compressor reader로 연결하고 trailers를 마지막 frame으로 전달합니다.large/long-lived response를 통째로 buffer하지 않고 cancellation과 오류 전파를 보존합니다.

의도적인 우회

  • HEAD, request Range, informational/204/304 response, Content-Range response는 원본을 유지합니다.
  • 이미 Content-Encoding이 있거나 Cache-Control: no-transform인 response는 다시 변환하지 않습니다.
  • content type이 없거나 allowlist 밖이면 압축하지 않습니다.
  • request body decompression, ETag/conditional representation 재계산, byte-range compression은 이 layer의 범위가 아닙니다. precompressed .br/.gz asset selection은 static layer의 명시적 opt-in입니다.

conditional static delivery, single/multipart byte range, precompressed asset selection과 opt-in large-file streaming은 정적 파일 문서에서 제공합니다. compression layer는 모든 Range request를 bypass하므로 multipart body도 origin 그대로 전달합니다. Linux CI의 Nginx proxy_cache contract는 gzip과 identity response가 Vary: Accept-Encoding으로 분리되어 각각 cache hit가 되는지를 검증합니다. 실제 CDN vendor의 purge, TLS, cache-control policy와 metrics는 별도 deployment gate입니다.

검증 기준

layer contract는 Brotli/gzip 실제 복원, quality negotiation, 기존 coding 보존, Range/HEAD/no-transform 우회, Vary/Content-Length 정리, trailer 보존을 in-process test로 확인합니다. Linux CI는 Nginx reverse-proxy cache에서 response coding과 cache key를 deployment integration test로 확인합니다. CDN vendor별 purge, edge compression과 cache-control policy도 별도 deployment test로 확인합니다.
