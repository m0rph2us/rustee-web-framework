Benchmarking

Record Repeatable Baselines Before Claiming Performance

Rustee benchmarks are diagnostics for a named workload. They detect changes under a controlled environment; they do not establish a universal latency or throughput claim.

Current Harness

The rustee-router route-dispatch harness builds a small static and parameterized route table, warms it, then repeatedly dispatches a matched parameterized request through the public App::call path. It verifies the response status on each iteration. 

cargo bench -p rustee-router --bench route_dispatch

Set RUSTEE_BENCH_ITERATIONS to an explicit integer from 1 through 10,000,000 when the default 100,000 measured iterations is not appropriate. Every run uses a fixed 10,000-iteration warmup.

Set RUSTEE_BENCH_OUTPUT to write a schema-1 JSON report with the workload, iterations, elapsed time, and calculated operations per second. The manual benchmark workflow records that report as a 90-day artifact together with its source reference and shared-runner identifier.

Recording Rules

  • Record the source commit, Rust toolchain, command, iteration count, operating system, CPU model, power mode, and competing workload.
  • Record the route table, request shape, body behavior, runtime model, and result units with the output.
  • Compare only like-for-like runs. Treat a result from a shared CI runner as a smoke baseline, not a release threshold.
  • Store significant results and regression decisions in the release or qualification evidence for the relevant source version.

Limits

  • This harness does not measure sockets, TLS, HTTP/2, application handlers, database calls, allocators, load balancing, or production tail latency.
  • No automated pass/fail performance threshold exists until maintainers approve a stable workload and controlled runner.
  • Benchmark numbers do not replace transport, provider, security, recovery, or external qualification evidence.
